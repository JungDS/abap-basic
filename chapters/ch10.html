10장

모듈화: 코드를 나눠 쓰기

이번 장 목표
  • 코드를 나눠 쓰면 무엇이 좋은지 말할 수 있어요.
  • FORM과 PERFORM으로 프로그램 안에서 코드를 나누고, USING·CHANGING으로 값을 주고받을 수 있어요.
  • SE37에서 Function Module을 만들고, 테스트하고, 프로그램에서 CALL FUNCTION으로 부를 수 있어요.
  • 로컬 클래스의 Method를 한 번 만들어 보고, 셋의 차이를 구분할 수 있어요.

10-1. 왜 나눠 써요?

9장까지 오면서 프로그램이 꽤 길어졌어요. 예를 들어 "할인 가격 계산"이 프로그램 여기저기에서 필요하다고 해 볼게요.

" 나누지 않은 경우: 같은 계산을 세 번
gv_result1 = gv_price1 - gv_price1 * gv_rate / 100.
...
gv_result2 = gv_price2 - gv_price2 * gv_rate / 100.
...
gv_result3 = gv_price3 - gv_price3 * gv_rate / 100.
" 나눈 경우: 계산은 한 곳, 부르기만 세 번
PERFORM calc_discount USING gv_price1 gv_rate
                      CHANGING gv_result1.
...
PERFORM calc_discount USING gv_price2 gv_rate
                      CHANGING gv_result2.
...

왼쪽은 계산식을 고칠 일이 생기면(예: 1원 단위 버림) 세 군데를 모두 찾아 고쳐야 해요. 하나라도 빠뜨리면 버그가 돼요. 오른쪽은 계산식이 한 곳에만 있어서 거기만 고치면 끝이에요.

이렇게 코드를 이름 붙인 덩어리로 나누는 것을 모듈화라고 해요. 좋은 점은 세 가지예요.

좋은 점 설명
다시 쓰기 한 번 만들어 두고 여러 번 불러요.
고치기 쉬움 고칠 곳이 한 군데예요.
읽기 쉬움 PERFORM calc_discount처럼 이름만 봐도 무슨 일을 하는지 알아요.

ABAP에서 코드를 나누는 방법은 크게 세 가지예요. 이 장에서 차례로 만나 볼게요.

방법 어디에 있어요? 누가 부를 수 있어요?
FORM (서브루틴) 내 프로그램 안 내 프로그램만
Function Module SE37, Function Group 안 시스템의 모든 프로그램
Method 클래스 안 클래스에 따라 달라요

10-2. 프로그램 안에서 나누기: FORM과 PERFORM

FORM 이름. … ENDFORM.으로 코드 덩어리를 만들고, PERFORM 이름.으로 불러요.

  1. PERFORM을 만나면 그 이름의 FORM으로 건너가요.
  2. FORM 안의 코드를 ENDFORM까지 실행해요.
  3. PERFORM 바로 다음 줄로 돌아와서 이어서 실행해요.

값 주고받기: USING과 CHANGING

FORM이 일을 하려면 재료(정가, 할인율)를 받고, 결과(할인가)를 돌려줘야 해요. 이때 USING과 CHANGING을 써요.

REPORT yg##_10_form.

DATA: gv_price  TYPE i VALUE 25000,
      gv_rate   TYPE i VALUE 10,
      gv_result TYPE i.

START-OF-SELECTION.
  PERFORM calc_discount USING    gv_price gv_rate
                        CHANGING gv_result.
  WRITE: / '정가  :', gv_price,
         / '할인가:', gv_result.

  gv_price = 15000.
  gv_rate  = 20.
  PERFORM calc_discount USING    gv_price gv_rate
                        CHANGING gv_result.
  WRITE: / '정가  :', gv_price,
         / '할인가:', gv_result.

*&---------------------------------------------------------------------*
*& Form calc_discount : 정가와 할인율로 할인 가격 계산
*&---------------------------------------------------------------------*
FORM calc_discount USING    pv_price  TYPE i
                            pv_rate   TYPE i
                   CHANGING cv_result TYPE i.
  cv_result = pv_price - pv_price * pv_rate / 100.
ENDFORM.

실행하면 22,500과 12,000이 나와요. 같은 FORM을 다른 값으로 두 번 불렀어요.

  • USING: FORM에 재료를 넘겨줘요. 받는 쪽은 읽기만 해요.
  • CHANGING: FORM이 값을 바꾸면 부른 쪽 변수에도 그대로 반영돼요. 결과를 돌려받을 때 써요.
  • 짝은 이름이 아니라 순서로 정해져요. PERFORM의 첫 번째 변수가 FORM의 첫 번째 파라미터로 가요. 그래서 개수와 순서를 꼭 맞춰야 해요.
  • FORM 안에서는 pv_price, cv_result처럼 파라미터 이름으로 써요. 전역 변수 gv_…를 직접 고치지 않는 것이 좋은 습관이에요.
파라미터 이름 규칙

교재에서는 받는 방식이 이름에 보이도록 앞에 표시를 붙여요. 수업에서 정한 규칙이 있으면 그것을 따르세요.

어디 앞에 붙이는 말 예
FORM의 USING P + 종류 pv_price, ps_book
FORM의 CHANGING C + 종류 cv_result
Function Module·Method의 Import I + 종류 iv_price
Function Module의 Export E + 종류 ev_price, es_book

종류 글자는 0장과 같아요. V는 변수 하나, S는 Structure, T는 Internal Table이에요.

자주 하는 실수
  • FORM은 프로그램 맨 아래에 모아요. 이벤트(START-OF-SELECTION 등) 중간에 FORM을 끼워 넣으면 그 뒤의 코드가 실행되지 않거나 오류가 나요.
  • PERFORM과 FORM의 파라미터 개수가 다르면 문법 검사에서 오류가 나요.
  • USING으로 받은 값을 FORM 안에서 바꾸지 않아요. 문법상 막히지 않는 경우도 있지만 읽는 사람이 헷갈려요. 바꿀 값은 CHANGING으로 받아요.
직접 해 보기
  1. 위 코드를 YG##_10_FORM으로 만들어요.
  2. FORM 부분을 쓰기 전에 PERFORM calc_discount … 줄만 먼저 써요. 그다음 calc_discount를 더블클릭해 보세요. 아직 없는 FORM을 만들지 물어봐요. Yes를 누르고 프로그램(Main Program)에 만들도록 고르면 FORM … ENDFORM 뼈대를 자동으로 써 줘요.
  3. 실행해서 두 결과를 확인해요.
  4. 6장에서 배운 디버거로 들어가 PERFORM 줄에서 F5를 눌러 보세요. FORM 안으로 들어가요. F6을 누르면 FORM을 한 번에 실행하고 다음 줄로 넘어가요.
FORM은 "읽을 줄 알면 되는" 방법이에요

SAP는 FORM(서브루틴)을 새로 만들 때는 쓰지 말라고 안내해요. 새 코드는 10-6의 Method를 권해요. 그래도 회사에 있는 오래된 프로그램에는 PERFORM이 아주 많아서, 읽고 고칠 줄은 알아야 해요. 이 교재에서 FORM을 먼저 배우는 이유는 구조가 가장 단순해서 "나눠 쓰기"를 익히기 좋기 때문이에요.

10-3. 모든 프로그램이 쓰는 기능: Function Module

FORM은 내 프로그램 안에서만 부를 수 있어요. 다른 친구의 프로그램에서도 "할인 가격 계산"을 쓰고 싶다면, 시스템 전체가 함께 쓰는 Function Module로 만들어요.

Function Module은 혼자 있지 않고 Function Group이라는 묶음 안에 들어가요. 그래서 순서는 이래요.

  1. Function Group 만들기 (한 번만): YG##_FG
  2. Function Module 만들기: Y_G##_DISCOUNT
  3. SE37에서 테스트하기
  4. 프로그램에서 부르기: CALL FUNCTION
이름 규칙

Function Group은 다른 객체처럼 Y로 시작해요(YG##_FG). Function Module은 이름이 Y_나 Z_로 시작해야 해요. 그래서 밑줄이 하나 더 들어간 Y_G##_DISCOUNT처럼 써요.

1단계: Function Group 만들기

SAP GUI 명령 칸에 SE37을 입력하면 Function Builder가 열려요.

직접 해 보기
  1. SE37 화면 위쪽 메뉴에서 Goto → Function Groups → Create Group을 골라요.
  2. Function Group에 YG##_FG, Short Text에 G## 연습용 Function Group을 적고 저장해요. 1
  3. Package를 묻는 창이 뜨면 Local Object를 눌러요(1장 1-6과 같아요).

2단계: Function Module 만들기

직접 해 보기
  1. SE37 첫 화면의 Function Module 칸에 Y_G##_DISCOUNT를 넣고 Create를 눌러요. 2
  2. 작은 창에 Function Group YG##_FG, Short Text 할인 가격 계산을 적고 Save를 눌러요.
  3. 이제 탭이 여러 개 있는 화면이 나와요. 아래 순서대로 채워요.

Function Module 화면의 탭 중에서 처음에는 네 개만 알면 돼요.

탭 무엇을 적어요?
Attributes 종류. 기본값 Normal Function Module 그대로 둬요.
Import 받을 값 (재료)
Export 돌려줄 값 (결과)
Source code 실제 코드
  • Import 탭: IV_PRICE(정가)는 7장에서 만든 Data Element YG##_E_PRICE, IV_RATE(할인율)는 정수 I로 적어요.
  • Export 탭: EV_PRICE(할인가)를 YG##_E_PRICE로 적어요.
  • Source code 탭을 열면 SAP가 적어 둔 주석 사이에 계산 한 줄만 넣으면 돼요.
FUNCTION y_g##_discount.
*"----------------------------------------------------------------------
*"*"Local Interface:
*"  IMPORTING
*"     REFERENCE(IV_PRICE) TYPE  YG##_E_PRICE
*"     REFERENCE(IV_RATE) TYPE  I
*"  EXPORTING
*"     REFERENCE(EV_PRICE) TYPE  YG##_E_PRICE
*"----------------------------------------------------------------------

  ev_price = iv_price - iv_price * iv_rate / 100.

ENDFUNCTION.

*"로 시작하는 주석은 Import·Export 탭에 적은 내용을 SAP가 자동으로 써 준 거예요. 직접 고치지 않아요. 파라미터를 바꾸고 싶으면 탭에서 바꿔요.

자주 하는 실수
  • 저장 → 검사 → 활성화는 똑같이 해요. 처음 활성화할 때 비활성 객체 목록이 뜨면, Function Group에 딸린 객체(SAPLYG##_FG 등)까지 모두 골라서 함께 활성화해요. Function Group이 비활성이면 Function Module을 불러도 오류가 나요.
  • Associated Type에 없는 이름(오타)을 적으면 저장할 때 오류가 나요. 7장의 Data Element가 활성화되어 있는지 확인해요.

3단계: SE37에서 테스트하기

Function Module은 프로그램을 만들지 않아도 SE37에서 바로 실행해 볼 수 있어요. 만들었으면 꼭 먼저 테스트해요.

직접 해 보기
  1. Function Module 화면이나 SE37 첫 화면에서 F8(Test/Execute)을 눌러요.
  2. IV_PRICE에 25000, IV_RATE에 10을 넣어요. 1
  3. 다시 F8을 눌러요.
  4. 결과 화면의 Export parameters에서 EV_PRICE가 22500인지 확인해요. 2

4단계: 프로그램에서 부르기 (Pattern 버튼)

CALL FUNCTION 문장은 길어서 직접 치면 틀리기 쉬워요. ABAP Editor의 Pattern 버튼(Ctrl+F6)을 쓰면 SAP가 뼈대를 써 줘요.

직접 해 보기
  1. 새 프로그램 YG##_10_CALL을 만들고, 문장을 넣을 줄에 커서를 둬요.
  2. 툴바의 Pattern을 눌러요.
  3. CALL FUNCTION을 고르고 Y_G##_DISCOUNT를 입력한 뒤 Enter를 눌러요.
  4. 아래처럼 뼈대가 들어가요. = 뒤에 내 변수를 채우고, 결과를 받을 IMPORTING 줄은 앞의 *를 지워서 주석을 풀어요.
" Pattern이 넣어 준 모습
CALL FUNCTION 'Y_G##_DISCOUNT'
  EXPORTING
    iv_price       =
    iv_rate        =
* IMPORTING
*   EV_PRICE       =
          .

다 채운 프로그램은 이래요.

REPORT yg##_10_call.

DATA gv_price TYPE yg##_e_price.

PARAMETERS: pa_price TYPE yg##_e_price DEFAULT 25000,
            pa_rate  TYPE i DEFAULT 10.

START-OF-SELECTION.
  CALL FUNCTION 'Y_G##_DISCOUNT'
    EXPORTING
      iv_price = pa_price
      iv_rate  = pa_rate
    IMPORTING
      ev_price = gv_price.

  WRITE: / '정가  :', pa_price,
         / '할인가:', gv_price.

여기가 처음에 가장 헷갈리는 곳이에요. Function Module 입장에서 Import(받는 값)는, 부르는 프로그램 입장에서는 내보내는 값이라 EXPORTING에 적어요. 반대로 Function Module의 Export(돌려주는 값)는 프로그램이 받는 값이라 IMPORTING에 적어요.

  • = 의 왼쪽은 Function Module의 파라미터 이름, 오른쪽은 내 프로그램의 변수예요.
  • FORM과 달리 이름으로 짝을 지어요. 그래서 순서는 바뀌어도 괜찮아요.
  • 이름은 작은따옴표 안에 대문자로 적어요. 'y_g##_discount'처럼 소문자로 적으면 Function Module을 찾지 못해 실행 중에 오류(덤프)가 나요. Pattern 버튼을 쓰면 이런 실수가 없어요.

실패를 알리기: Exceptions

책 번호를 받아 그 책을 돌려주는 Function Module을 생각해 볼게요. 없는 번호가 들어오면 "못 찾았어요"라고 알려 줘야 해요. 이때 Exceptions 탭을 써요.

Y_G##_GET_BOOK을 같은 Function Group YG##_FG에 만들어요.

탭 내용
Import IV_BOOK_ID TYPE YG##_E_BOOK_ID
Export ES_BOOK TYPE YG##_BOOK (Table 이름을 쓰면 한 줄 Structure가 돼요)
Exceptions NOT_FOUND / Short text 책이 없음 
FUNCTION y_g##_get_book.
*"  (자동 주석은 생략했어요)

  SELECT SINGLE * FROM yg##_book
    INTO es_book
    WHERE book_id = iv_book_id.

  IF sy-subrc <> 0.
    RAISE not_found.          " 부른 쪽에 "못 찾았어요"를 알리고 끝내요
  ENDIF.

ENDFUNCTION.

부르는 쪽에서 Pattern 버튼을 쓰면 EXCEPTIONS와 sy-subrc 검사까지 같이 들어와요.

CALL FUNCTION 'Y_G##_GET_BOOK'
  EXPORTING
    iv_book_id = pa_id
  IMPORTING
    es_book    = gs_book
  EXCEPTIONS
    not_found  = 1            " NOT_FOUND가 일어나면 sy-subrc = 1
    OTHERS     = 2.           " 그 밖의 예외는 sy-subrc = 2

IF sy-subrc <> 0.
  MESSAGE '그런 번호의 책이 없어요.' TYPE 'S' DISPLAY LIKE 'E'.
  RETURN.
ENDIF.

RAISE not_found.가 실행되면 Function Module은 그 자리에서 끝나고, 부른 쪽의 sy-subrc에 EXCEPTIONS에 적은 번호가 들어가요. 8장의 "sy-subrc는 방금 한 일의 성적표" 그대로예요.

자주 하는 실수

EXCEPTIONS 부분을 지우고 부르면, 예외가 일어났을 때 받을 곳이 없어서 프로그램이 덤프로 멈춰요. Pattern이 넣어 준 EXCEPTIONS와 IF sy-subrc <> 0.은 지우지 말고 채워 써요.

10-4. 맛보기: 로컬 클래스의 Method

요즘 새로 만드는 ABAP 코드는 대부분 클래스와 Method로 나눠요. 객체지향은 다음 과정에서 제대로 배우니, 여기서는 "할인 계산"을 Method로 한 번만 바꿔 볼게요.

REPORT yg##_10_method.

PARAMETERS: pa_price TYPE i DEFAULT 25000,
            pa_rate  TYPE i DEFAULT 10.

DATA gv_result TYPE i.

*----------------------------------------------------------------------*
* 클래스 설계도: 무엇을 받고 무엇을 돌려주는지
*----------------------------------------------------------------------*
CLASS lcl_calc DEFINITION.
  PUBLIC SECTION.
    CLASS-METHODS discount
      IMPORTING iv_price        TYPE i
                iv_rate         TYPE i
      RETURNING VALUE(rv_price) TYPE i.
ENDCLASS.

*----------------------------------------------------------------------*
* 실제 코드
*----------------------------------------------------------------------*
CLASS lcl_calc IMPLEMENTATION.
  METHOD discount.
    rv_price = iv_price - iv_price * iv_rate / 100.
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  gv_result = lcl_calc=>discount( iv_price = pa_price
                                  iv_rate  = pa_rate ).
  WRITE: / '할인가:', gv_result.

처음 보는 단어가 많지만, 구조는 FORM과 비슷해요.

부분 뜻
CLASS lcl_calc DEFINITION 설계도. 어떤 Method가 있고 무엇을 받고 돌려주는지 적어요. lcl_은 Local Class라는 뜻이에요.
CLASS-METHODS 클래스 이름으로 바로 부를 수 있는 Method예요.
RETURNING VALUE(rv_price) 결과 하나를 돌려줘요. 그래서 gv_result = …( )처럼 계산식 오른쪽에 바로 쓸 수 있어요.
CLASS lcl_calc IMPLEMENTATION 실제 코드예요. METHOD … ENDMETHOD 안에 써요.
lcl_calc=>discount( … ) 부르기. =>는 "이 클래스의"라는 뜻이에요.
자주 하는 실수
  • 클래스는 쓰기 전에(위쪽에) 있어야 해요. START-OF-SELECTION보다 아래에 CLASS … DEFINITION을 두면 "lcl_calc를 모른다"는 오류가 나요.
  • 부를 때 괄호 안쪽 앞뒤를 한 칸씩 띄워요. discount(iv_price = pa_price …)처럼 붙여 쓰면 오류가 나요.

셋을 한눈에 비교하기

FORM Function Module Method
만드는 곳 내 프로그램 안 SE37 (Function Group 안) 클래스 안 (로컬 또는 SE24)
부를 수 있는 곳 내 프로그램만 모든 프로그램 로컬은 내 프로그램, SE24 클래스는 모든 프로그램
부르는 방법 PERFORM CALL FUNCTION '이름' 클래스=>메서드( )
값 짝짓기 순서 이름 이름
실패 알리기 (없음) EXCEPTIONS + sy-subrc 예외 클래스 (다음 과정)
지금 위치 읽을 줄 알면 돼요 아주 많이 써요 새 코드의 기본
이렇게도 써요

SAP가 만들어 둔 Function Module도 수천 개 있어요. 예를 들어 날짜 계산, 숫자를 글자로 바꾸기 같은 일은 이미 만들어진 Function Module을 찾아 쓰는 경우가 많아요. SE37에서 이름 칸에 *DATE*처럼 별표를 넣고 F4를 누르면 찾아볼 수 있어요. 처음 쓰는 Function Module은 SE37에서 먼저 테스트해 보고 쓰는 습관을 들여요.

10-5. 미니 실습: 책 한 권 할인가 보기

직접 해 보기

프로그램 YG##_10_BOOK을 만들어요.

  1. Selection Screen에서 책 번호(pa_id, 꼭 입력)와 할인율(pa_rate, 기본값 10)을 받아요.
  2. Y_G##_GET_BOOK을 불러 책 한 권을 읽어요. 없으면 메시지(Text Symbol e01: "그런 번호의 책이 없어요.")를 띄우고 끝내요.
  3. Y_G##_DISCOUNT를 불러 할인가를 계산해요.
  4. 출력은 FORM print_book으로 따로 만들어요. 책 Structure와 할인가를 USING으로 넘겨요.
  5. Selection Text도 붙여요(5장).
예시 답안 보기
REPORT yg##_10_book.

DATA: gs_book  TYPE yg##_book,
      gv_price TYPE yg##_e_price.

PARAMETERS: pa_id   TYPE yg##_book-book_id OBLIGATORY,
            pa_rate TYPE i DEFAULT 10.

START-OF-SELECTION.
  " 1. 책 한 권 읽기
  CALL FUNCTION 'Y_G##_GET_BOOK'
    EXPORTING
      iv_book_id = pa_id
    IMPORTING
      es_book    = gs_book
    EXCEPTIONS
      not_found  = 1
      OTHERS     = 2.
  IF sy-subrc <> 0.
    MESSAGE TEXT-e01 TYPE 'S' DISPLAY LIKE 'E'.
    RETURN.
  ENDIF.

  " 2. 할인가 계산
  CALL FUNCTION 'Y_G##_DISCOUNT'
    EXPORTING
      iv_price = gs_book-price
      iv_rate  = pa_rate
    IMPORTING
      ev_price = gv_price.

  " 3. 출력
  PERFORM print_book USING gs_book gv_price.

*&---------------------------------------------------------------------*
*& Form print_book : 책 정보와 할인가 출력
*&---------------------------------------------------------------------*
FORM print_book USING ps_book  TYPE yg##_book
                      pv_price TYPE yg##_e_price.
  WRITE: / '도서 번호:', ps_book-book_id,
         / '제목    :', ps_book-title,
         / '정가    :', ps_book-price,
         / '할인가  :', pv_price.
ENDFORM.
확인 문제
  1. 아래 PERFORM을 실행한 뒤 gv_c의 값은 얼마일까요? 
    gv_a = 3. gv_b = 4.
PERFORM add USING gv_a gv_b CHANGING gv_c.

FORM add USING pv_x TYPE i pv_y TYPE i CHANGING cv_sum TYPE i.
  cv_sum = pv_x + pv_y.
ENDFORM.
  2. Function Module에서 Import 탭에 적은 파라미터는, CALL FUNCTION에서 EXPORTING과 IMPORTING 중 어디에 적을까요?
  3. CALL FUNCTION 'Y_G05_GET_BOOK'으로 없는 책 번호를 넘겼더니 sy-subrc가 1이었어요. 무슨 뜻일까요?
  4. Function Module을 프로그램에서 부르기 전에 SE37에서 먼저 해 보면 좋은 일은 무엇일까요?
  5. FORM과 Function Module 중, 다른 친구의 프로그램에서도 부를 수 있는 것은 무엇일까요?
정답 보기
  1. 7이에요. gv_a가 pv_x로, gv_b가 pv_y로 가고, cv_sum에 넣은 값이 gv_c로 돌아와요.
  2. EXPORTING이에요. Function Module이 받는 값은, 부르는 쪽에서는 내보내는 값이에요.
  3. Function Module 안에서 RAISE not_found.가 실행되었다는 뜻이에요(not_found = 1로 적었으니까요). 책을 못 찾은 거예요.
  4. 테스트(F8)예요. 값을 넣어 보고 결과가 맞는지 먼저 확인해요.
  5. Function Module이에요. FORM은 그 FORM이 있는 프로그램 안에서만 불러요.
정리
  • 모듈화는 코드를 이름 붙인 덩어리로 나눠서 다시 쓰고, 고치기 쉽고, 읽기 쉽게 만드는 일이에요.
  • FORM … ENDFORM을 PERFORM으로 불러요. 재료는 USING, 결과는 CHANGING으로 주고받고, 짝은 순서로 정해져요. 새로 만들기보다는 읽을 줄 알면 돼요.
  • Function Module은 SE37에서 Function Group 안에 만들고, F8로 테스트하고, Pattern 버튼으로 CALL FUNCTION을 넣어요.
  • 부르는 쪽에서는 방향이 반대예요. FM의 Import는 EXPORTING, FM의 Export는 IMPORTING에 적어요.
  • 실패는 RAISE로 알리고, 부르는 쪽은 EXCEPTIONS와 sy-subrc로 확인해요.
  • 새 코드의 기본은 클래스의 Method예요. 클래스=>메서드( )로 불러요.
