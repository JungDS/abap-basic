10장

모듈화: 코드를 나눠 쓰기

이번 장 목표
  • 코드를 나눠 쓰면 무엇이 좋은지 말할 수 있어요.
  • FORM과 PERFORM으로 프로그램 안에서 코드를 나누고, USING·CHANGING으로 값을 주고받을 수 있어요.
  • FORM 안에서만 쓰는 지역 변수를 만들고, Internal Table을 FORM에 통째로 넘기는 코드를 읽을 수 있어요.
  • SE37에서 Function Module을 만들고, 테스트하고, 프로그램에서 CALL FUNCTION으로 부를 수 있어요.
  • 로컬 클래스의 Method를 한 번 만들어 보고, 셋의 차이를 구분할 수 있어요.

10-1. 왜 나눠 써요?

9장까지 오면서 프로그램이 꽤 길어졌어요. 예를 들어 "할인 가격 계산"이 프로그램 여기저기에서 필요하다고 해 볼게요.

" 나누지 않은 경우: 같은 계산을 세 번
gv_result1 = gv_price1 - gv_price1 * gv_rate / 100.
...
gv_result2 = gv_price2 - gv_price2 * gv_rate / 100.
...
gv_result3 = gv_price3 - gv_price3 * gv_rate / 100.
" 나눈 경우: 계산은 한 곳, 부르기만 세 번
PERFORM calc_discount USING gv_price1 gv_rate
                      CHANGING gv_result1.
...
PERFORM calc_discount USING gv_price2 gv_rate
                      CHANGING gv_result2.
...
PERFORM calc_discount USING gv_price3 gv_rate
                      CHANGING gv_result3.

첫 번째 코드는 계산식을 고칠 일이 생기면(예: 1원 단위 버림) 세 군데를 모두 찾아 고쳐야 해요. 하나라도 빠뜨리면 버그가 돼요. 두 번째 코드는 계산식이 한 곳에만 있어서 거기만 고치면 끝이에요.

이렇게 코드를 이름 붙인 덩어리로 나누는 것을 모듈화라고 해요. 좋은 점은 세 가지예요.

좋은 점 설명
다시 쓰기 한 번 만들어 두고 여러 번 불러요.
고치기 쉬움 고칠 곳이 한 군데예요.
읽기 쉬움 PERFORM calc_discount처럼 이름만 봐도 무슨 일을 하는지 알아요.

ABAP에서 코드를 나누는 방법은 크게 세 가지예요. 이 장에서 차례로 만나 볼게요.

방법 어디에 있어요? 누가 부를 수 있어요?
FORM (서브루틴) 내 프로그램 안 내 프로그램만
Function Module SE37, Function Group 안 시스템의 모든 프로그램
Method 클래스 안 클래스에 따라 달라요

10-2. 프로그램 안에서 나누기: FORM과 PERFORM

FORM 이름. … ENDFORM.으로 코드 덩어리를 만들고, PERFORM 이름.으로 불러요. JavaScript로 치면 FORM은 함수(function)를 만드는 것, PERFORM은 그 함수를 부르는 것이에요.

  1. PERFORM을 만나면 그 이름의 FORM으로 건너가요.
  2. FORM 안의 코드를 ENDFORM까지 실행해요.
  3. PERFORM 바로 다음 줄로 돌아와서 이어서 실행해요.

값 주고받기: USING과 CHANGING

FORM이 일을 하려면 재료(정가, 할인율)를 받고, 결과(할인가)를 돌려줘야 해요. 이때 USING과 CHANGING을 써요. 새 프로그램으로 만들어 볼게요. 아래 코드는 먼저 눈으로 읽어요. 직접 만드는 것은 조금 아래 "직접 해 보기"에서 순서대로 해요.

새로 만들기ProgramSE38
Program
YG##_139
Title
[예제] FORM으로 할인가 계산
REPORT yg##_139.

DATA: gv_price  TYPE i VALUE 25000,
      gv_rate   TYPE i VALUE 10,
      gv_result TYPE i.

START-OF-SELECTION.
  PERFORM calc_discount USING    gv_price gv_rate
                        CHANGING gv_result.
  WRITE: / '정가  :', gv_price,
         / '할인가:', gv_result.

  gv_price = 15000.
  gv_rate  = 20.
  PERFORM calc_discount USING    gv_price gv_rate
                        CHANGING gv_result.
  WRITE: / '정가  :', gv_price,
         / '할인가:', gv_result.

*&---------------------------------------------------------------------*
*& Form calc_discount : 정가와 할인율로 할인 가격 계산
*&---------------------------------------------------------------------*
FORM calc_discount USING    pv_price  TYPE i
                            pv_rate   TYPE i
                   CHANGING cv_result TYPE i.
  cv_result = pv_price - pv_price * pv_rate / 100.
ENDFORM.

실행하면 이렇게 나와요. 같은 FORM을 다른 값으로 두 번 불렀어요.

정가  :     25,000
할인가:     22,500
정가  :     15,000
할인가:     12,000
  • FORM 줄에 적은 pv_price, pv_rate, cv_result는 값을 받는 자리의 이름이에요. 파라미터라고 불러요.
  • USING: FORM에 재료를 넘겨줘요. 받는 쪽은 읽기만 하기로 해요.
  • CHANGING: FORM이 값을 바꾸면 부른 쪽 변수에도 그대로 반영돼요. 결과를 돌려받을 때 써요. JavaScript 함수는 return으로 결과를 돌려주지만, FORM은 CHANGING 변수에 담아서 돌려줘요.
  • 짝은 이름이 아니라 순서로 정해져요. PERFORM의 첫 번째 변수가 FORM의 첫 번째 파라미터로 가요. 그래서 개수와 순서를 꼭 맞춰야 해요.
  • FORM 안에서는 pv_price, cv_result처럼 파라미터 이름으로 써요. 전역 변수 gv_…를 직접 고치지 않는 것이 좋은 습관이에요.
파라미터 이름 규칙

교재에서는 받는 방식이 이름에 보이도록 앞머리를 붙여요. 수업에서 정한 규칙이 있으면 그것을 따르세요.

어디 앞머리 예
FORM의 USING P + 종류 pv_price, ps_book, pt_book
FORM의 CHANGING C + 종류 cv_result, ct_book

종류 글자는 0장과 같아요. V는 변수 하나, S는 Structure, T는 Internal Table이에요. Function Module과 Method의 앞머리(iv_, ev_, rv_)는 10-3과 10-4에서 나올 때 알려 줄게요(전체는 부록 F).

자주 하는 실수
  • FORM은 프로그램 맨 아래에 모아요. 이벤트(START-OF-SELECTION 등) 중간에 FORM을 끼워 넣으면 그 뒤의 코드가 실행되지 않거나 오류가 나요.
  • PERFORM과 FORM의 파라미터 개수가 다르면 문법 검사에서 오류가 나요.
  • USING으로 받은 값을 FORM 안에서 바꾸지 않아요. 문법 오류는 나지 않지만, 부른 쪽 변수까지 바뀔 수 있어서 읽는 사람이 헷갈려요. 바꿀 값은 CHANGING으로 받아요.
직접 해 보기
  1. 위 카드대로 YG##_139를 만들고, 위 코드를 START-OF-SELECTION 부분의 끝(두 번째 PERFORM 아래의 WRITE 문장)까지만 써요. 그 아래 *&--- 주석 줄부터 ENDFORM.까지는 아직 쓰지 않아요. 코드를 이미 통째로 넣었다면 그 부분만 지우고 시작해요.
  2. 저장한 다음 PERFORM calc_discount … 줄의 calc_discount를 더블클릭해 보세요. 아직 없는 FORM을 만들지 물어봐요. Yes를 누르고 프로그램(Main Program)에 만들도록 고르면 FORM … ENDFORM 뼈대를 자동으로 써 줘요. 창에 끝이 F01인 새 이름이 골라져 있으면 그대로 확인하지 말고, 내 프로그램 이름 YG##_139가 적힌 줄을 골라요.
  3. 뼈대의 파라미터 이름은 p_gv_price처럼 들어와요(버전에 따라 모양이 조금 달라요). 위 코드처럼 이름과 TYPE을 고쳐 쓰고, 계산식 한 줄을 넣어요.
  4. 활성화하고 실행해서 두 결과를 확인해요.
  5. 첫 번째 PERFORM 줄에 Breakpoint를 걸고 실행해요(6-3). 디버거가 멈추면 F5를 눌러 보세요. FORM 안으로 들어가요.
  6. FORM 안에 멈춘 채로 디버거 위쪽의 Standard 탭을 눌러요. ABAP and Screen Stack(호출 순서) 칸에 지금 있는 CALC_DISCOUNT와, 나를 부른 START-OF-SELECTION이 차례로 보여요. "누가 나를 불렀지?"가 궁금할 때 보는 곳이에요. 화면 배치는 버전에 따라 조금 달라요.
  7. F5로 계속 내려가다가 두 번째 PERFORM 줄에서는 F6을 눌러 보세요. 이번에는 FORM을 한 번에 실행하고 다음 줄로 넘어가요.

FORM 안에서만 쓰는 변수

FORM 안에서도 DATA로 변수를 만들 수 있어요. 이렇게 만든 변수는 그 FORM 안에서만 쓸 수 있고, FORM이 끝나면 사라져요. 이런 변수를 지역 변수(Local Variable)라고 해요. 어디서나 쓸 수 있는 전역 변수는 이름이 g로 시작했죠. 지역 변수는 l로 시작해서 lv_, ls_, lt_로 이름을 지어요.

YG##_139의 FORM을 아래처럼 바꿔 써 보세요. 결과는 같아요.

FORM calc_discount USING    pv_price  TYPE i
                            pv_rate   TYPE i
                   CHANGING cv_result TYPE i.
  DATA lv_discount TYPE i.                  " 지역 변수: 깎아 줄 금액

  lv_discount = pv_price * pv_rate / 100.
  cv_result   = pv_price - lv_discount.
ENDFORM.

lv_discount는 START-OF-SELECTION이나 다른 FORM에서는 쓸 수 없어요. 쓰면 선언하지 않은 변수라는 문법 오류가 나요. 그래서 다른 곳의 변수와 이름이 겹칠 걱정이 없어요. 계산하는 동안만 잠깐 필요한 값은 전역 변수 말고 지역 변수로 만들어요.

Internal Table을 통째로 넘기기

값 하나가 아니라 Internal Table을 통째로 넘길 수도 있어요. 그런데 FORM의 파라미터 자리에는 TYPE TABLE OF ty_book을 바로 쓸 수 없어요. 그래서 먼저 TYPES로 표의 Type에 이름을 붙여요. 8장의 ty_book으로 보면 이런 모양이에요. 눈으로만 보는 조각이고, 12장 종합 실습에서 직접 써요.

TYPES ty_t_book TYPE STANDARD TABLE OF ty_book WITH DEFAULT KEY.

DATA gt_book TYPE ty_t_book.            " 표 Type으로 만든 Internal Table
...
  PERFORM print_books USING gt_book.    " 표를 통째로 넘겨요
...
FORM print_books USING pt_book TYPE ty_t_book.
  DATA ls_book TYPE ty_book.            " 지역 변수로 만든 Work Area

  LOOP AT pt_book INTO ls_book.
    WRITE: / ls_book-book_id, ls_book-title, ls_book-price.
  ENDLOOP.
ENDFORM.
  • ty_book이 한 줄의 설계도라면 ty_t_book은 그 줄을 여러 개 담는 표의 설계도예요. ty_t_의 t가 표(Table)라는 표시예요. TYPE STANDARD TABLE OF … WITH DEFAULT KEY는 8-2에서 본, TYPE TABLE OF의 긴 모양이에요.
  • 파라미터 이름 pt_book의 t도 Internal Table이라는 뜻이에요. FORM이 표를 바꿔서 돌려줘야 하면 CHANGING ct_book TYPE ty_t_book으로 받아요.
VALUE( )는 복사본을 넘겨요

지금까지 쓴 USING pv_price는 값을 복사해 오지 않아요. pv_price는 부른 쪽 변수 gv_price를 같이 보는 또 하나의 이름이에요. 그래서 FORM 안에서 pv_price를 바꾸면 gv_price도 바뀌어요. 앞의 "자주 하는 실수"에서 USING으로 받은 값을 바꾸지 말라고 한 까닭이에요. FORM에서 USING과 CHANGING의 차이는 컴퓨터가 지켜 주는 것이 아니라 읽는 사람에게 하는 약속이에요.

USING VALUE(pv_price) TYPE i처럼 VALUE( )로 감싸면 복사본을 받아요. FORM 안에서 바꿔도 부른 쪽 변수는 그대로예요. 3-2의 VALUE 10(처음 값)과 글자만 같고 다른 문법이에요.

같은 생각을 이 장에서 두 번 더 만나요. Function Module의 Import 탭에 있는 Pass Value(Pass by Value) 체크 칸, 그리고 10-4의 RETURNING VALUE(rv_price)예요. 둘 다 "복사본으로 주고받아요"라는 뜻이에요.

FORM은 "읽을 줄 알면 되는" 방법이에요

SAP는 FORM(서브루틴)을 새로 만들 때는 쓰지 말라고 안내해요. 새 코드는 10-4의 Method를 권해요. 그래도 회사에 있는 오래된 프로그램에는 PERFORM이 아주 많아서, 읽고 고칠 줄은 알아야 해요. 이 교재에서 FORM을 먼저 배우는 이유는 구조가 가장 단순해서 "나눠 쓰기"를 익히기 좋기 때문이에요.

10-3. 모든 프로그램이 쓰는 기능: Function Module

FORM은 내 프로그램 안에서만 부를 수 있어요. 다른 친구의 프로그램에서도 "할인 가격 계산"을 쓰고 싶다면, 시스템 전체가 함께 쓰는 Function Module로 만들어요.

Function Module은 혼자 있지 않고 Function Group이라는 묶음 안에 들어가요. 그래서 순서는 이래요.

  1. Function Group 만들기 (한 번만): YFG_G##
  2. Function Module 만들기: Y_G##_DISCOUNT
  3. SE37에서 테스트하기
  4. 프로그램에서 부르기: CALL FUNCTION
이름 규칙

Function Group은 다른 객체처럼 Y로 시작해요(YFG_G##). Function Module은 SAP가 권하는 이름이 Y_나 Z_로 시작하는 꼴이에요. 그래서 이 수업에서는 밑줄이 하나 더 들어간 Y_G##_DISCOUNT처럼 써요. 회사 코드에서는 ZFM_…처럼 밑줄 없이 시작하는 이름도 자주 보여요.

1단계: Function Group 만들기

명령 필드에 /nSE37을 넣고 Enter를 누르면 Function Builder가 열려요. 여기서 Function Group부터 만들어요.

새로 만들기Function GroupSE37
Function Group
YFG_G##
Short Description

직접 해 보기
  1. SE37 화면 위쪽 메뉴에서 Goto → Function Groups → Create Group을 골라요.
  2. Function Group에 YFG_G##, Short Text에 G## 연습용 Function Group을 적고 Save를 눌러요. 1 (카드의 Short Description을 이 창에서는 Short Text 칸에 적어요.)
  3. Package를 묻는 창이 뜨면 Local Object를 눌러요(2-2의 단계 3과 같아요). 창이 닫히고 SE37 첫 화면으로 돌아오면 다 된 거예요.

  4. 다 채웠으면 프로그램과 똑같이 저장(Ctrl+S), 검사(Ctrl+F2), 활성화(Ctrl+F3)를 해요. 활성화해야 3단계의 테스트를 할 수 있어요.

Function Module 화면의 탭 중에서 처음에는 네 개만 알면 돼요.

탭 무엇을 적어요?
Attributes 종류. 기본값 Normal Function Module 그대로 둬요.
Import 받을 값 (재료)
Export 돌려줄 값 (결과)
Source code 실제 코드
  • Import 탭: IV_PRICE(정가)는 7장에서 만든 Data Element YDE_G##_PRICE, IV_RATE(할인율)는 정수 I로 적어요. Typing 칸에는 TYPE을 적어요.
  • Export 탭: EV_PRICE(할인가)를 YDE_G##_PRICE로 적어요. 앞머리 IV_는 Import(받을 값), EV_는 Export(돌려줄 값)라는 표시예요.
  • Optional(안 넘겨도 되는 파라미터라는 표시)과 Pass Value(10-2에서 본 복사본으로 받기)는 체크하지 않고 그대로 둬요.
  • Source code 탭을 열어요. SAP가 적어 둔 *" 주석 묶음 아래, ENDFUNCTION. 위에 계산 한 줄만 넣으면 돼요.
FUNCTION y_g##_discount.
*"----------------------------------------------------------------------
*"*"Local Interface:
*"  IMPORTING
*"     REFERENCE(IV_PRICE) TYPE  YDE_G##_PRICE
*"     REFERENCE(IV_RATE) TYPE  I
*"  EXPORTING
*"     REFERENCE(EV_PRICE) TYPE  YDE_G##_PRICE
*"----------------------------------------------------------------------

  ev_price = iv_price - iv_price * iv_rate / 100.

ENDFUNCTION.

*"로 시작하는 주석은 Import·Export 탭에 적은 내용을 SAP가 자동으로 써 준 거예요. 직접 고치지 않아요. 파라미터를 바꾸고 싶으면 탭에서 바꿔요. REFERENCE( )는 Pass Value를 체크하지 않았다는 표시예요. 10-2에서 본 VALUE( )의 반대말로, 원본을 같이 본다는 뜻이에요.

자주 하는 실수
  • 처음 활성화할 때 비활성 객체 목록이 뜨면, Function Group에 딸린 객체(SAPLYFG_G## 등)까지 모두 골라서 함께 활성화해요. Function Group이 비활성이면 Function Module을 불러도 오류가 나요.
  • Associated Type에 없는 이름(오타)을 적으면 저장할 때 오류가 나요. 7장의 Data Element가 활성화되어 있는지 확인해요.

3단계: SE37에서 테스트하기

Function Module은 프로그램을 만들지 않아도 SE37에서 바로 실행해 볼 수 있어요. 만들었으면 꼭 먼저 테스트해요.

직접 해 보기
  1. Function Module 화면이나 SE37 첫 화면에서 F8(Test/Execute)을 눌러요.
  2. IV_PRICE에 25000, IV_RATE에 10을 넣어요. 1
  3. 다시 F8을 눌러요.
  4. 결과 화면의 Export parameters에서 EV_PRICE가 22500인지 확인해요. 2 설정에 따라 22,500처럼 쉼표가 들어가 보일 수 있어요.
  5. 값이 다르면 SE37 첫 화면에서 이름을 넣고 Change를 눌러 고쳐요. 고친 뒤에는 다시 활성화해요.

4단계: 프로그램에서 부르기 (Pattern 버튼)

CALL FUNCTION 문장은 길어서 직접 치면 틀리기 쉬워요. ABAP Editor의 Pattern 버튼(Ctrl+F6)을 쓰면 SAP가 뼈대를 써 줘요. 먼저 Function Module을 부를 프로그램을 만들어요.

새로 만들기ProgramSE38
Program
YG##_140
Title
[예제] Function Module로 할인가 계산
직접 해 보기
  1. 카드대로 YG##_140을 만들고, 조금 아래에 있는 완성 코드에서 START-OF-SELECTION. 줄까지 먼저 써요. 그 아랫줄에 커서를 둬요.
  2. 도구 모음의 Pattern을 눌러요.
  3. CALL FUNCTION을 고르고 Y_G##_DISCOUNT를 입력한 뒤 Enter를 눌러요.
  4. 아래처럼 뼈대가 들어가요. = 뒤에 내 변수를 채우고, 결과를 받을 IMPORTING 두 줄은 앞의 *를 지워서 주석을 풀어요. 맨 아래에 혼자 있는 .은 이 문장의 마침표예요.
" Pattern이 넣어 준 모습
CALL FUNCTION 'Y_G##_DISCOUNT'
  EXPORTING
    iv_price       =
    iv_rate        =
* IMPORTING
*   EV_PRICE       =
          .

WRITE 두 줄까지 쓰고 활성화하면 다 된 거예요. 다 채운 프로그램은 이래요.

REPORT yg##_140.

DATA gv_price TYPE yde_g##_price.

PARAMETERS: pa_price TYPE yde_g##_price DEFAULT 25000,
            pa_rate  TYPE i DEFAULT 10.

START-OF-SELECTION.
  CALL FUNCTION 'Y_G##_DISCOUNT'
    EXPORTING
      iv_price = pa_price
      iv_rate  = pa_rate
    IMPORTING
      ev_price = gv_price.

  WRITE: / '정가  :', pa_price,
         / '할인가:', gv_price.

기본값 그대로 실행(F8)하면 이렇게 나와요. 숫자 앞 공백 칸 수는 조금 달라도 괜찮아요.

정가  :      25,000
할인가:      22,500

여기가 처음에 가장 헷갈리는 곳이에요. Function Module 입장에서 Import(받는 값)는, 부르는 프로그램 입장에서는 내보내는 값이라 EXPORTING에 적어요. 반대로 Function Module의 Export(돌려주는 값)는 프로그램이 받는 값이라 IMPORTING에 적어요.

  • =의 왼쪽은 Function Module의 파라미터 이름, 오른쪽은 내 프로그램의 변수예요.
  • FORM과 달리 이름으로 짝을 지어요. 그래서 순서는 바뀌어도 괜찮아요.
  • 이름은 작은따옴표 안에 대문자로 적어요. 'y_g##_discount'처럼 소문자로 적으면 Function Module을 찾지 못해 실행 중에 덤프(CALL_FUNCTION_NOT_FOUND)가 나요. 덤프 읽는 법은 6-8에서 배웠죠. Pattern 버튼을 쓰면 이런 실수가 없어요.
  • = 오른쪽 변수는 왼쪽 파라미터와 Type이 같아야 해요. ev_price를 TYPE i 변수로 받으면 활성화는 되는데 실행 중에 덤프(CALL_FUNCTION_CONFLICT_TYPE)가 나요. 그래서 gv_price를 TYPE yde_g##_price로 선언했어요.
  • iv_rate 같은 EXPORTING 줄을 빼먹어도 덤프(CALL_FUNCTION_PARM_MISSING)가 나요. 덤프 이름은 외우지 않아도 돼요. 부록 C에 모아 뒀어요.

실패를 알리기: Exceptions

도서 번호를 받아 그 책을 돌려주는 Function Module을 생각해 볼게요. 없는 번호가 들어오면 "못 찾았어요"라고 알려 줘야 해요. 이때 Exceptions 탭을 써요. 같은 Function Group YFG_G##에 하나 더 만들어요. 만드는 순서는 2단계와 같아요.

새로 만들기Function ModuleSE37

ES_BOOK의 Type에 Table 이름 YTA_G##_BOOK을 적으면, 그 Table과 칸이 똑같은 한 줄짜리 Structure가 돼요(8-1에서 본 방법이에요). Exceptions 탭에는 예외 이름 NOT_FOUND를 적어요.

FUNCTION y_g##_get_book.
*"  (자동 주석은 생략했어요)

  SELECT SINGLE * FROM yta_g##_book
    INTO es_book
    WHERE book_id = iv_book_id.

  IF sy-subrc <> 0.
    RAISE not_found.          " 부른 쪽에 "못 찾았어요"를 알리고 끝내요
  ENDIF.

ENDFUNCTION.

활성화했으면 F8로 테스트해 보세요. IV_BOOK_ID에 B0001을 넣으면 ES_BOOK에 책 한 권이 담겨 와요. 없는 번호 B9999를 넣으면 예외 NOT_FOUND가 일어났다고 알려 줘요.

부르는 쪽에서 Pattern 버튼을 쓰면 EXCEPTIONS와 sy-subrc 검사까지 같이 들어와요. EXCEPTIONS 줄들도 IMPORTING처럼 * 주석으로 들어오니 *를 지워서 풀어요. 채우면 이런 모양이에요. 10-5 미니 실습에서 직접 써 볼 거예요.

CALL FUNCTION 'Y_G##_GET_BOOK'
  EXPORTING
    iv_book_id = pa_id
  IMPORTING
    es_book    = gs_book
  EXCEPTIONS
    not_found  = 1            " NOT_FOUND가 일어나면 sy-subrc = 1
    OTHERS     = 2.           " 그 밖의 예외는 sy-subrc = 2

IF sy-subrc <> 0.
  MESSAGE '그런 번호의 책이 없어요' TYPE 'S' DISPLAY LIKE 'E'.
  RETURN.
ENDIF.

RAISE not_found.가 실행되면 Function Module은 그 자리에서 끝나고, 부른 쪽의 sy-subrc에 EXCEPTIONS에 적은 번호가 들어가요. 8장의 "sy-subrc는 방금 한 일의 성적표" 그대로예요.

이 예외는 6-8에서 배운 예외와 이름만 같고, 더 오래된 다른 장치예요. Function Module이 RAISE 이름.으로 알린 예외는 TRY … CATCH로 받을 수 없어요. 꼭 EXCEPTIONS에 번호를 적고 sy-subrc로 확인해요. TRY … CATCH는 6-8의 cx_sy_zerodivide처럼 cx_로 시작하는 예외를 받을 때 써요.

Pattern이 넣어 주는 MESSAGE ID 줄

버전에 따라 Pattern이 IF sy-subrc <> 0.과 ENDIF. 사이에 이런 주석을 넣어 줘요.

* MESSAGE ID SY-MSGID TYPE SY-MSGTY NUMBER SY-MSGNO
*         WITH SY-MSGV1 SY-MSGV2 SY-MSGV3 SY-MSGV4.

5-6에서 본 꼴이에요. "Function Module이 남긴 메시지를 그대로 다시 띄워요"라는 뜻이에요. 우리 Y_G##_GET_BOOK은 RAISE만 하고 메시지를 남기지 않으니, 이 줄은 지우고 위처럼 메시지를 직접 써요. 새 버전에서는 이 자리에 * Implement suitable error handling here라고만 적혀 있어요.

자주 하는 실수

EXCEPTIONS 부분을 지우고 부르면, 예외가 일어났을 때 받을 곳이 없어서 프로그램이 덤프(RAISE_EXCEPTION)로 멈춰요. * 주석인 채로 둬도 지운 것과 똑같아요. Pattern이 넣어 준 EXCEPTIONS와 IF sy-subrc <> 0.은 지우지 말고, *를 풀어서 채워 써요.

10-4. 맛보기: 로컬 클래스의 Method

요즘 새로 만드는 ABAP 코드는 대부분 클래스와 Method로 나눠요. 클래스는 관련된 Method를 한데 묶어 두는 틀이고, 프로그램 안에 직접 쓴 클래스를 로컬 클래스(Local Class)라고 해요. 객체지향은 다음 과정에서 제대로 배우니, 여기서는 "할인 계산"을 Method로 한 번만 바꿔 볼게요.

새로 만들기ProgramSE38
Program
YG##_141
Title
[예제] Method로 할인가 계산
REPORT yg##_141.

PARAMETERS: pa_price TYPE i DEFAULT 25000,
            pa_rate  TYPE i DEFAULT 10.

DATA gv_result TYPE i.

*----------------------------------------------------------------------*
* 클래스 설계도: 무엇을 받고 무엇을 돌려주는지
*----------------------------------------------------------------------*
CLASS lcl_calc DEFINITION.
  PUBLIC SECTION.
    CLASS-METHODS discount
      IMPORTING iv_price        TYPE i
                iv_rate         TYPE i
      RETURNING VALUE(rv_price) TYPE i.
ENDCLASS.

*----------------------------------------------------------------------*
* 실제 코드
*----------------------------------------------------------------------*
CLASS lcl_calc IMPLEMENTATION.
  METHOD discount.
    rv_price = iv_price - iv_price * iv_rate / 100.
  ENDMETHOD.
ENDCLASS.

START-OF-SELECTION.
  gv_result = lcl_calc=>discount( iv_price = pa_price
                                  iv_rate  = pa_rate ).
  WRITE: / '할인가:', gv_result.

기본값 그대로 실행하면 한 줄이 나와요.

할인가:     22,500

처음 보는 단어가 많지만, 구조는 FORM과 비슷해요.

부분 뜻
CLASS lcl_calc DEFINITION 설계도. 어떤 Method가 있고 무엇을 받고 돌려주는지 적어요. lcl_은 Local Class라는 뜻이에요.
PUBLIC SECTION 이 아래에 적은 Method는 클래스 밖에서도 부를 수 있다는 표시예요.
CLASS-METHODS 클래스 이름으로 바로 부를 수 있는 Method예요.
IMPORTING iv_price … Method가 받는 값이에요. Function Module의 Import 탭과 같아요. 부를 때는 EXPORTING이라는 말 없이 괄호 안에 이름 = 값만 적어도 돼요.
RETURNING VALUE(rv_price) 결과 하나를 돌려줘요. 그래서 gv_result = …( )처럼 계산식 오른쪽에 바로 쓸 수 있어요. 앞머리 rv_는 Returning이라는 표시예요. VALUE( )는 10-2에서 본 "복사본으로 넘기기"예요. RETURNING에는 꼭 붙여요.
CLASS lcl_calc IMPLEMENTATION 실제 코드예요. METHOD … ENDMETHOD 안에 써요.
lcl_calc=>discount( … ) 부르기. =>는 "이 클래스의"라는 뜻이에요.
자주 하는 실수
  • 클래스는 쓰기 전에(위쪽에) 있어야 해요. START-OF-SELECTION보다 아래에 CLASS … DEFINITION을 두면 "lcl_calc를 모른다"는 오류가 나요.
  • 부를 때 괄호 안쪽 앞뒤를 한 칸씩 띄워요. discount(iv_price = pa_price …)처럼 붙여 쓰면 오류가 나요.

셋을 한눈에 비교하기

FORM Function Module Method
만드는 곳 내 프로그램 안 SE37 (Function Group 안) 클래스 안 (로컬, 또는 모두가 쓰는 클래스를 만드는 SE24)
부를 수 있는 곳 내 프로그램만 모든 프로그램 로컬은 내 프로그램, SE24 클래스는 모든 프로그램
부르는 방법 PERFORM CALL FUNCTION '이름' 클래스=>Method( )
값 짝짓기 순서 이름 이름
실패 알리기 (없음) EXCEPTIONS + sy-subrc 예외 클래스 (6-8에서 본 TRY … CATCH로 받아요)
요즘 쓰임새 읽을 줄 알면 돼요 아주 많이 써요 새 코드의 기본
SAP가 만들어 둔 Function Module

SAP가 만들어 둔 Function Module도 아주 많아요. 예를 들어 날짜 계산, 숫자를 글자로 바꾸기 같은 일은 이미 만들어진 Function Module을 찾아 쓰는 경우가 많아요. SE37에서 이름 칸에 *DATE*처럼 별표를 넣고 F4를 누르면 찾아볼 수 있어요. 처음 쓰는 Function Module은 SE37에서 먼저 테스트해 보고 쓰는 습관을 들여요.

                      pv_price TYPE yde_g##_price.

확인 문제
  1. 아래 PERFORM을 실행한 뒤 gv_c의 값은 얼마일까요? 
    gv_a = 3. gv_b = 4.
PERFORM add USING gv_a gv_b CHANGING gv_c.

FORM add USING pv_x TYPE i pv_y TYPE i CHANGING cv_sum TYPE i.
  cv_sum = pv_x + pv_y.
ENDFORM.
  2. Function Module에서 Import 탭에 적은 파라미터는, CALL FUNCTION에서 EXPORTING과 IMPORTING 중 어디에 적을까요?
  3. CALL FUNCTION 'Y_G##_GET_BOOK'으로 없는 도서 번호를 넘겼더니 sy-subrc가 1이었어요. 무슨 뜻일까요?
  4. Function Module을 프로그램에서 부르기 전에 SE37에서 먼저 해 보면 좋은 일은 무엇일까요?
  5. FORM과 Function Module 중, 다른 친구의 프로그램에서도 부를 수 있는 것은 무엇일까요?
  6. FORM 안에서 DATA lv_discount TYPE i.로 만든 변수를 START-OF-SELECTION에서도 쓸 수 있을까요?
  7. Internal Table gt_book을 FORM에 넘기려고 해요. FORM 줄의 파라미터에 Type을 적으려면 먼저 무엇을 만들어 둬야 할까요?
정답 보기

정리
  • 모듈화는 코드를 이름 붙인 덩어리로 나눠서 다시 쓰고, 고치기 쉽고, 읽기 쉽게 만드는 일이에요.
  • FORM … ENDFORM을 PERFORM으로 불러요. 재료는 USING, 결과는 CHANGING으로 주고받고, 짝은 순서로 정해져요. 새로 만들기보다는 읽을 줄 알면 돼요.
  • FORM 안에서 DATA로 만든 변수는 그 안에서만 쓰는 지역 변수(lv_, ls_, lt_)예요. Internal Table은 TYPES로 표 Type(ty_t_…)에 이름을 붙여서 넘겨요. VALUE( )는 복사본으로 주고받는다는 뜻이에요.
  • Function Module은 SE37에서 Function Group 안에 만들고, F8로 테스트하고, Pattern 버튼으로 CALL FUNCTION을 넣어요.
  • 부르는 쪽에서는 방향이 반대예요. Function Module의 Import는 EXPORTING, Export는 IMPORTING에 적어요.
  • Function Module의 실패는 RAISE로 알리고, 부르는 쪽은 EXCEPTIONS와 sy-subrc로 확인해요. 6-8의 TRY … CATCH로는 받을 수 없어요.
  • 새 코드의 기본은 클래스의 Method예요. 클래스=>Method( )로 불러요.
