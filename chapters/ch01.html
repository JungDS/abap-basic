1장

SAP 시스템과 SAP GUI 첫걸음

이번 장 목표
  • SAP 시스템, 클라이언트, Repository가 무엇인지 그림으로 설명할 수 있어요.
  • SAP GUI로 로그인하고 첫 화면(SAP Easy Access)의 각 부분을 알아봐요.
  • 트랜잭션 코드로 원하는 화면에 바로 이동할 수 있어요.
  • 내가 만든 프로그램이 어디에 저장되는지(Package, Local Object) 알아요.

1-1. SAP 시스템은 하나가 아니에요

회사에는 보통 SAP 시스템이 세 개 있어요. 새 프로그램을 바로 실제 업무 시스템에서 만들면 실수 하나로 회사 업무가 멈출 수 있거든요. 그래서 만드는 곳, 시험하는 곳, 실제로 쓰는 곳을 나눠 둬요.

DEV에서 만든 프로그램은 Transport라는 택배 상자에 담겨 QAS로, 다시 PRD로 옮겨져요. 우리 수업에서 접속하는 곳은 DEV 같은 개발용 시스템이에요. 마음 편히 만들고 지워 봐도 괜찮아요.

1-2. 한 시스템 안의 클라이언트

시스템 하나는 아파트 한 동이라고 생각하면 쉬워요.

  • 건물의 뼈대(계단, 엘리베이터, 수도관)는 모든 집이 함께 써요. SAP에서는 이것이 Repository예요. 프로그램 소스, Table의 설계도 같은 것이 여기에 있어요.
  • 집집마다 들어 있는 가구와 살림살이는 그 집만의 것이에요. SAP에서는 이것이 클라이언트(Client)별 데이터예요. 세 자리 번호(예: 100, 200)로 집을 구분해요.

그래서 프로그램은 한 번 만들면 모든 클라이언트에서 보이지만, Table에 넣은 데이터는 내가 로그인한 클라이언트에서만 보여요.

이게 왜 중요해요? MANDT 이야기

Table의 첫 번째 필드에 MANDT(Type CLNT)를 넣는 이유가 바로 이거예요. MANDT는 "이 줄은 몇 번 집 데이터인가"를 적어 두는 칸이에요. 이 칸이 있어야 SAP가 클라이언트마다 데이터를 알아서 나눠 줘요. 7장에서 Table을 만들 때 다시 볼게요.

1-3. SAP GUI로 로그인하기

SAP 시스템에 들어가는 프로그램이 SAP GUI예요. 컴퓨터에 설치된 SAP Logon을 실행하면 접속할 시스템 목록이 보여요.

직접 해 보기 · 로그인
  1. SAP Logon을 실행해요. Windows 시작 메뉴에서 "SAP Logon"을 검색하면 나와요.
  2. 목록에서 수업 시스템을 골라 1 두 번 클릭하거나 2 Log On 버튼을 눌러요.
  3. 로그인 화면에서 Client, User, Password, Language를 입력하고 Enter를 눌러요. 값은 수업에서 안내받은 그대로 넣으면 돼요.
그림 속 S4D, 100은 예시예요

시스템 이름과 클라이언트 번호는 수업 시스템마다 달라요. 꼭 수업에서 안내받은 값을 쓰세요. 처음 로그인하면 비밀번호를 새로 바꾸라는 창이 뜰 수 있는데, 정상이에요.

1-4. 첫 화면 둘러보기: SAP Easy Access

로그인하면 SAP Easy Access 화면이 나와요. 앞으로 거의 모든 화면이 이 모양을 따르니까, 각 부분의 이름을 한 번 익혀 두면 편해요.

번호 이름 하는 일
1 메뉴 바 화면마다 메뉴가 달라져요. 기능을 못 찾겠으면 여기서 찾아요.
2 명령 필드(Command Field) 트랜잭션 코드를 입력하는 칸이에요. 가장 많이 쓸 곳이에요!
3 표준 도구 모음 저장, 뒤로(F3), 나가기, 취소(F12)처럼 어느 화면에서나 같은 버튼이에요.
4 화면 제목 지금 어느 화면에 있는지 알려 줘요.
5 즐겨찾기 자주 쓰는 트랜잭션을 등록해 둘 수 있어요.
6 상태 표시줄 오류, 경고, 완료 메시지가 나와요. 뭔가 안 되면 여기부터 보세요.
명령 필드가 안 보여요

화면 테마에 따라 명령 필드가 접혀 있을 수 있어요. 왼쪽 위 도구 모음 근처의 작은 화살표(▸)를 누르면 펼쳐져요.

1-5. 트랜잭션 코드로 이동하기

트랜잭션 코드(Transaction Code, T-code)는 화면마다 붙은 바로 가기 주소예요. 메뉴를 하나하나 눌러 찾아가는 대신, 명령 필드에 코드를 넣고 Enter를 누르면 바로 이동해요.

직접 해 보기 · SE38로 이동하기
  1. 명령 필드에 SE38을 입력하고 Enter를 눌러요. ABAP Editor 첫 화면이 나오면 성공이에요.
  2. 이번엔 명령 필드에 /nSE11을 입력하고 Enter를 눌러요. 지금 화면을 닫고 ABAP Dictionary 화면으로 바뀌어요.
  3. /oSE38을 입력해 보세요. 새 창에 ABAP Editor가 하나 더 열려요.
  4. 마지막으로 /n만 입력하면 처음 화면(SAP Easy Access)으로 돌아와요.
입력 뜻 언제 쓰나요
SE38 해당 화면으로 이동 지금 첫 화면(SAP Easy Access)에 있을 때
/nSE38 지금 화면을 닫고 이동 다른 화면에 들어가 있을 때 (new)
/oSE38 새 창을 열어서 이동 지금 화면은 그대로 두고 싶을 때 (open)
/n 처음 화면으로 길을 잃었을 때
자주 하는 실수
  • 다른 화면 안에서 SE38만 입력하면 아무 일도 안 일어날 수 있어요. 이럴 땐 앞에 /n을 붙이세요.
  • /n으로 화면을 나가면 저장하지 않은 내용은 사라져요. 코드를 고치는 중이었다면 먼저 저장하세요.
  • 창(세션)은 보통 6개까지만 열려요. /o로 계속 열다 보면 더 이상 안 열리니, 안 쓰는 창은 닫아 주세요.

이 교재에서 만날 트랜잭션 코드

T-code 화면 이름 하는 일 나오는 장
SE38 ABAP Editor 프로그램을 만들고 실행해요 2장부터 계속
SE11 ABAP Dictionary Domain, Data Element, Table을 만들어요 7장
SE16N Data Browser Table에 들어 있는 데이터를 조회해요 7장, 9장
SE80 Object Navigator 여러 개발 객체를 한 화면에서 봐요 10장

1-6. 내가 만든 프로그램은 어디에 저장될까

프로그램을 처음 저장하면 SAP가 "어느 Package에 넣을까요?"라고 물어봐요. Package는 개발 객체를 담는 폴더예요.

  • 회사에서는 프로젝트별 Package에 저장하고, 변경 내용을 Transport Request(택배 상자)에 담아요. 이런 Package와 그 안의 객체는 보통 Z로 시작해요(ZSALES, ZSD_REPORT01).
  • 혼자 연습하는 프로그램은 Local Object로 저장해요. Package 이름이 $TMP로 들어가고, 다른 시스템으로 옮겨지지 않아요. 연습용은 Y로 시작하는 이름을 붙여서 한눈에 구분해요(YG05_02_HELLO).

이 교재의 실습은 특별한 안내가 없으면 Local Object로 저장해요. 2장에서 직접 해 볼 거예요.

확인 문제
  1. 개발 시스템에서 만든 프로그램을 운영 시스템으로 옮길 때 쓰는 "택배 상자"의 이름은 무엇일까요?
  2. 클라이언트 100에서 만든 프로그램을 클라이언트 200에서 볼 수 있을까요? 클라이언트 100에서 Table에 넣은 데이터는요?
  3. ABAP Editor에서 코드를 보다가, 지금 화면은 그대로 두고 새 창으로 SE11을 열고 싶어요. 명령 필드에 무엇을 입력할까요?
  4. 버튼을 눌렀는데 아무 반응이 없는 것 같아요. 가장 먼저 어디를 봐야 할까요?
정답 보기
  1. Transport (정확히는 Transport Request)예요.
  2. 프로그램은 볼 수 있어요. 프로그램은 모든 클라이언트가 함께 쓰는 Repository에 있으니까요. 데이터는 볼 수 없어요. MANDT가 있는 Table의 데이터는 클라이언트마다 따로예요.
  3. /oSE11
  4. 화면 맨 아래 상태 표시줄이에요. 오류나 안내 메시지가 거기에 나와요.
정리
  • 회사에는 보통 DEV → QAS → PRD 세 시스템이 있고, 프로그램은 Transport로 옮겨져요.
  • 프로그램(Repository)은 모든 클라이언트가 함께 쓰고, 데이터는 클라이언트마다 따로예요. 그래서 Table에 MANDT가 필요해요.
  • 트랜잭션 코드는 화면 바로 가기예요. /n은 이동, /o는 새 창이에요.
  • 연습용 프로그램은 Local Object($TMP)로 저장해요.
