1장

SAP 시스템과 SAP GUI 첫걸음

이번 장 목표
  • SAP 시스템, 클라이언트, Repository가 무엇인지 그림으로 설명할 수 있어요.
  • ABAP 코드가 내 PC가 아니라 서버에서 실행된다는 것을 알아요.
  • SAP GUI로 로그인하고 첫 화면(SAP Easy Access)의 각 부분을 알아봐요.
  • 트랜잭션 코드로 원하는 화면에 바로 이동할 수 있어요.
  • 내가 만든 프로그램이 어디에 저장되는지(Package, Local Object) 알아요.

1-1. SAP 시스템은 하나가 아니에요

회사에는 보통 SAP 시스템이 세 개 있어요. 새 프로그램을 바로 실제 업무 시스템에서 만들면 실수 하나로 회사 업무가 멈출 수 있거든요. 그래서 만드는 곳, 시험하는 곳, 실제로 쓰는 곳을 나눠 둬요.

DEV, QAS, PRD는 Development(개발), Quality Assurance(품질 확인), Production(운영)을 줄인 이름이에요. DEV에서 만든 프로그램은 Transport Request라는 택배 상자에 담겨 QAS로, 다시 PRD로 옮겨져요. 이렇게 옮기는 일을 Transport라고 해요.

우리 수업에서 접속하는 곳은 DEV 같은 개발용 시스템이에요. 내 번호가 들어간 이름으로 만든 것은 마음 편히 만들고 지워 봐도 괜찮아요. 다른 사람이 만든 것과 SAP가 만든 것은 열어 보기만 하고, 고치거나 지우지 않아요.

1-2. 한 시스템 안의 클라이언트

시스템 하나는 아파트 한 동이라고 생각하면 쉬워요.

  • 건물의 뼈대(계단, 엘리베이터, 수도관)는 모든 집이 함께 써요. SAP에서는 이것이 Repository예요. 프로그램 소스, Table(데이터를 줄과 칸으로 담아 두는 표)의 설계도 같은 것이 여기에 있어요.
  • 집집마다 들어 있는 가구와 살림살이는 그 집만의 것이에요. SAP에서는 이것이 클라이언트(Client)별 데이터예요. 세 자리 번호(예: 100, 200)로 집을 구분해요.

SAP의 클라이언트는 웹에서 말하는 클라이언트(서버에 접속하는 브라우저 쪽)와 다른 말이에요. 한 시스템 안에서 데이터를 따로 쓰는 집 하나를 가리켜요.

그래서 프로그램은 한 번 만들면 모든 클라이언트에서 보이지만, Table에 넣은 데이터는 내가 로그인한 클라이언트에서만 보여요.

이게 왜 중요해요? MANDT 이야기

업무 데이터를 담는 Table에는 대부분 맨 앞에 MANDT라는 칸(Field)이 있어요. 까닭이 바로 이거예요. MANDT는 "이 줄은 몇 번 집 데이터인가"를 적어 두는 칸이에요. 이 칸이 있어야 SAP가 클라이언트마다 데이터를 알아서 나눠 줘요. 7장에서 Table을 만들 때 직접 넣어 볼게요.

ABAP 코드는 내 PC가 아니라 서버에서 돌아요

이 아파트(SAP 시스템)는 내 PC가 아니라 멀리 있는 서버에 있어요. 그래서 다른 PC에서 로그인해도 내 프로그램과 데이터가 그대로 있어요. 화면 ↔ ABAP 서버 ↔ DB, 세 곳이 이어져서 일해요.

  • 화면: 내 PC에서 켜는 SAP GUI예요. 입력을 서버로 보내고 결과를 보여 줘요.
  • ABAP 서버: ABAP 프로그램이 실행되는 곳이에요. 우리가 쓴 코드는 여기서 돌아요.
  • DB: Table의 데이터가 저장된 곳이에요. ABAP 서버가 필요할 때 읽고 써요.

SAPUI5 앱도 구조가 같아요. 화면 자리에 브라우저가 들어가요. JavaScript는 브라우저에서 돌지만, ABAP 코드는 이때도 서버에서 돌아요. 다음 과정의 "연동"은 브라우저의 앱이 ABAP 서버의 코드를 부르는 일이에요.

1-3. SAP GUI로 로그인하기

SAP 시스템에 들어가는 프로그램이 SAP GUI예요. SAP GUI를 설치하면 SAP Logon이라는 프로그램이 함께 깔려요. 이것을 실행하면 접속할 시스템 목록이 보여요.

직접 해 보기 · 로그인
  1. SAP Logon을 실행해요. Windows 시작 메뉴에서 "SAP Logon"을 검색하면 나와요.
  2. 목록(그림 1-3)에서 수업 시스템을 골라 1 더블클릭(빠르게 두 번 클릭)하거나 2 Log On 버튼을 눌러요. 목록에 수업 시스템이 안 보이면 강사에게 물어봐요.
  3. 로그인 화면(그림 1-4)에서 Client, User, Password, Language를 입력하고 Enter를 눌러요. 값은 수업에서 안내받은 그대로 넣으면 돼요.
  4. SAP Easy Access 화면(그림 1-5)이 나오면 로그인된 거예요.
로그인할 때 알아 둘 것

그림 속 시스템 이름 S4D와 클라이언트 번호 100은 예시예요. 꼭 수업에서 안내받은 값을 쓰세요.

  • 처음 로그인하면 비밀번호를 새로 바꾸라는 창이 뜰 수 있어요. 정상이에요. 새 비밀번호를 두 번 넣으면 돼요.
  • 비밀번호를 여러 번 틀리면 ID가 잠겨요. 그때는 강사에게 풀어 달라고 해요.
  • Language는 늘 같은 값으로 로그인해요. 프로그램의 Title처럼 내가 넣는 글자는 로그인한 언어마다 따로 저장돼요. 다른 언어로 들어가면 넣어 둔 글자가 비어 보일 수 있어요.
  • 같은 ID가 이미 로그인되어 있다는 창이 뜨면, 전에 로그인한 것이 아직 남아 있는 거예요. "이번 로그인으로 계속하고 다른 로그인은 끝내기" 쪽(보통 첫 번째 선택지)을 골라요. 끊기는 쪽에서 저장하지 않은 내용은 사라져요.

1-4. 첫 화면 둘러보기: SAP Easy Access

로그인하면 SAP Easy Access 화면이 나와요. 앞으로 만날 화면도 같은 부분들로 이루어져 있으니까, 각 부분의 이름을 한 번 익혀 두면 편해요.

번호 이름 하는 일
1 메뉴 바 화면마다 메뉴가 달라져요. 기능을 못 찾겠으면 여기서 찾아요.
2 명령 필드(Command Field) 트랜잭션 코드(원하는 화면으로 바로 가는 짧은 코드. 1-5에서 배워요)를 입력하는 칸이에요. 가장 많이 쓸 곳이에요! 왼쪽의 ✓ 버튼은 Enter와 같아요.
3 표준 도구 모음 저장(Ctrl+S), 뒤로(F3), 나가기(Shift+F3), 취소(F12)처럼 어느 화면에서나 같은 버튼이에요.
4 화면 제목 지금 어느 화면에 있는지 알려 줘요.
5 화면별 도구 모음(Application Toolbar) 화면마다 달라지는 버튼 줄이에요. 2장에서 쓸 검사, 활성화, 실행 버튼이 이 줄에 나와요.
6 즐겨찾기 자주 쓰는 트랜잭션 코드를 등록해 둘 수 있어요. 메뉴 Favorites → Insert transaction으로 넣어요.
7 상태 표시줄 오류, 경고, 완료 메시지가 나와요. 뭔가 안 되면 여기부터 보세요. 오른쪽 끝의 S4D (1) 100은 차례로 시스템 이름, 창 번호, 클라이언트 번호예요.

3의 뒤로, 나가기, 취소는 비슷해 보여도 하는 일이 달라요. 뒤로(Back)는 바로 앞 화면으로 한 단계 돌아가요. 나가기(Exit)는 하던 기능을 끝내고 나가요. 취소(Cancel)는 하던 입력을 그만둬요. 지금은 뒤로(F3) 하나만 기억해도 충분해요. 2장부터 자주 누를 버튼이에요.

내 화면이 그림과 조금 달라요

SAP GUI는 버전과 화면 테마에 따라 생김새가 달라요. 요즘 테마에서는 도구 모음이 한 줄로 합쳐져 있거나, 메뉴가 More 버튼 안에 들어가 있기도 해요. 자리는 달라도 버튼 이름과 단축키는 같아요. 버튼이 안 보이면 단축키(저장 Ctrl+S, 뒤로 F3)를 쓰거나 More 안에서 찾아요.

명령 필드가 안 보이면 접혀 있을 수 있어요. 왼쪽 위 도구 모음 근처의 작은 화살표(▸)를 누르면 펼쳐져요. 화살표의 자리는 테마에 따라 조금 달라요. 못 찾겠으면 강사에게 물어봐요.

1-5. 트랜잭션 코드로 이동하기

트랜잭션 코드(Transaction Code, T-code)는 SAP의 기능마다 붙은 바로 가기 주소예요. 메뉴를 하나하나 눌러 찾아가는 대신, 명령 필드에 코드를 넣고 Enter를 누르면 그 기능의 화면으로 바로 이동해요.

직접 해 보기 · SE38로 이동하기
  1. 명령 필드에 SE38을 입력하고 Enter를 눌러요. ABAP Editor 첫 화면이 나오면 성공이에요. 화면 제목이 ABAP Editor: Initial Screen이면 맞아요.
  2. 이번엔 명령 필드에 /nSE11을 입력하고 Enter를 눌러요. 지금 화면을 닫고 ABAP Dictionary 화면으로 바뀌어요. 화면 제목은 ABAP Dictionary: Initial Screen이에요.
  3. /oSE38을 입력해 보세요. 새 창이 하나 더 열리고 거기에 ABAP Editor가 나와요. 처음 창에는 ABAP Dictionary가 그대로 있어요.
  4. 새 창의 명령 필드에 /n만 입력해요. 그 창이 첫 화면(SAP Easy Access)으로 바뀌어요.
  5. 새 창은 이제 필요 없으니 창 오른쪽 위의 X를 눌러 닫아요. 창이 여러 개일 때는 그 창만 닫혀요. 창이 하나뿐일 때 X를 누르면 로그오프할지 물어요.
입력 뜻 언제 쓰나요
SE38 그 기능의 화면으로 이동 지금 첫 화면(SAP Easy Access)에 있을 때
/nSE38 지금 화면을 닫고 이동 다른 화면에 들어가 있을 때 (new: 같은 창에서 새로 시작)
/oSE38 새 창을 열어서 이동 지금 화면은 그대로 두고 싶을 때 (open: 창을 하나 더 열기)
/n 첫 화면(SAP Easy Access)으로 길을 잃었을 때
자주 하는 실수
  • 다른 화면 안에서 SE38만 입력하면 아무 일도 안 일어나거나 상태 표시줄에 오류 메시지가 나올 수 있어요. 이럴 땐 앞에 /n을 붙이세요.
  • /n으로 화면을 나가면 저장하지 않은 내용은 사라져요. 코드를 고치는 중이었다면 먼저 저장하세요.
  • 창(세션)은 보통 6개까지만 열려요. /o로 계속 열다 보면 더 이상 안 열리니, 안 쓰는 창은 오른쪽 위의 X로 닫아 주세요.
  • 명령 필드에 ㄴㄷ38처럼 한글이 쳐지면 한/영 키를 눌러 영문으로 바꿔요. T-code는 대문자든 소문자든 똑같이 돼요(/nse38도 돼요).

끝낼 때: 로그오프

수업을 마칠 때는 메뉴 System → Log Off로 나가요. 정말 나갈지 묻는 창이 뜨면 Yes를 눌러요. 저장하지 않은 내용은 사라지니 먼저 저장해요.

이 교재에서 만날 트랜잭션 코드

지금 외울 필요는 없어요. 낯선 낱말은 그 장에서 하나씩 풀어 줄게요.

T-code 이름 하는 일 배우는 장
SE38 ABAP Editor 프로그램을 만들고 실행해요 2장부터 계속
SE91 Message Maintenance 프로그램이 보여 줄 메시지를 한곳에 모아 둬요 5장
ST22 ABAP Dump Analysis 실행 중에 멈춘 프로그램의 원인을 찾아봐요 6장
SE11 ABAP Dictionary Domain, Data Element, Table, Structure를 만들어요 7장, 11장
SE16N General Table Display Table에 들어 있는 데이터를 조회해요 7장, 9장
SE37 Function Builder Function Module을 만들고 테스트해요 10장
SE24 Class Builder SAP가 만들어 둔 클래스를 열어 봐요 11장
SE80 Object Navigator 프로그램을 이루는 부분들을 한 화면에서 봐요 12장

표의 T-code는 모두 SAP가 만들어 둔 도구를 여는 코드예요. 우리가 만들 연습 프로그램에는 T-code가 없어요. SE38에서 프로그램 이름을 넣고 실행해요. 2장에서 해 볼게요.

1-6. 내가 만든 프로그램은 어디에 저장될까

프로그램을 처음 저장하면 SAP가 "어느 Package에 넣을까요?"라고 물어봐요. Package는 프로그램, Table 같은 객체를 담는 폴더예요.

  • 회사에서는 프로젝트별 Package에 저장하고, 변경 내용을 Transport Request(택배 상자)에 담아요. 그림의 ZSALES, ZSD_REPORT01은 회사에서 볼 법한 이름의 예시예요.
  • 혼자 연습하는 프로그램은 Package를 묻는 창에서 Local Object 버튼을 눌러 저장해요. Package 이름이 $TMP로 들어가고, 다른 시스템으로 옮겨지지 않아요. 우리가 만들 YG##_101 같은 프로그램이 여기에 들어가요.

그림에서는 이름이 Z와 Y로 나뉘어 있지만, 첫 글자가 저장하는 곳을 정하는 것은 아니에요. Y로 시작하는 것은 이 수업의 약속일 뿐이에요(0-3). 다른 시스템으로 옮겨지는지는 이름이 아니라 저장할 때 고른 곳(Package인지 Local Object인지)이 정해요.

이 교재의 실습은 특별한 안내가 없으면 Local Object로 저장해요. 2장에서 직접 해 볼 거예요.

회사에서는 이렇게 달라요

회사에서는 저장할 때 Local Object 버튼을 누르지 않아요.

  • Package를 묻는 창에 팀에서 정해 준 Package 이름을 넣고 저장해요.
  • 그러면 Transport Request를 고르는 창이 한 번 더 떠요. "이 변경을 어느 택배 상자에 담을까요?"라고 묻는 창이에요. 보통 팀에서 정해 준 Request를 골라요.
  • 내 Request와 그 안에 담긴 객체는 SE09(Transport Organizer)에서 볼 수 있어요.
  • 다른 사람이 고치는 중인 객체를 고치려고 하면 잠겨 있다는 안내가 나와요. 고장이 아니에요. 그 사람에게 먼저 물어봐요.

수업 계정에는 이런 권한이 없을 수 있어서 따라 하지는 않아요. "회사에서는 창이 하나 더 뜬다"는 것만 기억해 두면 돼요.

확인 문제
  1. 개발 시스템에서 만든 프로그램을 운영 시스템으로 옮길 때 쓰는 "택배 상자"의 이름은 무엇일까요?
  2. 클라이언트 100에서 만든 프로그램을 클라이언트 200에서 볼 수 있을까요? 클라이언트 100에서 Table에 넣은 데이터는요?
  3. 우리가 쓴 ABAP 코드는 내 PC에서 실행될까요, 서버에서 실행될까요? 그때 SAP GUI는 무슨 일을 할까요?
  4. ABAP Editor에서 코드를 보다가, 지금 화면은 그대로 두고 새 창으로 SE11을 열고 싶어요. 명령 필드에 무엇을 입력할까요?
  5. 버튼을 눌렀는데 아무 반응이 없는 것 같아요. 가장 먼저 어디를 봐야 할까요?
  6. 친구가 "이름이 Y로 시작하니까 다른 시스템으로 안 옮겨지는 거지?"라고 물어요. 맞는 말일까요?
정답 보기
  1. Transport Request예요. 이 상자에 담아 옮기는 일을 Transport라고 해요.
  2. 프로그램은 볼 수 있어요. 프로그램은 모든 클라이언트가 함께 쓰는 Repository에 있으니까요. 데이터는 볼 수 없어요. MANDT가 있는 Table의 데이터는 클라이언트마다 따로예요.
  3. 서버(ABAP 서버)에서 실행돼요. SAP GUI는 내가 입력한 것을 서버로 보내고, 돌아온 결과를 보여 주는 화면이에요.
  4. /oSE11
  5. 화면 맨 아래 상태 표시줄이에요. 오류나 안내 메시지가 거기에 나와요.
  6. 아니에요. Y로 시작하는 이름은 이 수업의 약속일 뿐이에요. 옮겨지는지는 저장할 때 고른 곳이 정해요. Local Object($TMP)로 저장해서 옮겨지지 않는 거예요.
정리
  • 회사에는 보통 DEV → QAS → PRD 세 시스템이 있고, 프로그램은 Transport로 옮겨져요.
  • 프로그램(Repository)은 모든 클라이언트가 함께 쓰고, 데이터는 클라이언트마다 따로예요. 그래서 Table에 MANDT가 필요해요.
  • ABAP 코드는 내 PC가 아니라 서버에서 돌아요. SAP GUI는 입력을 보내고 결과를 보여 주는 화면이에요.
  • 화면에서 가장 많이 쓸 곳은 명령 필드예요. 뭔가 안 되면 맨 아래 상태 표시줄부터 봐요.
  • 트랜잭션 코드는 원하는 기능의 화면으로 바로 가는 주소예요. /n을 붙이면 지금 화면을 닫고 이동하고, /o를 붙이면 새 창으로 열어요.
  • 연습용 프로그램은 Local Object($TMP)로 저장해요. 다른 시스템으로 옮겨지는지는 이름이 아니라 저장할 때 고른 곳이 정해요.
다음 장 예고
