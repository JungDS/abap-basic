9장

Open SQL

이번 장 목표
  • DB Table의 데이터를 SELECT로 읽어 Internal Table에 담을 수 있어요.
  • WHERE로 원하는 줄만, Field 목록으로 원하는 칸만 가져올 수 있어요.
  • SELECT SINGLE로 한 줄만 읽고, sy-subrc·sy-dbcnt로 결과를 확인할 수 있어요.
  • SELECT-OPTIONS로 범위 조건을 입력받아 IN으로 걸러 낼 수 있어요.
  • Table 두 개를 INNER JOIN으로 이어 읽을 수 있어요.
  • INSERT·UPDATE·MODIFY·DELETE로 DB Table을 바꾸고, 처음 상태로 되돌릴 수 있어요.

9-1. DB에서 메모리로

DB에게 "이런 데이터를 주세요", "이렇게 바꿔 주세요" 하고 부탁할 때 쓰는 말을 SQL이라고 해요. ABAP 프로그램 안에서 쓰는 SQL이 Open SQL(요즘 이름은 ABAP SQL)이에요. 7장에서 만든 YTA_G##_BOOK을 읽어서, 8장에서 배운 Internal Table에 담는 것이 이번 장의 첫 목표예요.

9-2. 전부 읽어 오기: SELECT … INTO TABLE

7-7에서 넣은 다섯 권을 조건 없이 전부 읽어서 한 줄씩 출력해 볼게요. 시작하기 전에 /nSE16N에서 YTA_G##_BOOK을 조회해서 다섯 줄이 있는지 먼저 확인해요. 이 장의 결과는 모두 그 다섯 줄 기준이에요. 줄 수나 값이 7-7의 표와 다르면 9-7의 YG##_137(도서 데이터 처음 상태로 되돌리기)을 먼저 만들어 실행해도 돼요.

이 장에서도 카드가 붙은 예제는 2-2에서 한 순서대로 새 프로그램을 만들어 실행해요. 카드 없이 나오는 짧은 코드는 눈으로만 봐요.

[예제] 도서 전체 조회

DATA: gt_book TYPE TABLE OF yta_g##_book,  " DB Table과 같은 모양의 Internal Table
      gs_book TYPE yta_g##_book.           " 같은 모양의 Work Area

START-OF-SELECTION.
  SELECT * FROM yta_g##_book INTO TABLE gt_book.

  LOOP AT gt_book INTO gs_book.
    WRITE: / gs_book-book_id, gs_book-title(20), gs_book-price, gs_book-stock.
  ENDLOOP.

활성화하고 실행하면 SE16N에서 본 다섯 줄이 그대로 나와요. 이 장의 실행 결과는 칸 사이 빈칸을 줄여서 적었어요. 실제 화면에서는 숫자 앞이 더 넓게 벌어져요.

B0001 ABAP 첫걸음   25,000  3
B0002 바다의 노래   15,000  0
B0003 오늘의 산책   13,000  5
B0004 SQL 한 그릇   28,000  2
B0005 별을 세는 밤  17,000  7
  • INTO TABLE은 읽은 줄을 모두 Internal Table에 담아요. 원래 들어 있던 줄은 지워지고 새로 채워져요.
  • MANDT는 신경 쓰지 않아도 돼요. SAP가 지금 로그인한 클라이언트의 데이터만 알아서 골라 줘요(1장 1-2).
  • gs_book-title(20)은 3-6에서 배운 글자 일부만 꺼내기예요. 칸 이름 뒤에 (20)을 붙여서 앞 20칸만 출력해요. 제목이 40칸이라 줄이 너무 길어지지 않게 했어요.
  • 지금은 보통 도서 번호 순서로 나와요. 하지만 순서를 정하지 않고 읽으면 어떤 순서로 나올지는 약속되어 있지 않아요. 순서를 정하는 방법은 9-3에서 배워요.
회사 Table은 다 읽지 않아요

우리 Table은 다섯 줄이라 조건 없이 다 읽어도 괜찮아요. 회사 Table은 수백만 줄이에요. 그런 Table을 WHERE 없이 읽으면 아주 오래 걸리거나 메모리가 모자라서 멈춰요. 회사에서는 WHERE 없이 읽지 않아요. WHERE는 바로 다음 절에서 배워요.

실행했는데 아무것도 안 나와요

결과 화면 없이 편집기로 돌아왔다면 SELECT가 한 줄도 읽지 못한 거예요. 코드보다 데이터를 먼저 봐요. SE16N에서 YTA_G##_BOOK에 줄이 없으면 7-7로 돌아가 다섯 권을 넣어요. 다른 클라이언트로 로그인했을 때도 안 보여요(1장 1-2).

활성화부터 막힐 때도 있어요. YTA_G##_BOOK을 모른다는 오류가 나면 코드의 Table 이름 철자를 먼저 봐요. 철자가 맞으면 SE11에서 그 Table이 Active인지 확인해요(7-6).

9-3. 원하는 줄만, 원하는 칸만

원하는 줄만: WHERE

이번에는 다섯 권 가운데 장르가 같은 책만 읽어요. 장르는 화면에서 입력받아요.

새로 만들기ProgramSE38
Program
YG##_130
Title
[예제] 장르로 도서 조회
REPORT yg##_130.

DATA: gt_book TYPE TABLE OF yta_g##_book,
      gs_book TYPE yta_g##_book.

PARAMETERS pa_genre TYPE yde_g##_genre.      " Data Element로 만든 입력 칸

START-OF-SELECTION.
  SELECT * FROM yta_g##_book
    INTO TABLE gt_book
    WHERE genre = pa_genre
    ORDER BY price DESCENDING.             " 비싼 순서로 정렬해서 가져오기

  LOOP AT gt_book INTO gs_book.
    WRITE: / gs_book-book_id, gs_book-title(20),
             gs_book-genre, gs_book-price.
  ENDLOOP.

활성화하고 실행해요. 입력 칸 PA_GENRE에 N(소설)을 넣고 F8을 누르면 소설 두 권이 비싼 순서로 나와요.

B0005 별을 세는 밤  N  17,000
B0002 바다의 노래   N  15,000
  • SELECT부터 ORDER BY까지 네 줄이 한 문장이에요. 마침표는 맨 끝에 하나만 찍어요(2-5). 이 장의 예제는 늘 SELECT → FROM → INTO → WHERE → ORDER BY 순서로 써요.
  • WHERE에는 4장의 비교 연산자, AND·OR를 그대로 써요. 8-4의 LOOP AT … WHERE처럼 왼쪽에는 칸 이름만 써요.
  • ORDER BY 칸 DESCENDING을 붙이면 정렬된 상태로 가져와요. DESCENDING을 빼면 작은 값부터 나와요. 한번 지우고 실행해 보세요. 두 줄의 순서가 뒤바뀌어요(확인한 뒤에는 다시 적어 둬요).
  • 장르를 비워 두고 실행하면 한 줄도 안 나와요. 고장이 아니에요. 빈칸은 "조건 없음"이 아니라 "genre가 빈칸인 줄을 찾아 줘"라는 뜻이거든요. 비우면 전부 나오게 하는 방법은 9-5에서 배워요.
직접 해 보기 · 이름표 붙이기

입력 칸 옆에 PA_GENRE라고 보였죠? 5-2에서는 이름표 글자를 직접 적었어요. 이번에는 7-5에서 Data Element에 적어 둔 글자를 가져와요.

  1. F3으로 편집기까지 돌아와서 메뉴 Goto → Text Elements로 들어가 Selection Texts 탭을 눌러요(5-2).
  2. PA_GENRE 줄의 Dictionary Ref. 칸에 체크하고 Enter를 눌러요. Text 칸에 장르가 저절로 들어와요. Data Element의 Field Label이에요.
  3. 저장하고 활성화(Ctrl+F3)한 뒤 F3으로 돌아와서 F8로 실행해요. 입력 칸 옆 글자가 PA_GENRE에서 장르로 바뀌어 있어요.
  4. 장르 칸에서 F4를 눌러 봐요. 7-4에서 Domain에 넣은 고정값 세 개가 목록으로 나와요. 입력 칸을 Data Element(yde_g##_genre)로 만들어서 저절로 붙은 거예요.

Text Elements 화면은 버전에 따라 조금 달라요. 체크했는데 글자가 바로 안 보이면 저장하고 활성화한 뒤 다시 봐요. 그래도 안 들어오면 체크를 풀고 Text 칸에 장르를 직접 적어도 돼요(5-2). 화면에 보이는 이름표는 같아요.

글자 일부로 찾기: LIKE

제목에 ABAP이 들어간 책을 찾고 싶으면 LIKE와 %를 써요. %는 "아무 글자나 몇 글자든"이라는 뜻이에요.

WHERE title LIKE '%ABAP%'

DB는 대소문자를 구분해요. abap으로 찾으면 ABAP 첫걸음은 나오지 않아요. 저장된 글자와 대소문자까지 똑같이 적어야 해요. 대문자로만 저장하는 칸이라면, 입력받은 글자를 3-6의 TRANSLATE … TO UPPER CASE로 대문자로 바꾼 뒤에 찾아요.

원하는 칸만: Field 목록

SELECT *는 모든 칸을 가져와요. 칸이 많은 Table에서 필요한 건 두세 칸뿐이라면 낭비예요. * 자리에 가져올 칸 이름을 적으면 그 칸만 읽어 와요. 이렇게 적은 칸 이름들을 Field 목록이라고 해요. 필요한 칸만 적는 습관을 들여요.

TYPES: BEGIN OF ty_list,

         title   TYPE yde_g##_title,
         price   TYPE yde_g##_price,
       END OF ty_list.

      gs_list TYPE ty_list.               " 출력할 때 쓸 Work Area

START-OF-SELECTION.
  SELECT book_id title price
    FROM yta_g##_book
    INTO CORRESPONDING FIELDS OF TABLE gt_list
    WHERE genre = 'I'.

  LOOP AT gt_list INTO gs_list.
    WRITE: / gs_list-book_id, gs_list-title(20), gs_list-price.
  ENDLOOP.

IT 책 두 권의 번호, 제목, 가격만 나와요.

B0001 ABAP 첫걸음   25,000
B0004 SQL 한 그릇   28,000
  • 세 칸만 담을 표가 필요해서 ty_list를 새로 만들었어요. TYPE 뒤에 7장의 Data Element를 쓰면 Table의 그 칸과 똑같은 Type이 돼요. 8-1의 note에서 미리 본 방법이에요.
  • Field 목록의 칸 이름 사이에는 쉼표를 쓰지 않아요. 빈칸으로만 띄워요.
  • INTO CORRESPONDING FIELDS OF TABLE은 이름이 같은 칸끼리 짝을 지어 담아 줘요. 8-1의 MOVE-CORRESPONDING과 같은 생각이에요. Internal Table의 칸 순서가 Field 목록과 달라도 괜찮아요.
  • 칸의 순서와 Type이 받는 쪽과 똑같으면 INTO TABLE gt_list만 써도 돼요. 이 예제가 그런 경우예요. 그때는 Field 목록에 적은 순서대로 왼쪽 칸부터 채워져요. 회사 코드에서는 이 모양을 더 자주 봐요.
  • 'I'를 소문자 'i'로 적으면 한 줄도 안 나와요. 따옴표 안의 값은 DB에 저장된 값과 대소문자까지 같아야 해요. YG##_130의 입력 칸은 n을 넣어도 대문자로 바꿔서 받지만(5-3), 코드에 적은 값은 아무도 바꿔 주지 않아요.

이 뒤의 짧은 예제들은 코드를 줄이려고 다시 SELECT *를 써요. 미니 실습에서는 필요한 칸만 읽어 봐요.

9-4. 한 줄만 읽기와 결과 확인

SELECT SINGLE

Key로 딱 한 줄만 읽을 땐 SELECT SINGLE을 써요. 담는 곳도 Internal Table이 아니라 Work Area예요.

새로 만들기ProgramSE38
Program
YG##_132
Title
[예제] 도서 한 권 조회
REPORT yg##_132.

DATA gs_book TYPE yta_g##_book.

PARAMETERS pa_id TYPE yde_g##_book_id.

START-OF-SELECTION.
  SELECT SINGLE * FROM yta_g##_book
    INTO gs_book
    WHERE book_id = pa_id.

  IF sy-subrc = 0.
    WRITE: / gs_book-title, '재고:', gs_book-stock.
  ELSE.
    MESSAGE '없는 도서 번호예요' TYPE 'S' DISPLAY LIKE 'E'.
  ENDIF.

B0003을 넣고 실행하면 이렇게 나와요.

오늘의 산책   재고:  5

없는 번호 B0009를 넣으면 결과 화면이 뜨지 않아요. Selection Screen 맨 아래 상태 표시줄에 없는 도서 번호예요가 나와요.

  • 읽었는지는 바로 다음 줄에서 sy-subrc로 확인해요. 0이면 찾은 것, 4면 그런 책이 없는 거예요(8-5).
  • TYPE 'S' DISPLAY LIKE 'E'는 5-5에서 배운 모양이에요. 종류는 S(계속 진행)인데 모양만 오류처럼 보여 줘요.
  • 짧은 예제라서 메시지 글자를 따옴표 안에 바로 적었어요. 미니 실습에서는 Text Symbol로 빼 볼 거예요.
  • 입력 칸 옆에는 PA_ID라고 보여요. 9-3처럼 Dictionary Ref.에 체크하면 도서 번호로 바뀌어요.

한 칸만 필요하면 Work Area 대신 변수 하나에 바로 담을 수 있어요. 아래는 눈으로만 보는 조각이에요.

DATA gv_title TYPE yde_g##_title.

SELECT SINGLE title FROM yta_g##_book
  INTO gv_title
  WHERE book_id = pa_id.

* 자리에 칸 이름 하나를, INTO 뒤에 변수 하나를 썼어요. 회사 코드에서 이름이나 설명 한 칸을 읽어 올 때 가장 흔한 모양이에요.

sy-subrc와 sy-dbcnt

시스템 필드 뜻 예
sy-subrc 0이면 한 줄 이상 읽음, 4면 하나도 없음 SELECT SINGLE 후 4면 없는 번호
sy-dbcnt 읽은(또는 바꾼) 줄 수 SELECT 후 3이면 세 줄

아래 두 줄도 눈으로만 봐요.

SELECT * FROM yta_g##_book INTO TABLE gt_book WHERE genre = 'N'.
WRITE: / '소설', sy-dbcnt, '권'.

소설은 두 권이라 소설 2 권이 나와요(숫자 앞 빈칸은 줄여 적었어요).

직접 해 보기 · 디버거로 확인하기

YG##_129를 열고, SELECT 바로 다음 줄인 LOOP AT 줄에 Breakpoint를 걸어 실행해요. 디버거가 멈추면 8-4에서 해 본 것처럼 gt_book을 더블클릭해서 표 모양으로 열어 봐요. 다섯 줄이 들어와 있어요. sy-dbcnt(5)와 sy-subrc(0)도 변수 목록에 올려 봐요. 다 봤으면 F8로 끝까지 실행하고 Breakpoint를 지워요.

결과가 이상할 때 "SELECT가 못 읽은 것인지, 출력이 틀린 것인지"를 가르는 가장 빠른 방법이에요.

자주 하는 실수
  • INTO TABLE의 TABLE을 빼먹으면 문법 오류가 나요. TABLE이 없는 SELECT … INTO는 한 줄씩 읽는 옛 반복문(SELECT … ENDSELECT)의 시작으로 읽히거든요. 오류 문구에 ENDSELECT나 Work Area 이야기가 보이면 INTO 뒤에 TABLE이 있는지부터 봐요. 여러 줄은 INTO TABLE, 한 줄은 SELECT SINGLE … INTO Work Area로 기억해요.
  • SELECT SINGLE 다음에 sy-subrc를 확인하지 않고 gs_book을 쓰면, 책을 못 찾았을 때 그 전에 담겨 있던 값이 그대로 출력돼요. INTO TABLE은 못 읽으면 표가 비어서 LOOP가 한 바퀴도 돌지 않아요.
  • LOOP 안에서 한 줄씩 SELECT SINGLE을 반복하면 DB를 너무 자주 불러서 느려져요. 가능하면 한 번에 INTO TABLE로 읽어 와요.

9-5. 범위로 입력받기: SELECT-OPTIONS

"가격이 15,000원부터 25,000원까지"처럼 범위로 조건을 받고 싶을 때는 SELECT-OPTIONS를 써요. 5장 PARAMETERS의 형님 같은 존재예요. PARAMETERS가 값 하나를 받는다면 SELECT-OPTIONS는 "~부터 ~까지"를 받아요.

새로 만들기ProgramSE38
Program
YG##_133
Title
[예제] 가격 범위로 도서 조회
REPORT yg##_133.

DATA: gt_book TYPE TABLE OF yta_g##_book,
      gs_book TYPE yta_g##_book.

SELECT-OPTIONS so_price FOR gs_book-price.       " 가격 범위 입력

START-OF-SELECTION.
  SELECT * FROM yta_g##_book
    INTO TABLE gt_book
    WHERE price IN so_price.                     " 범위 조건은 IN

  LOOP AT gt_book INTO gs_book.
    WRITE: / gs_book-book_id, gs_book-title(20), gs_book-price.
  ENDLOOP.

코드를 활성화한 다음 Selection Text를 넣어요. 이번에도 글자를 직접 적지 않고, 9-3에서 한 것처럼 Dictionary Ref.에 체크해요.

Name Text
SO_PRICE Dictionary Ref.에 체크 (가격이 들어와요)

그림처럼 15000과 25000을 넣고 실행하면 세 권이 나와요. 양 끝 값(15,000원과 25,000원)도 포함이에요.

B0001 ABAP 첫걸음   25,000
B0002 바다의 노래   15,000
B0005 별을 세는 밤  17,000
  • SELECT-OPTIONS 이름 FOR 변수. 형태예요. FOR 뒤에는 Type을 빌려 올 변수를 써요. 그래서 gs_book을 먼저 만들었어요. 이름은 PARAMETERS처럼 8글자까지예요. 앞머리 so_는 Select-Options예요.
  • 입력하면 위 오른쪽처럼 SIGN · OPTION · LOW · HIGH 네 칸짜리 줄이 담긴 Internal Table이 돼요(8-6에서 본 Header Line 모양).
  • WHERE 칸 IN so_price라고만 쓰면 SAP가 이 표를 보고 알아서 조건을 만들어 줘요.
  • 아무것도 입력하지 않으면 조건이 없는 것으로 보고 모든 줄을 가져와요. PARAMETERS와 가장 크게 다른 점이에요.
  • 왼쪽 칸에만 값을 넣으면 "그 값 이상"이 아니라 "그 값과 같은 것만"이에요. 15000만 넣으면 B0002 한 권만 나와요.
  • 1 화살표 버튼(Multiple Selection)을 누르면 "20000 이상", "이 값은 빼고" 같은 조건을 여러 개 넣을 수 있어요.

PARAMETERS처럼(5-3) 뒤에 말을 덧붙여 입력 칸을 꾸밀 수 있어요.

덧붙이는 말 하는 일
OBLIGATORY 꼭 입력해야 하는 칸으로 만들어요
NO INTERVALS 오른쪽 칸(to)을 없애요
NO-EXTENSION 화살표 버튼(Multiple Selection)을 없애요
DEFAULT 10000 TO 30000 처음부터 범위가 들어가 있어요

SELECT-OPTIONS so_price FOR gs_book-price DEFAULT 10000 TO 30000.처럼 써요. NO INTERVALS는 띄어 쓰고 NO-EXTENSION은 하이픈으로 이어요. 헷갈리기 쉬우니 표를 보고 그대로 적어요.

OPTION 칸에는 BT(사이) 말고도 EQ(같다), GE(이상), LE(이하), CP(*를 넣은 모양으로 찾기) 같은 값이 들어가요. 다음 과정에서 화면의 필터 조건이 바로 이 모양(SIGN · OPTION · LOW · HIGH)으로 넘어와요. 네 칸의 이름을 눈에 익혀 둬요.

자주 하는 실수

SELECT-OPTIONS에 WHERE price = so_price처럼 =를 쓰면 안 돼요. 범위 조건은 꼭 IN이에요.

이렇게도 써요

요즘 코드에서는 칸을 쉼표로 나누고, ABAP 변수 앞에 @를 붙이는 새 문법을 많이 써요. INTO는 맨 뒤에 써요.

SELECT book_id, title, price
  FROM yta_g##_book
  WHERE price IN @so_price
  ORDER BY price DESCENDING
  INTO TABLE @DATA(lt_new).

@는 "여기부터는 ABAP 변수예요"라는 표시예요. @DATA(lt_new)는 결과를 담을 Internal Table을 그 자리에서 만들어요(그 자리에서 만든 것이라 8-7에서처럼 이름이 l로 시작해요). 한 문장 안에서 옛 문법과 새 문법을 섞으면 오류가 나요. 하나라도 @를 쓰면 Field 목록은 쉼표로, 변수는 모두 @로 써야 해요.

9-6. Table 두 개를 이어 읽기: INNER JOIN

7-8 미니 실습에서 대여 기록 Table YTA_G##_RENT를 만들었죠. 여기에는 누가 몇 번 책을 빌렸는지만 있고 책 제목은 없어요. 제목은 YTA_G##_BOOK에 있거든요. "누가 어떤 제목의 책을 빌렸는지" 보려면 두 Table을 BOOK_ID로 이어서 읽어야 해요. 이렇게 잇는 것을 JOIN이라고 해요.

7-8 미니 실습을 건너뛰었다면 먼저 돌아가서 Table과 데이터 네 줄을 만들고 와요. 만들어 뒀다면 SE16N에서 YTA_G##_RENT를 조회해서 아래 그림의 왼쪽 표와 같은 네 줄인지 확인해요.

그림의 제목 줄에 적은 r, b는 프로그램에서 두 Table을 부를 짧은 별명이에요.

REPORT yg##_134.

TYPES: BEGIN OF ty_rent,
         rent_id     TYPE yde_g##_rent_id,
         book_id     TYPE yde_g##_book_id,

DATA: gt_rent TYPE TABLE OF ty_rent,
      gs_rent TYPE ty_rent.

START-OF-SELECTION.
  SELECT r~rent_id r~book_id b~title r~member_name r~rent_date
    FROM yta_g##_rent AS r
    INNER JOIN yta_g##_book AS b
      ON b~book_id = r~book_id
    INTO CORRESPONDING FIELDS OF TABLE gt_rent.

  SORT gt_rent BY rent_id.

  LOOP AT gt_rent INTO gs_rent.
    WRITE: / gs_rent-rent_id, gs_rent-book_id, gs_rent-title(20),
             gs_rent-member_name(10), gs_rent-rent_date.
  ENDLOOP.

대여 기록 네 줄에 책 제목이 붙어서 나와요. 날짜 모양은 사용자 설정에 따라 조금 달라요.

R0001 B0001 ABAP 첫걸음   홍길동  2026.11.03
R0002 B0004 SQL 한 그릇   김하나  2026.11.05
R0003 B0001 ABAP 첫걸음   이두리  2026.11.10
R0004 B0005 별을 세는 밤  홍길동  2026.11.12
  • FROM yta_g##_rent AS r: AS 뒤는 Table에 붙이는 별명이에요. 긴 이름 대신 r, b로 짧게 불러요.
  • r~rent_id, b~title: SQL 안에서 "이 Table의 이 칸"은 물결표(~)로 가리켜요. gs_rent-title의 하이픈(-)은 ABAP 변수의 칸, b~title의 물결표는 DB Table의 칸이에요. book_id처럼 두 Table에 다 있는 칸은 어느 쪽 것인지 꼭 적어야 해요.
  • ON b~book_id = r~book_id: ON 뒤가 짝을 맞추는 조건이에요. 대여 기록의 책 번호와 번호가 같은 책을 찾아서 한 줄로 붙여요.
  • ty_rent의 칸 이름은 Table의 Field 이름과 똑같이 지었어요. 그래야 INTO CORRESPONDING FIELDS OF TABLE이 이름으로 짝을 맞춰 채워 줘요.
  • 활성화할 때 MEMBER_NAME이나 YDE_G##_MEMBER 같은 이름을 모른다는 오류가 나면, SE11에서 내 Table의 Field 이름과 Data Element 이름이 7-8의 예시 답안과 같은지 봐요.
  • B0001은 두 번 빌려 가서 두 줄에 나와요. 대여 기록 한 줄마다 짝이 되는 책을 찾아 붙이기 때문이에요.
  • 결과의 순서는 약속되어 있지 않아서 SORT로 대여 번호 순서로 정렬했어요(8-6). 9-3처럼 SELECT 문장 끝에 ORDER BY r~rent_id를 써도 돼요.

INNER는 "양쪽에 다 있는 줄만"이라는 뜻이에요. 그래서 한 번도 빌리지 않은 B0002, B0003은 결과에 없어요. 책을 기준으로, 안 빌린 책까지 모두 보고 싶을 때는 LEFT OUTER JOIN을 써요. 그때는 FROM 뒤에 도서 Table을 먼저 적어요. 먼저 적은(왼쪽) Table의 줄은 짝이 없어도 모두 나오거든요. 지금은 이름만 알아 둬요.

회사 옛 코드에서는 이렇게도 읽어요: FOR ALL ENTRIES

오래된 프로그램은 JOIN 대신 두 번에 나눠 읽는 모양이 많아요. 먼저 대여 기록을 gt_rent에 읽어 두고, 거기 나온 책 번호로 도서를 한 번 더 읽어요.

IF gt_rent IS NOT INITIAL.                 " 이 IF가 없으면 큰일 나요
  SELECT * FROM yta_g##_book
    INTO TABLE gt_book
    FOR ALL ENTRIES IN gt_rent
    WHERE book_id = gt_rent-book_id.
ENDIF.

FOR ALL ENTRIES IN gt_rent는 "gt_rent의 줄마다"라는 뜻이에요. WHERE의 gt_rent-book_id는 "그 줄의 book_id"예요. 8-6에서 본 Header Line과 생김새가 같지만, FOR ALL ENTRIES에서만 쓰는 약속된 모양이에요.

조심할 것은 하나예요. 기준이 되는 표(gt_rent)가 비어 있으면 WHERE가 통째로 무시되어 Table의 모든 줄을 읽어 와요. 그래서 앞에 꼭 IF … IS NOT INITIAL.을 둬요. 지금은 읽을 줄만 알면 돼요.

다음 과정에서 배울 CDS View는 이런 JOIN을 이름 붙여 저장해 두고, 여러 프로그램이 같이 쓰게 하는 것이에요.

9-7. DB Table 바꾸기: INSERT · UPDATE · MODIFY · DELETE

지금까지는 읽기만 했어요. 이제 DB Table에 줄을 넣고, 고치고, 지워 볼게요. 여기서 바꾼 것은 프로그램이 끝나도 DB에 그대로 남아요. 그래서 이 절 끝에서 처음 상태로 되돌리는 프로그램도 같이 만들어요.

DB Table을 바꾸는 문장은 네 가지예요. gs_book은 Table과 모양이 같은 Work Area예요.

INSERT yta_g##_book FROM gs_book.
UPDATE yta_g##_book FROM gs_book.
MODIFY yta_g##_book FROM gs_book.
DELETE FROM yta_g##_book WHERE stock = 0.
문장 하는 일 그런 줄이 이미 있으면 없으면
INSERT 새 줄 넣기 실패 (sy-subrc = 4) 넣기
UPDATE 줄 전체 고치기 고치기 실패 (sy-subrc = 4)
MODIFY 있으면 고치고 없으면 넣기 고치기 넣기
DELETE 조건에 맞는 줄 모두 지우기 지우기 실패 (sy-subrc = 4)
  • 위의 세 문장(INSERT·UPDATE·MODIFY)은 Work Area와 Key가 같은 줄(여기서는 book_id가 같은 줄)이 있는지를 봐요. DELETE는 WHERE 조건에 맞는 줄이 있는지를 봐요.
  • UPDATE … FROM과 MODIFY … FROM은 Key를 뺀 모든 칸을 Work Area의 값으로 덮어써요. 한두 칸만 바꿀 때는 조금 뒤에 나오는 UPDATE … SET이 안전해요.
8장의 MODIFY·DELETE와 뭐가 달라요?

이름은 같지만 대상이 달라요. gt_book처럼 Internal Table 이름을 쓰면 메모리 속 표를, yta_g##_book처럼 DB Table 이름을 쓰면 데이터베이스를 바꿔요. DELETE gt_book WHERE …는 읽어 온 복사본만 지워요. SE16N으로 보면 DB에는 그대로 있어요.

바꾼 내용은 언제 저장돼요? COMMIT WORK

INSERT·UPDATE·MODIFY·DELETE로 바꾼 내용은 프로그램이 정상적으로 끝나면 SAP가 저장(Commit)해 줘요. 정확히는 끝날 때만이 아니라 화면이 한 번 바뀔 때마다 저장돼요. 반대로 저장되기 전에 프로그램이 덤프로 멈추면(6-8) 그때까지 바꾼 내용이 취소(Rollback)돼요. 이 시점을 직접 정하고 싶으면 COMMIT WORK.를 써요. 회사 프로그램에서는 언제 저장할지를 신중하게 설계해요.

자주 하는 실수
  • DELETE와 UPDATE … SET의 WHERE는 두 번 확인해요. 조건이 틀리거나 WHERE를 빼먹으면 원하지 않은 줄까지 한꺼번에 바뀌거나 지워져요. 먼저 같은 WHERE로 SELECT를 해서 몇 줄이 걸리는지(sy-dbcnt) 확인해 보는 것도 좋은 습관이에요.
  • 연습은 꼭 내 Table(YTA_G##_…)에서만 해요. SAP 표준 Table을 직접 바꾸면 안 돼요. 표준 데이터를 바꿔야 할 때는 SAP가 만들어 둔 Function Module(BAPI라고 불러요)을 불러요. Function Module은 10장에서 배워요.

  INSERT yta_g##_book FROM TABLE gt_book.   " 표의 모든 줄을 한 번에 넣어요

  WRITE: / '넣은 줄 수:', sy-dbcnt.
넣은 줄 수: 5
  • 줄 수를 줄이려고 한 줄에 문장을 두 개씩 적었어요. ABAP은 마침표로 문장을 나누니까 괜찮아요(2-5).
  • DELETE도 SELECT처럼 지금 로그인한 클라이언트의 줄만 다뤄요. WHERE가 없으니 그 안에서는 한 줄도 남기지 않아요.
  • INSERT … FROM TABLE gt_book.은 Internal Table의 모든 줄을 한꺼번에 넣어요. SELECT … INTO TABLE의 반대 방향이에요. 넣은 줄 수는 sy-dbcnt에 들어 있어요.
  • 먼저 다 지우고 넣으니까 몇 번을 실행해도 결과가 같아요. 실행한 뒤 SE16N에서 다섯 줄(재고 3, 0, 5, 2, 7)인지 확인해요.
  • 대여 기록 Table YTA_G##_RENT는 이 장의 예제가 바꾸지 않아서 되돌릴 필요가 없어요.
조심해요
  • WHERE 없는 DELETE는 위험해요. 내 연습 Table이라서 쓴 거예요. 회사 Table에서 WHERE를 빼먹으면 모든 데이터가 사라져요.
  • DELETE 줄을 빼고 INSERT … FROM TABLE만 실행하면, 이미 있는 줄과 Key가 겹쳐서 덤프(SAPSQL_ARRAY_INSERT_DUPREC)로 멈춰요. 한 줄씩 넣는 INSERT는 sy-subrc가 4가 될 뿐이지만, 표를 통째로 넣을 때는 프로그램이 멈춰요. 덤프 읽는 법은 6-8에서 배웠어요.
  • 다섯 권을 손으로 치다가 book_id를 고치지 않아 같은 번호가 두 번 들어가도 같은 덤프가 나요. 그때는 앞의 DELETE도 함께 취소돼서 Table은 실행하기 전 그대로예요. 번호를 고치고 다시 실행하면 돼요.

9-8. 미니 실습: 장르와 가격으로 도서 조회

이번에는 혼자 써 봐요. 이 실습의 그림은 7-7의 다섯 권 기준이에요. 결과가 그림과 다르면 9-7의 YG##_137을 먼저 실행해요.

새로 만들기ProgramSE38
Program
YG##_138

[실습] 장르와 가격으로 도서 조회
직접 해 보기
  1. 입력: 장르(SELECT-OPTIONS so_genre), 가격(SELECT-OPTIONS so_price). (힌트: FOR 뒤에 쓸 변수로 gs_book TYPE yta_g##_book을 하나 만들어요.)
  2. 조건에 맞는 책을 필요한 칸만(번호, 제목, 저자, 가격, 재고) 가격이 비싼 순서로 읽어 와요. (힌트: YG##_131의 ty_list에 author TYPE yde_g##_author와 stock TYPE yde_g##_stock을 더해요. 조건 두 개는 AND로 이어요.)
  3. 한 권도 없으면 TEXT-e01 메시지를 S + DISPLAY LIKE 'E'로 보여 주고 RETURN.으로 끝내요(5-5).
  4. 있으면 그림 9-5처럼 한 줄씩 출력하고, 맨 아래에 '조회된 책:'과 sy-dbcnt(권수)를 출력해요.
  5. Selection Text와 Text Symbol을 아래 표대로 넣고 활성화해요.
  6. 세 가지로 실행해서 결과를 견줘 보세요.
    • 장르 I, 가격은 비움: 그림 9-5처럼 2권
    • 장르 I, 가격 15000~25000: B0001 1권
    • 장르 E, 가격 20000~30000: 결과 화면 없이 조건에 맞는 책이 없어요

예시 답안 보기
*&---------------------------------------------------------------------*
* 설명: SELECT-OPTIONS + SELECT(Field 목록, WHERE IN, ORDER BY) 연습
* Text Symbol E01: 조건에 맞는 책이 없어요
* Selection Text SO_GENRE, SO_PRICE: Dictionary Ref. 체크
*&---------------------------------------------------------------------*
REPORT yg##_138.

TYPES: BEGIN OF ty_list,
         book_id TYPE yde_g##_book_id,
         title   TYPE yde_g##_title,
         author  TYPE yde_g##_author,
         price   TYPE yde_g##_price,
         stock   TYPE yde_g##_stock,
       END OF ty_list.

DATA: gs_book TYPE yta_g##_book,       " SELECT-OPTIONS의 FOR용
      gt_list TYPE TABLE OF ty_list,
      gs_list TYPE ty_list,
      gv_cnt  TYPE i.

SELECT-OPTIONS: so_genre FOR gs_book-genre,
                so_price FOR gs_book-price.

START-OF-SELECTION.
  " 1. 조건에 맞는 책 읽기
  SELECT book_id title author price stock
    FROM yta_g##_book
    INTO CORRESPONDING FIELDS OF TABLE gt_list
    WHERE genre IN so_genre
      AND price IN so_price
    ORDER BY price DESCENDING.

  " 2. 없으면 메시지 후 끝내기
  IF sy-subrc <> 0.
    MESSAGE TEXT-e01 TYPE 'S' DISPLAY LIKE 'E'.
    RETURN.                              " START-OF-SELECTION을 여기서 끝내요
  ENDIF.
  gv_cnt = sy-dbcnt.                     " 다음 SQL 문장이 바꾸기 전에 옮겨 두기

  " 3. 출력
  LOOP AT gt_list INTO gs_list.
    WRITE: / gs_list-book_id, gs_list-title(20), gs_list-author(15),
             gs_list-price, gs_list-stock.
  ENDLOOP.

  WRITE: / '조회된 책:', gv_cnt.

gv_cnt에 옮겨 담지 않고 맨 아래 줄을 WRITE: / '조회된 책:', sy-dbcnt.로 써도 여기서는 결과가 같아요. sy-dbcnt는 다음 SQL 문장이 실행되면 바뀌니까, 미리 옮겨 두는 습관을 들이려고 이렇게 썼어요.

확인 문제
  1. SELECT * FROM yta_g##_book INTO TABLE gt_book.에서 MANDT 조건을 따로 쓰지 않아도 되는 이유는 무엇일까요?
  2. SELECT-OPTIONS를 비워 두고 실행하면 어떤 결과가 나올까요? PARAMETERS를 비워 두고 WHERE genre = pa_genre로 조회하면요?
  3. INSERT했더니 sy-subrc가 4였어요. 무슨 뜻일까요?
  4. 아래 코드는 무엇이 문제일까요? 
    SELECT * FROM yta_g##_book INTO gt_book WHERE genre = 'N'.
  5. UPDATE … SET이나 DELETE를 실행하기 전에 꼭 확인해야 하는 것은 무엇일까요?
  6. SELECT SINGLE 다음 줄에서 sy-subrc를 확인하지 않고 gs_book-title을 출력했어요. 없는 도서 번호를 넣으면 무엇이 출력될까요?
  7. 대여 기록과 도서를 INNER JOIN으로 이어 읽었더니 B0002, B0003이 결과에 없어요. 왜 그럴까요? 그리고 b~title의 ~는 무슨 뜻일까요?
정답 보기
  1. SAP가 로그인한 클라이언트의 데이터만 자동으로 골라 주기 때문이에요(클라이언트 자동 처리).
  2. SELECT-OPTIONS는 비우면 조건이 없는 것이라 모든 줄이 나와요. PARAMETERS를 비우면 genre가 빈칸인 줄만 찾으니 보통 한 줄도 안 나와요.
  3. 같은 Key가 이미 있어서 넣지 못했다는 뜻이에요.
  4. 여러 줄을 담는데 INTO TABLE이 아니라 INTO라서 문법 오류가 나요. TABLE이 없으면 한 줄씩 읽는 옛 반복문(SELECT … ENDSELECT)으로 읽히는데, gt_book은 한 줄을 담는 Work Area가 아니에요. INTO TABLE gt_book으로 고쳐요.
  5. WHERE 조건이에요. 조건이 틀리거나 빠지면 원하지 않는 줄까지 바뀌거나 지워져요.
  6. 못 찾으면 gs_book은 바뀌지 않아요. 그래서 그 전에 들어 있던 값(처음이라면 빈칸)이 그대로 출력돼요. IF sy-subrc = 0.으로 확인한 뒤에 써야 해요.
  7. INNER JOIN은 양쪽 Table에 다 있는 줄만 가져와요. 두 책은 대여 기록에 한 번도 없어서 짝이 없어요. b~title은 "별명이 b인 Table의 title 칸"이라는 뜻이에요.
정리
  • 여러 줄은 SELECT … FROM … INTO TABLE …, 한 줄은 SELECT SINGLE … INTO Work Area로 읽어요.
  • WHERE로 줄을, Field 목록과 INTO CORRESPONDING FIELDS OF TABLE로 칸을 골라요. ORDER BY로 정렬해서 가져올 수 있어요.
  • 결과는 sy-subrc(0 성공, 4 없음)와 sy-dbcnt(줄 수)로 확인해요.
  • 범위 조건은 SELECT-OPTIONS … FOR …로 받고 WHERE 칸 IN 이름으로 써요. 비우면 전체예요.
  • Table 두 개는 INNER JOIN … ON …으로 이어 읽어요. SQL 안에서 Table의 칸은 별명~칸으로 가리키고, 양쪽에 다 있는 줄만 나와요.
  • INSERT·UPDATE·MODIFY·DELETE로 DB를 바꾸고, WHERE는 두 번 확인해요.
  • 실습 데이터가 교재와 달라졌으면 YG##_137로 처음 다섯 권으로 되돌려요.
