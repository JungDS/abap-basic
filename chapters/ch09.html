9장

Open SQL

이번 장 목표
  • DB Table의 데이터를 SELECT로 읽어 Internal Table에 담을 수 있어요.
  • WHERE로 원하는 줄만, 필드 목록으로 원하는 칸만 가져올 수 있어요.
  • SELECT SINGLE로 한 줄만 읽고, sy-subrc·sy-dbcnt로 결과를 확인할 수 있어요.
  • SELECT-OPTIONS로 범위 조건을 입력받아 IN으로 걸러 낼 수 있어요.
  • INSERT·UPDATE·MODIFY·DELETE로 DB Table을 바꿀 수 있어요.

9-1. DB에서 메모리로

ABAP 프로그램이 DB Table을 읽고 쓰는 SQL을 Open SQL(요즘 이름은 ABAP SQL)이라고 해요. 7장에서 만든 YG##_BOOK을 읽어서, 8장에서 배운 Internal Table에 담는 것이 이번 장의 첫 목표예요.

9-2. 전부 읽어 오기: SELECT … INTO TABLE

REPORT yg##_09_select.

DATA: gt_book TYPE TABLE OF yg##_book,     " DB Table과 같은 모양의 Internal Table
      gs_book TYPE yg##_book.              " 같은 모양의 Work Area

START-OF-SELECTION.
  SELECT * FROM yg##_book INTO TABLE gt_book.

  LOOP AT gt_book INTO gs_book.
    WRITE: / gs_book-book_id, gs_book-title(20), gs_book-price, gs_book-stock.
  ENDLOOP.
  • INTO TABLE은 읽은 줄을 모두 Internal Table에 담아요. 원래 들어 있던 줄은 지워지고 새로 채워져요.
  • MANDT는 신경 쓰지 않아도 돼요. SAP가 지금 로그인한 클라이언트의 데이터만 알아서 골라 줘요(1장 1-2).
  • gs_book-title(20)처럼 칸 이름 뒤에 (20)을 붙이면 앞 20칸만 출력해요. 제목이 40칸이라 줄이 너무 길어지지 않게 했어요.

9-3. 원하는 줄만, 원하는 칸만

원하는 줄만: WHERE

PARAMETERS pa_genre TYPE yg##_e_genre.      " Data Element로 만든 입력 칸

START-OF-SELECTION.
  SELECT * FROM yg##_book
    INTO TABLE gt_book
    WHERE genre = pa_genre
    ORDER BY price DESCENDING.             " 비싼 순서로 정렬해서 가져오기
  • WHERE에는 4장의 비교 연산자, AND·OR를 그대로 써요.
  • ORDER BY 칸 DESCENDING을 붙이면 정렬된 상태로 가져와요.
  • PARAMETERS를 Data Element(yg##_e_genre)로 만들면 고정값 목록(F4)이 저절로 붙어요. Selection Text에서 Dictionary Ref.를 체크하면 이름표도 Field Label(장르)로 붙어요.
글자 일부로 찾기: LIKE

제목에 ABAP이 들어간 책을 찾고 싶으면 LIKE와 %를 써요. %는 "아무 글자나 몇 글자든"이라는 뜻이에요.

WHERE title LIKE '%ABAP%'

DB는 대소문자를 구분해요. abap으로 찾으면 ABAP 첫걸음은 나오지 않아요.

원하는 칸만: 필드 목록

SELECT *는 모든 칸을 가져와요. 칸이 많은 Table에서 필요한 건 두세 칸뿐이라면 낭비예요. 필요한 칸만 적는 습관을 들여요.

TYPES: BEGIN OF ty_list,
         book_id TYPE yg##_e_book_id,
         title   TYPE yg##_e_title,
         price   TYPE yg##_e_price,
       END OF ty_list.

DATA gt_list TYPE TABLE OF ty_list.

START-OF-SELECTION.
  SELECT book_id title price
    FROM yg##_book
    INTO CORRESPONDING FIELDS OF TABLE gt_list
    WHERE genre = 'I'.

INTO CORRESPONDING FIELDS OF TABLE은 이름이 같은 칸끼리 짝을 지어 담아 줘요. Internal Table의 칸 순서가 SELECT 목록과 달라도 괜찮아요.

9-4. 한 줄만 읽기와 결과 확인

SELECT SINGLE

Key로 딱 한 줄만 읽을 땐 SELECT SINGLE을 써요. 담는 곳도 Internal Table이 아니라 Work Area예요.

PARAMETERS pa_id TYPE yg##_e_book_id.

START-OF-SELECTION.
  SELECT SINGLE * FROM yg##_book
    INTO gs_book
    WHERE book_id = pa_id.

  IF sy-subrc = 0.
    WRITE: / gs_book-title, '재고:', gs_book-stock.
  ELSE.
    MESSAGE TEXT-e01 TYPE 'S' DISPLAY LIKE 'E'.   " 없는 도서 번호예요
  ENDIF.

sy-subrc와 sy-dbcnt

시스템 필드 뜻 예
sy-subrc 0이면 한 줄 이상 읽음, 4면 하나도 없음 8장과 같아요
sy-dbcnt 읽은(또는 바꾼) 줄 수 SELECT 후 3이면 세 줄 
SELECT * FROM yg##_book INTO TABLE gt_book WHERE genre = 'N'.
WRITE: / '소설', sy-dbcnt, '권'.
자주 하는 실수
  • INTO TABLE의 TABLE을 빼먹으면 SELECT … ENDSELECT라는 반복문 모양으로 읽혀서 ENDSELECT가 없다는 오류가 나요. 여러 줄은 INTO TABLE, 한 줄은 SELECT SINGLE … INTO 워크에어리어로 기억해요.
  • SELECT 바로 다음에 sy-subrc를 확인하지 않고 결과를 쓰면, 데이터가 없을 때 엉뚱한 값이 출력돼요.
  • LOOP 안에서 한 줄씩 SELECT SINGLE을 반복하면 DB를 너무 자주 불러서 느려져요. 가능하면 한 번에 INTO TABLE로 읽어 와요.

9-5. 범위로 입력받기: SELECT-OPTIONS

"가격이 15,000원부터 25,000원까지"처럼 범위로 조건을 받고 싶을 때는 SELECT-OPTIONS를 써요. 5장 PARAMETERS의 형님 같은 존재예요.

REPORT yg##_09_range.

DATA: gt_book TYPE TABLE OF yg##_book,
      gs_book TYPE yg##_book.

SELECT-OPTIONS so_price FOR gs_book-price.       " 가격 범위 입력

START-OF-SELECTION.
  SELECT * FROM yg##_book
    INTO TABLE gt_book
    WHERE price IN so_price.                     " 범위 조건은 IN

  LOOP AT gt_book INTO gs_book.
    WRITE: / gs_book-book_id, gs_book-title(20), gs_book-price.
  ENDLOOP.
  • SELECT-OPTIONS 이름 FOR 변수. 형태예요. FOR 뒤에는 Type을 빌려 올 변수를 써요. 그래서 gs_book을 먼저 만들었어요. 이름은 PARAMETERS처럼 8글자까지예요.
  • 입력하면 위 오른쪽처럼 SIGN · OPTION · LOW · HIGH 네 칸짜리 줄이 담긴 Internal Table이 돼요(8장의 Header Line 모양).
  • WHERE 칸 IN so_price라고만 쓰면 SAP가 이 표를 보고 알아서 조건을 만들어 줘요.
  • 아무것도 입력하지 않으면 조건이 없는 것으로 보고 모든 줄을 가져와요. PARAMETERS와 가장 크게 다른 점이에요.
  • 1 화살표 버튼(Multiple Selection)을 누르면 "15000 하나만", "20000 이상", "이 값은 빼고" 같은 조건을 여러 개 넣을 수 있어요.
자주 하는 실수

SELECT-OPTIONS에 WHERE price = so_price처럼 =를 쓰면 안 돼요. 범위 조건은 꼭 IN이에요.

9-6. DB Table 바꾸기: INSERT · UPDATE · MODIFY · DELETE

문장 하는 일 Key가 이미 있으면 Key가 없으면
INSERT 테이블 FROM 워크에어리어. 새 줄 넣기 실패 (sy-subrc = 4) 넣기
UPDATE 테이블 FROM 워크에어리어. 줄 고치기 고치기 실패 (sy-subrc = 4)
MODIFY 테이블 FROM 워크에어리어. 있으면 고치고 없으면 넣기 고치기 넣기
DELETE FROM 테이블 WHERE 조건. 줄 지우기 지우기 실패 (sy-subrc = 4)

예: 새 책 넣기

CLEAR gs_book.
gs_book-book_id = 'B0006'.
gs_book-title   = '처음 만나는 SAP'.
gs_book-author  = '최입문'.
gs_book-genre   = 'I'.
gs_book-price   = 22000.
gs_book-stock   = 4.

INSERT yg##_book FROM gs_book.
IF sy-subrc = 0.
  MESSAGE '새 책을 등록했어요' TYPE 'S'.
ELSE.
  MESSAGE '이미 있는 도서 번호예요' TYPE 'S' DISPLAY LIKE 'E'.
ENDIF.

예: 대여 처리(재고 1 줄이기)

UPDATE … SET을 쓰면 Work Area 없이 특정 칸만 바꿀 수 있어요.

PARAMETERS pa_id TYPE yg##_e_book_id OBLIGATORY.

START-OF-SELECTION.
  UPDATE yg##_book
    SET stock = stock - 1
    WHERE book_id = pa_id
      AND stock > 0.                     " 재고가 있을 때만

  IF sy-subrc = 0.
    MESSAGE '대여 처리했어요' TYPE 'S'.
  ELSE.
    MESSAGE '재고가 없거나 없는 책이에요' TYPE 'S' DISPLAY LIKE 'E'.
  ENDIF.
바꾼 내용은 언제 저장돼요? COMMIT WORK

INSERT·UPDATE·DELETE로 바꾼 내용은 프로그램이 정상적으로 끝나면 SAP가 저장(Commit)해 줘요. 반대로 중간에 프로그램이 오류로 멈추면 바꾼 내용이 취소(Rollback)돼요. 이 시점을 직접 정하고 싶으면 COMMIT WORK.를 써요. 회사 프로그램에서는 언제 저장할지를 신중하게 설계해요.

자주 하는 실수
  • DELETE와 UPDATE … SET의 WHERE는 두 번 확인해요. 조건이 틀리면 원하지 않은 줄까지 한꺼번에 바뀌거나 지워져요. 먼저 같은 WHERE로 SELECT를 해서 몇 줄이 걸리는지(sy-dbcnt) 확인해 보는 것도 좋은 습관이에요.
  • 연습은 꼭 내 Table(YG##_...)에서만 해요. SAP 표준 Table을 직접 바꾸면 안 돼요.
이렇게도 써요

요즘 코드에서는 칸을 쉼표로 나누고, ABAP 변수 앞에 @를 붙이는 새 문법을 많이 써요. INTO는 맨 뒤로 가요.

SELECT book_id, title, price
  FROM yg##_book
  WHERE price IN @so_price
  ORDER BY price DESCENDING
  INTO TABLE @DATA(gt_list).

@는 "여기부터는 ABAP 변수예요"라는 표시예요. 한 문장 안에서 옛 문법과 새 문법을 섞으면 오류가 나요. 하나라도 @를 쓰면 칸 목록은 쉼표로, 변수는 모두 @로 써야 해요.

9-7. 미니 실습: 도서 조회 프로그램

직접 해 보기

프로그램 YG##_09_BOOK을 만들어 보세요.

  1. 입력: 장르(SELECT-OPTIONS so_genre), 가격(SELECT-OPTIONS so_price). Selection Text는 Dictionary Ref.를 체크해요.
  2. 조건에 맞는 책을 필요한 칸만(번호, 제목, 저자, 가격, 재고) 가격이 비싼 순서로 읽어 와요.
  3. 한 권도 없으면 TEXT-e01(조건에 맞는 책이 없어요) 메시지를 S + DISPLAY LIKE 'E'로 보여 주고 끝내요.
  4. 있으면 한 줄씩 출력하고, 맨 아래에 sy-dbcnt로 권수를 출력해요.
  5. 장르 I, 가격은 비워 두고 실행해 보세요. 그다음 가격 15000~25000도 넣어서 결과가 어떻게 바뀌는지 봐요.
예시 답안 보기
*&---------------------------------------------------------------------*
* 설명: SELECT-OPTIONS + SELECT(필드 목록, WHERE IN, ORDER BY) 연습
* Text Symbol E01: 조건에 맞는 책이 없어요
*&---------------------------------------------------------------------*
REPORT yg##_09_book.

TYPES: BEGIN OF ty_list,
         book_id TYPE yg##_e_book_id,
         title   TYPE yg##_e_title,
         author  TYPE yg##_e_author,
         price   TYPE yg##_e_price,
         stock   TYPE yg##_e_stock,
       END OF ty_list.

DATA: gs_book TYPE yg##_book,          " SELECT-OPTIONS의 FOR용
      gt_list TYPE TABLE OF ty_list,
      gs_list TYPE ty_list,
      gv_cnt  TYPE i.

SELECT-OPTIONS: so_genre FOR gs_book-genre,
                so_price FOR gs_book-price.

START-OF-SELECTION.
  " 1. 조건에 맞는 책 읽기
  SELECT book_id title author price stock
    FROM yg##_book
    INTO CORRESPONDING FIELDS OF TABLE gt_list
    WHERE genre IN so_genre
      AND price IN so_price
    ORDER BY price DESCENDING.

  " 2. 없으면 메시지 후 끝내기
  IF sy-subrc <> 0.
    MESSAGE TEXT-e01 TYPE 'S' DISPLAY LIKE 'E'.
    RETURN.
  ENDIF.
  gv_cnt = sy-dbcnt.                     " 다른 문장이 바꾸기 전에 옮겨 두기

  " 3. 출력
  LOOP AT gt_list INTO gs_list.
    WRITE: / gs_list-book_id, gs_list-title(20), gs_list-author(15),
             gs_list-price, gs_list-stock.
  ENDLOOP.

  WRITE: / '조회된 책:', gv_cnt.
확인 문제
  1. SELECT * FROM yg##_book INTO TABLE gt_book.에서 MANDT 조건을 따로 쓰지 않아도 되는 이유는 무엇일까요?
  2. SELECT-OPTIONS를 비워 두고 실행하면 어떤 결과가 나올까요? PARAMETERS를 비워 두고 WHERE genre = pa_genre로 조회하면요?
  3. INSERT했더니 sy-subrc가 4였어요. 무슨 뜻일까요?
  4. 아래 코드는 무엇이 문제일까요? 
    SELECT * FROM yg##_book INTO gt_book WHERE genre = 'N'.
  5. UPDATE … SET이나 DELETE를 실행하기 전에 꼭 확인해야 하는 것은 무엇일까요?
정답 보기
  1. SAP가 로그인한 클라이언트의 데이터만 자동으로 골라 주기 때문이에요(클라이언트 자동 처리).
  2. SELECT-OPTIONS는 비우면 조건이 없는 것이라 모든 줄이 나와요. PARAMETERS를 비우면 genre = ' '(공백)인 줄만 찾으니 보통 한 줄도 안 나와요.
  3. 같은 Key가 이미 있어서 넣지 못했다는 뜻이에요.
  4. 여러 줄을 담는데 INTO TABLE이 아니라 INTO라서 SELECT … ENDSELECT 반복문으로 읽혀요. ENDSELECT가 없다는 오류가 나요. INTO TABLE gt_book으로 고쳐요.
  5. WHERE 조건이에요. 조건이 틀리면 원하지 않는 줄까지 바뀌거나 지워져요.
정리
  • 여러 줄은 SELECT … FROM … INTO TABLE …, 한 줄은 SELECT SINGLE … INTO 워크에어리어로 읽어요.
  • WHERE로 줄을, 필드 목록과 INTO CORRESPONDING FIELDS OF TABLE로 칸을 골라요. ORDER BY로 정렬해서 가져올 수 있어요.
  • 결과는 sy-subrc(0 성공, 4 없음)와 sy-dbcnt(줄 수)로 확인해요.
  • 범위 조건은 SELECT-OPTIONS … FOR …로 받고 WHERE 칸 IN 이름으로 써요. 비우면 전체예요.
  • INSERT·UPDATE·MODIFY·DELETE로 DB를 바꾸고, WHERE는 두 번 확인해요.
