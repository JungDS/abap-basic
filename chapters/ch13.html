B. 자주 쓰는 sy- 필드

sy-로 시작하는 값은 SAP가 알아서 채워 주는 시스템 필드예요.

필드 뜻 예 / 언제 봐요?
sy-subrc 방금 한 일의 결과. 0이면 성공 READ TABLE, SELECT, CALL FUNCTION 바로 뒤
sy-tabix LOOP에서 지금 줄 번호. READ TABLE로 찾은 줄 번호 MODIFY gt_book FROM gs_book INDEX sy-tabix.
sy-index DO·WHILE에서 지금 몇 번째 바퀴 4장 구구단
sy-dbcnt SELECT 같은 SQL 문장이 처리한 줄 수 9장
sy-datum 오늘 날짜. 안에는 YYYYMMDD로 들어 있어요 20261117. WRITE로 찍으면 2026.11.17처럼 구분 기호가 붙어요
sy-uzeit 지금 시각 (HHMMSS) 093000
sy-uname 로그인한 사용자 ID
sy-mandt 로그인한 클라이언트 번호 100
sy-langu 로그인한 언어. 안에는 한 글자로 들어 있어요 3(한국어), E(영어). 화면에는 KO, EN으로 보여요
sy-repid 지금 실행 중인 프로그램 이름
sy-sysid 시스템 ID
기억해 두기

sy-subrc, sy-tabix, sy-dbcnt는 뒤의 문장이 실행되면서 바뀔 수 있어요. 필요하면 바로 다음 줄에서 확인하거나 내 변수에 옮겨 둬요. sy-index도 반복문이 끝나면 반복 전 값(보통 0)으로 돌아가요(4-7).

D. 옛 문법과 새 문법 대응표

이 교재는 회사 프로그램에서 가장 많이 보는 옛(Classic) 문법으로 배웠어요. 요즘 코드에서는 오른쪽 모양도 자주 보이니, 보면 "아, 그거구나" 할 정도로만 알아 두세요. 본문의 "이렇게도 써요" 상자에서 본 것에, 요즘 코드에서 자주 만나는 몇 가지(COND, SWITCH, gt_book[ … ])를 더해 모았어요. 괄호 안의 번호는 왼쪽 문법을 배운 절이에요. 수업 시스템의 버전에 따라 쓸 수 없는 것도 있어요.

하는 일 옛 문법 (이 교재) 새 문법
자기 자신에 더하기 (3-4) gv_cnt = gv_cnt + 1. gv_cnt += 1.
변수 만들기 (3-2) DATA gv_cnt TYPE i. 뒤에 gv_cnt = 10. DATA(lv_cnt) = 10.
글자 잇기 (3-5) CONCATENATE gv_a gv_b INTO gv_c SEPARATED BY space. gv_c = |{ gv_a } { gv_b }|.
대문자로 · 공백 정리 (3-6) TRANSLATE gv_a TO UPPER CASE. · CONDENSE gv_a. gv_a = to_upper( gv_a ). · gv_a = condense( gv_a ).
조건으로 값 고르기 (4-1) IF … ELSE … ENDIF. gv_s = COND #( WHEN gv_stock = 0 THEN '품절' ELSE '있음' ).
값에 따라 고르기 (4-5) CASE … WHEN … ENDCASE. gv_t = SWITCH #( gv_genre WHEN 'N' THEN '소설' WHEN 'I' THEN 'IT' ).
같은 이름 칸 옮기기 (8-1) MOVE-CORRESPONDING gs_a TO gs_b. gs_b = CORRESPONDING #( gs_a ).
여러 줄 넣기 (8-3) APPEND를 여러 번 gt_book = VALUE #( ( … ) ( … ) ).
Work Area 만들기 (8-4) DATA gs_book TYPE ty_book. 뒤에 LOOP AT gt_book INTO gs_book. LOOP AT gt_book INTO DATA(ls_book).
한 줄 찾기 (8-5) READ TABLE gt_book INTO gs_book WITH KEY book_id = 'B0001'. gs_book = gt_book[ book_id = 'B0001' ]. (없으면 예외가 나요)
줄 수 세기 (8-6) DESCRIBE TABLE gt_book LINES gv_lines. gv_lines = lines( gt_book ).
Field Symbol 만들기 (8-7) FIELD-SYMBOLS <gs_book> TYPE ty_book. 뒤에 LOOP AT gt_book ASSIGNING <gs_book>. LOOP AT gt_book ASSIGNING FIELD-SYMBOL(<ls_book>).
DB 읽기 (9-3) SELECT * FROM yta_g##_book INTO TABLE gt_book WHERE genre = pa_genre. SELECT * FROM yta_g##_book WHERE genre = @pa_genre INTO TABLE @DATA(lt_book).
코드 나누기 (10-2) FORM / PERFORM 클래스의 METHOD (10-4에서 맛봤어요)
  • 오른쪽 칸의 DATA( ), FIELD-SYMBOL( )처럼 쓰는 자리에서 바로 만든 것은 이름이 l로 시작해요. 본문의 상자(3-8, 8-6, 8-7, 9-5)와 같아요(부록 F).
  • 괄호 앞의 #은 "Type은 값을 받는 변수와 같게"라는 뜻이에요. gv_s = COND #( … ).이면 결과가 gv_s의 Type이 돼요. # 자리에 string 같은 Type 이름을 직접 적어도 돼요.
  • 표에 TRY … CATCH가 없는 까닭은 새 문법이 아니라서예요. 6-8에서 배웠고 11장 ALV에서 계속 썼어요. Function Module의 EXCEPTIONS와 sy-subrc(10-3)는 그보다 오래된 다른 장치예요. 지금도 많이 쓰니 둘 다 읽을 줄 알아야 해요.
  • lines( )는 옛 시스템에서도 돼요. 요즘 코드에서 DESCRIBE TABLE보다 훨씬 자주 보여서 표에 넣었어요.
  • 오른쪽 문법은 대부분 NetWeaver 7.40부터 돼요. +=는 그보다 뒤(7.54)에 생겼어요.

완성 예제: 새 문법으로 쓴 도서 목록

조각으로만 보면 손에 익지 않아요. 프로그램 하나를 처음부터 끝까지 새 문법으로 써 볼게요. 프로그램 이름은 YG##_148, Title은 [예제] 새 문법으로 쓴 도서 목록이에요. 재고가 있는 책을 비싼 순서로 읽어서, 재고가 3권 미만이면 부족, 아니면 충분을 붙여 출력해요.

7.40 SP08 이상에서만 돼요

이 프로그램은 NetWeaver 7.40 SP08 이상에서만 활성화돼요. 교재와 똑같이 쳤는데 @나 쉼표가 있는 줄에서 문법 오류가 나면, 내 실수가 아니라 시스템이 옛 버전인 거예요. 오타인지 헷갈리면 웹 교재의 복사 버튼으로 코드를 붙여 넣어 봐요. 그래도 같은 줄에서 오류가 나면 옛 버전이 맞아요. 그럴 때는 따라 치지 말고 눈으로만 읽어요.

맨 위에 TYPES도, DATA … TYPE … 선언 줄도 없죠. 변수 네 개는 모두 처음 쓰는 자리에서 DATA( )로 바로 만들었어요(3-8의 인라인 선언). 그래서 이름도 l로 시작해요. 본문에서 배운 문법과 견줘 보면 이래요.

여기서는 뜻 본문에서는
SELECT book_id, title, … 읽을 칸 사이에 쉼표를 찍어요 쉼표 없는 Field 목록 (9-3)
INTO TABLE @DATA(lt_book) 받을 Internal Table을 그 자리에서 만들어요. 칸은 읽은 네 칸 그대로예요. @는 "ABAP 변수예요"라는 표시이고, INTO가 맨 뒤로 갔어요 TYPES와 DATA로 미리 선언하고 INTO TABLE (9-3)
LOOP AT … INTO DATA(ls_book) Work Area를 그 자리에서 만들어요 DATA gs_book 선언 뒤 LOOP AT … INTO gs_book (8-4)
COND string( WHEN … THEN … ELSE … ) 조건에 맞는 값을 골라서 돌려줘요. 위 대응표에서는 #을 썼지만, 여기서는 받는 변수도 그 자리에서 만들어서 결과의 Type(string)을 직접 적었어요 IF … ELSE … ENDIF (4-1)
|{ … } { … }| 문자열 템플릿. { } 안의 변수 값이 그 자리에 들어가요 CONCATENATE … SEPARATED BY space (3-5)

문자열 템플릿을 감싸는 |는 JavaScript의 ||에 쓰던 그 글자예요. Shift를 누른 채 \(한글 자판에서는 ₩) 키를 눌러요. 이 교재처럼 가운데가 끊어진 막대로 보이는 글꼴도 있어요.

같은 일을 본문 문법으로 쓰면 선언과 IF 때문에 길이가 두 배쯤 돼요. 다음 과정(CDS, RAP)의 예제 코드는 처음부터 이런 모양이니, 한 번은 손으로 쳐 보세요.

E. 회사 코드에서 만나는 옛 모양 읽기

이 교재의 "옛 문법"은 깔끔하게 쓴 Classic 문법이에요. 그런데 회사에서 처음 열어 보는 10~20년 된 프로그램은 그보다 한 세대 더 옛 모양인 경우가 많아요. 아래 표는 쓰려고 외우는 표가 아니라 읽으려고 찾아보는 표예요. 새로 쓸 때는 본문에서 배운 모양으로 써요. 12-9 읽기 실습의 YG##_147을 읽을 때 옆에 펴 두세요.

한 줄에 모양이 둘 이상이면 가운뎃점(·)으로 나눴어요. 오른쪽 설명도 같은 순서예요.

회사 코드의 모양 뜻, 교재의 같은 모양
TABLES yta_g##_book. Table과 이름이 같은 Work Area를 만들어요. SELECT-OPTIONS s_genre FOR yta_g##_book-genre.의 FOR 뒤에 쓰려고 맨 위에 두는 경우가 많아요. 교재는 DATA gs_book TYPE yta_g##_book.을 따로 만들었어요 (9-5)

I. 다음에 배울 것

이 교재는 SAP GUI에서 쓰는 Classic ABAP까지 다뤘어요. 다음 과정에서는 CDS View를 만들고, 그것을 OData 서비스로 열어서, 앞 과정에서 배운 SAPUI5 화면과 이어요. 지금 다 알 필요는 없고, 이름만 눈에 익혀 두세요.

이름 한 줄 설명
ADT (ABAP Development Tools) Eclipse에서 ABAP을 개발하는 도구. SE38 대신 쓰는 편집기라고 생각하면 돼요. CDS View는 여기서 만들어요
CDS View DB 데이터를 원하는 모양으로 미리 정의해 두는 "똑똑한 View". 7장 Dictionary와 9장 SQL의 다음 단계예요
OData 서비스 화면(브라우저)과 ABAP 서버가 데이터를 주고받는 창구. 화면이 주소로 요청하면 ABAP이 데이터를 돌려줘요
RAP (RESTful Application Programming Model) CDS View와 클래스로 OData 서비스를 만드는 방법. SAPUI5로 만든 SAP의 웹 화면(Fiori 앱)이 이 서비스를 불러 써요
SAPUI5 연동 앞 과정에서 만든 SAPUI5 화면이 OData 서비스를 불러서, ABAP이 읽은 데이터를 보여 주고 고치는 것
새 ABAP 문법 부록 D의 오른쪽 문법들. 인라인 선언, 문자열 템플릿, VALUE, COND 등
ABAP 객체지향 클래스, 객체, Method, 예외 클래스. 10-4 맛보기의 본편이에요
ABAP Cloud 클라우드에서도 쓸 수 있도록 정해진 규칙 안에서 개발하는 방식

이 교재에서 배운 것 다시 만나는 곳

이 교재에서 다루지 않은 것 가운데 이름을 자주 듣게 될 두 가지예요.

  • SE93: 내 프로그램에 T-code를 붙이는 화면이에요. 회사 사용자는 프로그램 이름이 아니라 T-code로 실행해요.
