7장

ABAP Dictionary

이번 장 목표
  • 데이터를 프로그램 밖에 오래 보관하려면 왜 Table이 필요한지 알아요.
  • Domain, Data Element, Table이 어떤 관계인지 그림으로 설명할 수 있어요.
  • SE11에서 Domain → Data Element → Table을 순서대로 만들고 활성화할 수 있어요.
  • MANDT와 Key가 왜 필요한지 알고, Table에 데이터를 넣고 조회할 수 있어요.
  • 만들어 둔 Domain과 Data Element를 다시 써서 두 번째 Table을 혼자 만들 수 있어요.

7-1. 프로그램이 끝나도 남는 데이터

3~6장의 변수는 프로그램이 끝나면 모두 사라져요. 도서 목록처럼 내일도, 다음 달에도 써야 하는 데이터는 데이터베이스(DB)의 Table에 저장해요. SAP에서 Table의 설계도를 만들고 관리하는 곳이 ABAP Dictionary, 트랜잭션 코드는 SE11이에요.

1주차에 이미 한 번 만들어 봤죠? 이번 장에서는 그때 한 일을 "왜 이렇게 하는지" 중심으로 차근차근 다시 정리해요. 그리고 9장부터 12장까지 계속 쓸 도서 Table을 만들어요.

7-2. Domain · Data Element · Field의 관계

Table의 칸(Field) 하나를 만들려면 두 가지 정보가 필요해요.

  • 기술 정보: 글자인가 숫자인가, 몇 칸인가, 어떤 값만 들어갈 수 있나 → Domain
  • 의미 정보: 이 칸은 무엇인가, 화면에 어떤 이름표를 보여 줄까 → Data Element

그림에서 YDO_G##_NAME Domain 하나를 제목과 저자 두 Data Element가 함께 쓰고 있어요. 둘 다 "글자 40칸"이라는 기술 규칙은 같지만, 의미(이름표)는 "도서 제목"과 "저자"로 달라요. 이렇게 규칙은 한 곳에 두고 여러 곳에서 다시 쓰는 것이 Dictionary의 핵심이에요.

객체 한 줄 설명 비유
Domain Type, 길이, 허용 값 그릇의 크기와 재질
Data Element 의미, Field Label(이름표) 그릇에 붙인 라벨
Table Field들을 모아 실제로 데이터를 저장 그릇을 줄지어 놓은 찬장
Data Element는 Domain 없이도 만들 수 있어요

Data Element의 Type에는 Domain 대신 Predefined Type을 바로 적을 수도 있어요. Predefined Type은 SAP가 미리 만들어 둔 기본 Type이에요(예: 정수 INT4, 자릿수를 정하는 숫자 DEC). 고정값이나 소문자 설정이 필요 없고, 다른 곳에서 다시 쓸 일이 없는 단순한 숫자라면 이 방법이 간단해요. 이번 장에서도 가격과 재고는 이렇게 만들어요.

7-3. 이번 장에서 만들 것

9장부터 12장까지 계속 쓸 도서 Table YTA_G##_BOOK이에요. 만드는 순서는 Domain → Data Element → Table이에요. 바탕이 되는 것부터 만들어야 그다음 것이 가져다 쓸 수 있거든요. Domain 3개, Data Element 6개, Table 1개를 만들어요.

Field Key Data Element Type (Domain 또는 Predefined) 이름표
MANDT ✔ MANDT CLNT 3 (SAP가 만들어 둔 것) 클라이언트
BOOK_ID ✔ YDE_G##_BOOK_ID Domain YDO_G##_BOOK_ID (CHAR 5) 도서 번호
TITLE YDE_G##_TITLE Domain YDO_G##_NAME (CHAR 40, 소문자) 도서 제목
AUTHOR YDE_G##_AUTHOR Domain YDO_G##_NAME 저자
GENRE YDE_G##_GENRE Domain YDO_G##_GENRE (CHAR 1, 고정값) 장르
PRICE YDE_G##_PRICE Predefined DEC 9, 소수 0 가격
STOCK YDE_G##_STOCK Predefined INT4 재고

표의 Key는 줄 하나를 콕 집어내는 데 쓰는 칸이에요. 7-6에서 자세히 봐요.

Type 이름이 3장과 조금 다르죠? Dictionary에서는 3-3에서 배운 c를 CHAR, i를 INT4, p를 DEC, d를 DATS라고 불러요. 이름만 다를 뿐 서로 짝이 되는 Type이에요.

객체 이름은 앞머리 세 글자만 봐도 종류를 알 수 있어요. YDO는 Domain, YDE는 Data Element, YTA는 Table이에요(0-3, 부록 F).

지금까지 본 카드는 거의 다 Program을 만드는 카드였죠? Dictionary 객체의 카드에는 Title 대신 SE11 화면에 넣을 값이 적혀 있어요. 그대로 넣으면 돼요. Short Description(짧은 설명)도 5-6의 Message Class 때처럼 카드의 글자 그대로 적어요. 나중에 내가 만든 것을 다시 찾을 때 길잡이가 돼요.

직접 해 보기
  1. SE11에서 Domain을 고르고 YDO_G##_NAME을 입력한 뒤 Create를 눌러요. 1 2
  2. Short Description에 도서 이름용 글자 40칸을 적어요.
  3. Definition 탭에서 Data Type CHAR, No. Characters 40을 넣어요.
  4. Lowercase에 체크해요. 영어 제목이 대문자로 바뀌지 않게 하려는 거예요.
  5. 저장(Local Object) → 검사(Ctrl+F2) → 활성화(Ctrl+F3). 2장의 순서와 똑같아요. 이름 옆의 상태가 New에서 Active로 바뀌면 끝이에요.
만든 것을 다시 열어 고치거나 지우려면

프로그램 때와 같아요(2-8). SE11 첫 화면에서 종류를 고르고 이름을 넣은 뒤 Change를 누르면 고칠 수 있어요. 고친 뒤에는 다시 저장하고 활성화해요. 이름이 기억나지 않으면 YDO_G##*처럼 적고 F4를 눌러 목록에서 골라요. 조건을 묻는 창이 먼저 뜨면 Enter를 눌러요.

이름을 틀리게 만들었다면 같은 화면에서 그 이름을 넣고 도구 모음의 Delete(휴지통 모양)로 지운 뒤 새로 만들어요. 다른 객체가 쓰고 있는 것은 지워지지 않아요. 그럴 때는 쓰는 쪽부터, 곧 Table → Data Element → Domain 순서로 지워요. 버튼의 위치는 버전에 따라 조금 달라요.

Domain을 넣고 Enter를 누르면 Data Type과 Length가 Domain에서 자동으로 채워져요(회색). 직접 고칠 필요가 없어요.

Field Label이 네 칸인 것은 이름표를 놓을 자리의 너비가 쓰이는 곳마다 달라서예요. 좁은 자리에는 Short, 넓은 자리에는 Medium이나 Long이 쓰여요. 그래서 Short에는 연습 삼아 줄인 말 제목을 적어 봤어요. Heading은 표의 칸 제목에 쓰려고 적어 두는 이름표예요.

Length 칸은 비워 두면 알아서 채워져요. 적은 글자 수에 맞춰 잡히기도 해서, 숫자가 그림과 달라도 괜찮아요.

Field Label은 어디에 쓰여요?

Field Label은 Selection Screen의 이름표(5-2에서 본 Selection Text 화면의 Dictionary Ref. 칸. 9-3에서 써 봐요), 데이터 입력 화면, 11장에서 배울 ALV 표의 칸 제목에 자동으로 쓰여요. 한 번 잘 적어 두면 여러 곳에서 이름표를 따로 붙이지 않아도 돼요.

따라 하기 ② Field 넣기

직접 해 보기
  1. Fields 탭을 눌러요.
  2. 7-3의 표대로 일곱 줄을 넣어요(그림 7-6). Field에 칸 이름, Data element에 7-5에서 만든 이름을 적고 Enter를 누르면 Type, 길이, 설명이 자동으로 채워져요.
  3. MANDT와 BOOK_ID 두 줄만 Key 칸에 체크해요.
  • 첫 줄은 Field도 Data element도 MANDT예요. Data Element MANDT는 SAP가 만들어 둔 것이라 이름만 적으면 돼요.
  • Key는 "이 값으로 한 줄을 콕 집어낼 수 있는 칸"이에요. 도서 번호가 같은 책이 두 권 있으면 안 되니까 BOOK_ID가 Key예요.
  • Key는 Table 맨 앞에 붙여서 놓아요. MANDT, BOOK_ID 순서예요.
  • Initial Val.은 직접 건드리지 않아도 돼요. Key로 체크한 줄은 저절로 체크돼요.
자주 하는 실수
  • MANDT를 빼먹지 마세요. 1장 1-2에서 본 것처럼, MANDT가 있어야 데이터가 클라이언트(집)마다 나뉘어요. 업무 데이터를 담는 Table이라면 항상 첫 번째 Field, Key로 넣어요. 1주차 과제에서 가장 많이 빠졌던 부분이에요.
  • Key를 전부 체크하면 "모든 칸이 같아야 같은 줄"이 되어 버려요. 그러면 같은 도서 번호로 제목만 다른 줄이 여러 개 들어갈 수 있어요. Key는 꼭 필요한 칸만 체크해요.

따라 하기 ③ Technical Settings와 Enhancement Category

Table은 활성화하기 전에 두 가지를 더 정해야 해요.

직접 해 보기
  1. 도구 모음의 Technical Settings 버튼을 눌러요. 먼저 저장할지 묻는 창이 뜨면 Yes를 누르고 Local Object로 저장해요.
    • Data Class: APPL0 (자주 바뀌지 않는 기본 데이터)
    • Size Category: 0 (데이터가 적은 Table)
    • 저장하고 F3으로 돌아와요.
  2. 메뉴 Extras → Enhancement Category에서 Can Be Enhanced (Deep)을 고르고 Copy를 눌러요. 안내 창이 먼저 뜨면 Enter로 넘겨요. (안 하면 활성화할 때 경고가 나와요.)
  3. 저장 → 검사 → 활성화해요. 상태가 Active가 되면 완성이에요!

Enhancement Category는 나중에 이 Table에 칸을 덧붙여도 되는지 정해 두는 설정이에요. 지금은 위 값으로 두면 돼요.

활성화가 안 되면 Data Element나 Domain 가운데 아직 Active가 아닌 것이 있는지 먼저 봐요. Domain → Data Element → Table 순서로 활성화해야 해요.

Structure는 Table과 무엇이 달라요?

7-5에서 Data type을 고르고 Create를 눌렀을 때 뜬 작은 창에 Structure도 있었죠? Table과 똑같이 Field를 모아 두지만 DB에 데이터를 저장하지 않는 설계도예요. 이름은 YST_G##_…로 지어요. 8장에서 프로그램 안의 Structure를 먼저 배우고, 11-3에서 Dictionary Structure를 직접 만들어 봐요.

  1. 명령 필드에 /nSE16N을 입력해요.
  2. Table 칸에 YTA_G##_BOOK을 넣고 Enter를 눌러요.
  3. 조건 없이 F8을 누르면 넣은 데이터가 모두 보여요. 조건 칸에 값을 넣으면 걸러서 볼 수도 있어요.

우리 Table은 다섯 줄이라 조건 없이 봐도 괜찮아요. 회사 Table은 수백만 줄이라 SE16N에서도 조건을 넣고 조회해요.

보이는 값과 저장된 값은 다를 수 있어요

가격에 25000을 넣었는데 그림 7-8에는 25,000으로 보이죠? 쉼표는 화면이 읽기 좋게 붙여 준 것이고, DB에는 25000이 들어 있어요. 내 사용자 설정에 따라 쉼표 대신 점(25.000)으로 보이기도 해요. 이렇게 화면에 보이는 모양과 저장된 값이 다른 칸이 꽤 있어요.

  • 날짜: DB에는 20261103처럼 숫자 여덟 자리로 저장돼요. 화면에는 2026.11.03이나 03.11.2026처럼 내 사용자 설정에 맞춰 보여요. 바로 다음 7-8에서 만나요.
  • 앞자리 0: 회사 Table의 문서 번호 같은 칸은 0000004711로 저장되어 있어도 화면에는 4711만 보이곤 해요.

SAP가 만들어 둔 표준 Table을 처음 조회할 때 누구나 한 번씩 헷갈리는 부분이에요. 프로그램에서 조건을 줄 때는 저장된 값을 기준으로 써요.

자주 하는 실수
  • Create Entries가 안 보이거나 막혀요: 7-6에서 Data Browser/Table View Editing을 Display/Maintenance Allowed로 했는지 확인해요. 고친 뒤에는 다시 활성화해요.
  • 같은 도서 번호를 또 넣었더니 오류: Key가 같은 줄은 두 번 넣을 수 없어요. 정상이에요.
  • 값을 틀리게 넣고 저장했어요: Table 화면에서 Utilities → Table Contents → Display로 들어가 F8을 눌러요. 고칠 줄 앞의 네모에 체크하고 메뉴 Table Entry → Change로 고쳐요. 도서 번호(Key)를 틀렸다면 Table Entry → Delete로 지우고 다시 넣어요. 버전에 따라 메뉴 이름이 조금 달라요.
  • 데이터를 넣은 뒤 Table을 고쳤더니 활성화가 안 돼요: Key나 Type을 바꾸면 DB에 이미 있는 데이터와 맞지 않아서 그래요. 혼자 풀기 어려우니 먼저 강사에게 물어봐요. 고치는 방법은 SE11 메뉴 Utilities → Database Object → Database Utility의 Activate and adjust database예요(Save data를 고른 채로 눌러요).

7-8. 미니 실습: 대여 기록 Table 만들기

이번에는 따라 하기 없이 혼자 만들어 봐요. 도서관에는 책 목록 말고도 누가 어떤 책을 언제 빌려 갔는지 적어 두는 대여 기록이 필요해요. 이 Table은 9-6에서 도서 Table과 이어 읽을 때 다시 써요.

새로 만들 것은 Data Element 세 개와 Table 하나예요. Domain은 새로 만들지 않아요. 앞에서 만든 것을 다시 쓰는 연습이거든요. 회원 이름도 "글자 40칸, 소문자 허용"이면 충분하니 YDO_G##_NAME을 그대로 써요. Domain의 설명은 "도서 이름용"이지만, 기술 규칙이 같으면 다시 써도 돼요.

둘째 칸의 제목이 도서 번호로 나왔죠? 이번 실습에서는 어디에도 적지 않은 글자예요. 7-5에서 만든 Data Element를 다시 썼기 때문에 이름표도 따라온 거예요.

없는 책 번호도 들어가요

BOOK_ID에 B9999처럼 도서 Table에 없는 번호를 넣어도 지금은 막히지 않아요. 막으려면 Table끼리의 관계를 정해 주는 Foreign Key를 쓰는데, 이 교재에서는 다루지 않아요.

예시 답안 보기
Field Key Data Element
MANDT ✔ MANDT
RENT_ID ✔ YDE_G##_RENT_ID
BOOK_ID YDE_G##_BOOK_ID (7-5에서 만든 것)
MEMBER_NAME YDE_G##_MEMBER
RENT_DATE YDE_G##_RENT_DATE

막히기 쉬운 곳이에요.

  • MANDT: 문제에는 없었지만 업무 데이터를 담는 Table이니 첫 번째 Field, Key로 넣어요.
  • Key는 MANDT와 RENT_ID뿐이에요: 한 줄을 콕 집는 데는 대여 번호 하나면 충분해요. RENT_ID 대신 BOOK_ID를 Key로 삼으면 같은 책을 두 번째로 빌린 줄(R0003)이 안 들어가요. 둘 다 Key로 체크하면 들어가기는 하지만, 같은 대여 번호가 책만 바꿔서 두 줄 들어갈 수 있게 돼요(7-6의 "자주 하는 실수").
  • Field 이름과 Data Element 이름은 달라도 돼요: MEMBER_NAME Field에 YDE_G##_MEMBER를 써요.
  • 활성화가 안 되거나 Create Entries가 막히면 7-6 끝의 안내와 7-7의 "자주 하는 실수"를 다시 봐요.
  • 데이터를 넣은 뒤에 MANDT나 Key가 틀린 것을 알았다면: 넣은 줄을 먼저 모두 지워요(7-7 "자주 하는 실수"의 Table Entry → Delete). 빈 Table은 Key를 바꿔도 그대로 활성화돼요. 고친 다음 네 줄을 다시 넣어요.
확인 문제
  1. Domain과 Data Element는 각각 무엇을 정할까요? 한마디씩 말해 보세요.
  2. 제목과 저자가 같은 Domain YDO_G##_NAME을 쓰는데도 화면에 다른 이름표가 보이는 이유는 무엇일까요?
  3. Table에 MANDT를 넣지 않으면 어떤 문제가 생길까요?
  4. Domain, Data Element, Table은 어떤 순서로 만들고 활성화해야 할까요?
  5. 장르 칸에 X를 넣었더니 오류가 났어요. 왜 그럴까요?
  6. 대여 기록 Table의 BOOK_ID에 새 Data Element를 만들지 않고 YDE_G##_BOOK_ID를 다시 썼어요. 무엇이 좋을까요?
  7. SE16N에서 대여일이 2026.11.03으로 보여요. DB에는 어떤 값으로 저장되어 있을까요?
정답 보기
  1. Domain은 기술 규칙(Type·길이·허용 값), Data Element는 의미(설명·이름표)예요.
  2. 이름표(Field Label)는 Domain이 아니라 Data Element에 있기 때문이에요. 제목과 저자는 Data Element가 서로 달라요.
  3. 데이터가 클라이언트별로 나뉘지 않아서, 다른 클라이언트에서도 같은 데이터가 보이게 돼요. 업무 데이터 Table에는 항상 MANDT를 첫 Key로 넣어요.
  4. Domain → Data Element → Table 순서예요. 가져다 쓰이는 쪽이 먼저 활성화되어 있어야 해요.
  5. YDO_G##_GENRE Domain의 고정값에 N, I, E만 있기 때문이에요.
  6. Type과 길이(CHAR 5), 이름표(도서 번호)를 다시 정하지 않아도 도서 Table과 똑같이 맞춰져요. 나중에 규칙을 바꿀 때도 한 곳만 고치면 돼요.
  7. 20261103이에요. 날짜는 구분 기호 없이 여덟 자리로 저장되고, 화면이 사용자 설정에 맞춰 보여 줄 뿐이에요.
정리
  • 오래 보관할 데이터는 DB Table에 저장하고, 그 설계도는 SE11(ABAP Dictionary)에서 만들어요.
  • Domain은 기술 규칙, Data Element는 의미와 이름표, Table Field는 실제 칸이에요. 만드는 순서도 이 순서예요.
  • Domain 하나를 여러 Data Element가, Data Element 하나를 여러 Table이 다시 쓸 수 있어요. 정해진 값만 받으려면 Domain의 고정값을 써요.
  • Table에는 MANDT를 첫 Key로 넣고, Key는 한 줄을 콕 집어낼 수 있는 칸만 체크해요.
  • 데이터는 Utilities → Table Contents → Create Entries로 넣고, SE16N으로 조회해요.
  • 화면에 보이는 모양과 저장된 값은 다를 수 있어요. 날짜는 20261103처럼 저장돼요.
  • 이름은 YDO_(Domain), YDE_(Data Element), YTA_(Table)로 시작해요. 이번 장에서 YTA_G##_BOOK(도서 목록)과 YTA_G##_RENT(대여 기록)를 만들었어요.
다음 장 예고

Table에 도서 다섯 권이 들어갔어요. 이 데이터를 프로그램으로 가져오면 여러 줄이 한꺼번에 와요. 8장에서는 여러 줄 데이터를 메모리에 담는 그릇, Internal Table을 배워요. 대여 기록 Table은 9-6에서 다시 만나요.
