7장

ABAP Dictionary

이번 장 목표
  • 데이터를 프로그램 밖에 오래 보관하려면 왜 Table이 필요한지 알아요.
  • Domain, Data Element, Table이 어떤 관계인지 그림으로 설명할 수 있어요.
  • SE11에서 Domain → Data Element → Table을 순서대로 만들고 활성화할 수 있어요.
  • MANDT와 Key가 왜 필요한지 알고, Table에 데이터를 넣고 조회할 수 있어요.

7-1. 프로그램이 끝나도 남는 데이터

3~6장의 변수는 프로그램이 끝나면 모두 사라져요. 도서 목록처럼 내일도, 다음 달에도 써야 하는 데이터는 데이터베이스(DB)의 Table에 저장해요. SAP에서 Table의 설계도를 만들고 관리하는 곳이 ABAP Dictionary, 트랜잭션 코드는 SE11이에요.

1주차에 이미 한 번 만들어 봤죠? 이번 장에서는 그때 한 일을 "왜 이렇게 하는지" 중심으로 차근차근 다시 정리해요. 그리고 8~9장에서 계속 쓸 도서 Table을 만들어요.

7-2. Domain · Data Element · Field의 관계

Table의 칸(Field) 하나를 만들려면 두 가지 정보가 필요해요.

  • 기술 정보: 글자인가 숫자인가, 몇 칸인가, 어떤 값만 들어갈 수 있나 → Domain
  • 의미 정보: 이 칸은 무엇인가, 화면에 어떤 이름표를 보여 줄까 → Data Element

그림에서 YG##_D_NAME Domain 하나를 제목과 저자 두 Data Element가 함께 쓰고 있어요. 둘 다 "글자 40칸"이라는 기술 규칙은 같지만, 의미(이름표)는 "도서 제목"과 "저자"로 달라요. 이렇게 규칙은 한 곳에 두고 여러 곳에서 다시 쓰는 것이 Dictionary의 핵심이에요.

객체 한 줄 설명 비유
Domain Type, 길이, 허용 값 그릇의 크기와 재질
Data Element 의미, Field Label(이름표) 그릇에 붙인 라벨
Table Field들을 모아 실제로 데이터를 저장 그릇을 줄지어 놓은 찬장
Data Element는 Domain 없이도 만들 수 있어요

Data Element의 Type에는 Domain 대신 Predefined Type(예: INT4, DEC)을 바로 적을 수도 있어요. 고정값이나 소문자 설정이 필요 없고, 다른 곳에서 다시 쓸 일이 없는 단순한 숫자라면 이 방법이 간단해요. 이번 장에서도 가격과 재고는 이렇게 만들어요.

7-3. 이번 장에서 만들 것

8~9장에서 계속 쓸 도서 Table YG##_BOOK이에요. 만드는 순서는 Domain → Data Element → Table이에요. 아래에 있는 것부터 만들어야 위에서 가져다 쓸 수 있거든요.

Field Key Data Element Type (Domain 또는 Predefined) 이름표
MANDT ✔ MANDT CLNT 3 (SAP가 만들어 둔 것) 클라이언트
BOOK_ID ✔ YG##_E_BOOK_ID Domain YG##_D_BOOK_ID (CHAR 5) 도서 번호
TITLE YG##_E_TITLE Domain YG##_D_NAME (CHAR 40, 소문자) 도서 제목
AUTHOR YG##_E_AUTHOR Domain YG##_D_NAME 저자
GENRE YG##_E_GENRE Domain YG##_D_GENRE (CHAR 1, 고정값) 장르
PRICE YG##_E_PRICE Predefined DEC 9, 소수 0 가격
STOCK YG##_E_STOCK Predefined INT4 재고
이름 규칙

교재에서는 Domain은 _D_, Data Element는 _E_를 넣어 구분해요. Table과 Dictionary 객체도 Local Object로 저장하니 Y로 시작해요. 수업에서 따로 정한 이름이 있으면 그 규칙을 따르세요.

7-4. Domain 만들기

SE11 첫 화면

라디오 버튼으로 무엇을 만들지 고르고, 옆 칸에 이름을 넣어요. Data Element는 Data type 줄에서 만들어요.

따라 하기 ① 글자 Domain YG##_D_NAME

직접 해 보기
  1. SE11에서 Domain을 고르고 YG##_D_NAME을 입력한 뒤 Create를 눌러요. 1 2
  2. Short Description에 도서 이름용 글자 40칸을 적어요.
  3. Definition 탭에서 Data Type CHAR, No. Characters 40을 넣어요.
  4. Lowercase에 체크해요. 영어 제목이 대문자로 바뀌지 않게 하려는 거예요.
  5. 저장(Local Object) → 검사(Ctrl+F2) → 활성화(Ctrl+F3). 2장의 순서와 똑같아요.

따라 하기 ② 도서 번호 Domain YG##_D_BOOK_ID

같은 방법으로 CHAR 5짜리 Domain을 만들어요. 도서 번호는 B0001처럼 대문자로 쓸 거라 Lowercase는 체크하지 않아요.

따라 하기 ③ 고정값이 있는 Domain YG##_D_GENRE

장르는 아무 글자나 들어가면 안 되고 정해진 값만 들어가야 해요. 이럴 때 Domain의 Fixed Value(고정값)를 써요.

직접 해 보기
  1. YG##_D_GENRE를 CHAR 1로 만들어요.
  2. Value Range 탭으로 가서 아래처럼 고정값과 설명을 넣어요.
  3. 저장 → 검사 → 활성화해요.
고정값 설명은 꼭 넣어요

코드는 N, I, E처럼 짧게 두고, 사람이 읽을 뜻은 Short Descript.에 적어요. 데이터를 넣는 화면에서 F4(값 목록)를 누르면 이 설명이 함께 보여서 고르기 쉬워요. 고정값에 없는 값을 넣으면 화면에서 오류로 막아 줘요.

7-5. Data Element 만들기

따라 하기 ① Domain을 쓰는 Data Element YG##_E_TITLE

직접 해 보기
  1. SE11에서 Data type을 고르고 YG##_E_TITLE을 입력한 뒤 Create를 눌러요.
  2. 작은 창이 뜨면 Data element를 고르고 Enter를 눌러요.
  3. Short Description에 도서 제목을 적어요.
  4. Data Type 탭에서 Elementary Type → Domain을 고르고 YG##_D_NAME을 넣어요. 1
  5. Field Label 탭에서 길이별 이름표를 모두 적어요. 2
  6. 저장 → 검사 → 활성화해요.

Domain을 넣고 Enter를 누르면 Data Type과 Length가 Domain에서 자동으로 채워져요(회색). 직접 고칠 필요가 없어요.

같은 방법으로 아래 Data Element를 만들어요.

Data Element Domain Short Description · Field Label
YG##_E_BOOK_ID YG##_D_BOOK_ID 도서 번호
YG##_E_AUTHOR YG##_D_NAME 저자
YG##_E_GENRE YG##_D_GENRE 장르

따라 하기 ② Predefined Type을 쓰는 Data Element

가격과 재고는 Domain 없이 만들어 볼게요. Data Type 탭에서 Predefined Type을 고르고 Type을 직접 적으면 돼요.

Data Element Predefined Type Length Decimal Places Field Label
YG##_E_PRICE DEC 9 0 가격
YG##_E_STOCK INT4 (자동 10) 재고
Field Label은 어디에 쓰여요?

Field Label은 Selection Screen의 이름표(5장 Selection Text의 Dictionary Ref.), 데이터 입력 화면, 11장의 ALV 표 머리글에 자동으로 쓰여요. 한 번 잘 적어 두면 여러 곳에서 이름표를 따로 붙이지 않아도 돼요.

7-6. Table 만들기

따라 하기 ① Table 속성 정하기

직접 해 보기
  1. SE11에서 Database table을 고르고 YG##_BOOK을 입력한 뒤 Create를 눌러요.
  2. Short Description에 도서 목록을 적어요.
  3. Delivery and Maintenance 탭에서 - Delivery Class: A (업무 데이터를 담는 Table) - Data Browser/Table View Editing: Display/Maintenance Allowed (나중에 화면에서 데이터를 넣을 수 있게)

따라 하기 ② Field 넣기

Fields 탭에서 7-3의 표대로 한 줄씩 넣어요.

  • Field에 칸 이름, Data element에 7-5에서 만든 이름을 넣고 Enter를 누르면 Type, 길이, 설명이 자동으로 채워져요.
  • Key는 "이 값으로 한 줄을 콕 집어낼 수 있는 칸"이에요. 도서 번호가 같은 책이 두 권 있으면 안 되니까 BOOK_ID가 Key예요.
  • Key는 Table 맨 앞에 붙여서 놓아요. MANDT, BOOK_ID 순서예요.
자주 하는 실수
  • MANDT를 빼먹지 마세요. 1장 1-2에서 본 것처럼, MANDT가 있어야 데이터가 클라이언트(집)마다 나뉘어요. 업무 데이터를 담는 Table이라면 항상 첫 번째 Field, Key로 넣어요. 1주차 과제에서 가장 많이 빠졌던 부분이에요.
  • Key를 전부 체크하면 "모든 칸이 같아야 같은 줄"이 되어 버려요. 그러면 같은 도서 번호로 제목만 다른 줄이 여러 개 들어갈 수 있어요. Key는 꼭 필요한 칸만 체크해요.

따라 하기 ③ Technical Settings와 Enhancement Category

Table은 활성화하기 전에 두 가지를 더 정해야 해요.

직접 해 보기
  1. 도구 모음의 Technical Settings 버튼을 눌러요. - Data Class: APPL0 (자주 바뀌지 않는 기본 데이터) - Size Category: 0 (데이터가 적은 Table) - 저장하고 F3으로 돌아와요.
  2. 메뉴 Extras → Enhancement Category에서 Can Be Enhanced (Deep)을 고르고 Copy를 눌러요. (안 하면 활성화할 때 경고가 나와요.)
  3. 저장 → 검사 → 활성화해요. 상태가 Active가 되면 완성이에요!
Structure는 Table과 무엇이 달라요?

SE11의 Data type 아래에는 Structure도 있어요. Field를 모아 둔 모양은 Table과 똑같지만 DB에 데이터를 저장하지 않는 설계도예요. 8장에서 프로그램 안의 Structure를 배우면 자연스럽게 이해될 거예요.

7-7. 데이터 넣고 조회하기

데이터 넣기

직접 해 보기
  1. Table YG##_BOOK 화면에서 메뉴 Utilities → Table Contents → Create Entries를 눌러요.
  2. 입력 화면이 나오면 아래 첫 줄을 넣고 저장(Ctrl+S)해요. MANDT는 자동으로 들어가서 칸이 없어요.
  3. Reset을 누르면 빈 화면이 되니, 나머지 네 줄도 같은 방법으로 넣어요.
  4. 장르 칸에서 F4를 눌러 보세요. 고정값 목록이 나와요.
BOOK_ID TITLE AUTHOR GENRE PRICE STOCK
B0001 ABAP 첫걸음 김에이 I 25000 3
B0002 바다의 노래 박소설 N 15000 0
B0003 오늘의 산책 이수필 E 13000 5
B0004 SQL 한 그릇 김에이 I 28000 2
B0005 별을 세는 밤 정하늘 N 17000 7

입력 칸 옆의 이름이 도서 번호, 도서 제목으로 보이죠? 7-5에서 적은 Field Label이 자동으로 쓰인 거예요.

데이터 조회하기: SE16N

직접 해 보기
  1. 명령 필드에 /nSE16N을 입력해요.
  2. Table 칸에 YG##_BOOK을 넣고 Enter를 눌러요.
  3. 조건 없이 F8을 누르면 넣은 데이터가 모두 보여요. 조건 칸에 값을 넣으면 걸러서 볼 수도 있어요.
자주 하는 실수
  • Create Entries가 안 보이거나 막혀요: 7-6에서 Data Browser/Table View Editing을 Display/Maintenance Allowed로 했는지 확인해요.
  • 같은 도서 번호를 또 넣었더니 오류: Key가 같은 줄은 두 번 넣을 수 없어요. 정상이에요.
  • Table이 활성화되지 않아요: Data Element나 Domain 중 활성화 안 된 것이 있는지 확인해요. 아래 객체부터 차례로 활성화해야 해요.
확인 문제
  1. Domain과 Data Element는 각각 무엇을 정할까요? 한 단어씩으로 말해 보세요.
  2. 제목과 저자가 같은 Domain YG##_D_NAME을 쓰는데도 화면에 다른 이름표가 보이는 이유는 무엇일까요?
  3. Table에 MANDT를 넣지 않으면 어떤 문제가 생길까요?
  4. Domain, Data Element, Table은 어떤 순서로 만들고 활성화해야 할까요?
  5. 장르 칸에 X를 넣었더니 오류가 났어요. 왜 그럴까요?
정답 보기
  1. Domain은 기술 규칙(Type·길이·허용 값), Data Element는 의미(설명·이름표)예요.
  2. 이름표(Field Label)는 Domain이 아니라 Data Element에 있기 때문이에요. 제목과 저자는 Data Element가 서로 달라요.
  3. 데이터가 클라이언트별로 나뉘지 않아서, 다른 클라이언트에서도 같은 데이터가 보이게 돼요. 업무 데이터 Table에는 항상 MANDT를 첫 Key로 넣어요.
  4. Domain → Data Element → Table 순서예요. 아래에서 쓰는 것이 먼저 활성화되어 있어야 해요.
  5. YG##_D_GENRE Domain의 고정값에 N, I, E만 있기 때문이에요.
정리
  • 오래 보관할 데이터는 DB Table에 저장하고, 그 설계도는 SE11(ABAP Dictionary)에서 만들어요.
  • Domain은 기술 규칙, Data Element는 의미와 이름표, Table Field는 실제 칸이에요. 만드는 순서도 이 순서예요.
  • Domain 하나를 여러 Data Element가 다시 쓸 수 있어요. 정해진 값만 받으려면 Domain의 고정값을 써요.
  • Table에는 MANDT를 첫 Key로 넣고, Key는 한 줄을 콕 집어낼 수 있는 칸만 체크해요.
  • 데이터는 Utilities → Table Contents → Create Entries로 넣고, SE16N으로 조회해요.
다음 장 예고

Table에 도서 다섯 권이 들어갔어요. 이 데이터를 프로그램으로 가져오면 여러 줄이 한꺼번에 와요. 8장에서는 여러 줄 데이터를 메모리에 담는 그릇, Internal Table을 배워요.
