8장

Structure와 Internal Table

이번 장 목표
  • 여러 칸을 한 묶음으로 다루는 Structure를 만들고 쓸 수 있어요.
  • 여러 줄을 메모리에 담는 Internal Table과, 한 줄을 다루는 Work Area의 관계를 그림으로 설명할 수 있어요.
  • APPEND, LOOP AT, READ TABLE, MODIFY, DELETE, SORT로 Internal Table을 다룰 수 있어요.
  • sy-subrc로 성공했는지 확인하고, sy-tabix로 몇 번째 줄인지 알 수 있어요.
  • 복사본이 아니라 표의 줄을 바로 고치는 Field Symbol을 읽고 쓸 수 있어요.

8-1. 여러 칸을 한 묶음으로: Structure

도서 한 권에는 번호, 제목, 장르, 가격, 재고 같은 정보가 있어요. 3장 방식대로라면 변수를 다섯 개 따로 만들어야 하죠. Structure를 쓰면 이 칸들을 한 묶음으로 다룰 수 있어요. (7장 Table에 있던 저자는 예제를 짧게 하려고 뺐어요.)

이 장에서는 프로그램 하나를 만들어 놓고, 8-7까지 절마다 코드를 조금씩 이어 써요. 이어 쓰다 막히면 8-7 끝에 있는 전체 코드와 견줘 보세요. 먼저 아래 카드대로 프로그램을 만들고 코드를 써요.

새로 만들기ProgramSE38
Program
YG##_127
Title
[예제] Internal Table 따라 하기
REPORT yg##_127.

TYPES: BEGIN OF ty_book,             " 설계도 시작
         book_id TYPE c LENGTH 5,
         title   TYPE c LENGTH 40,
         genre   TYPE c LENGTH 1,
         price   TYPE p LENGTH 8 DECIMALS 0,
         stock   TYPE i,
       END OF ty_book.               " 설계도 끝

DATA gs_book TYPE ty_book.               " 설계도로 만든 Structure 변수

START-OF-SELECTION.
  " 8-1. Structure에 값을 넣고 출력하기
  gs_book-book_id = 'B0001'.
  gs_book-title   = 'ABAP 첫걸음'.
  gs_book-genre   = 'I'.
  gs_book-price   = 25000.
  gs_book-stock   = 3.

  WRITE: / gs_book-book_id, gs_book-title, gs_book-price.
  • TYPES: BEGIN OF 이름, … END OF 이름. 사이에 칸(Component)을 나열해요. 3장의 TYPES처럼 설계도예요. 7장 Table에서는 칸을 Field라고 불렀죠. Structure에서는 Component라고도 부르는데, 같은 "칸"이에요.
  • TYPES:부터 END OF ty_book.까지가 쉼표로 이어 쓴 한 문장이에요(2장의 체인 문장). 그래서 칸마다 쉼표를 찍고, 마침표는 맨 끝에만 찍어요.
  • 실제 변수는 DATA gs_book TYPE ty_book.처럼 만들어요. 이름 앞 gs_는 Global Structure예요.
  • 칸 하나에 값을 넣거나 꺼낼 땐 하이픈(-)을 써요.

활성화하고 실행하면 한 줄이 나와요.

B0001 ABAP 첫걸음   25,000

제목 칸이 40칸이라서 실제 화면에서는 제목과 가격 사이가 넓게 벌어져요. 틀린 게 아니에요. 이 장의 실행 결과는 칸 사이 빈칸을 줄여서 적었어요.

자주 하는 실수
  • gs_book-title의 하이픈 앞뒤를 띄우면 안 돼요. gs_book - title은 "빼기"로 읽혀서 오류가 나요. 3장의 "연산자는 띄어 쓰기"와 반대라서 헷갈리기 쉬워요.
  • 하이픈은 Structure의 칸, 밑줄 _은 이름의 일부예요. gs_book의 _와 -title의 -를 구분해요.
7장의 Table을 설계도로 쓰기

7장에서 만든 Table YTA_G##_BOOK도 Structure 설계도로 쓸 수 있어요. TYPES를 따로 쓰지 않아도 Table과 똑같은 칸을 가진 변수가 만들어져요.

DATA gs_book TYPE yta_g##_book.     " MANDT, BOOK_ID, TITLE, … 칸이 모두 생겨요

칸 하나의 Type만 빌려 올 수도 있어요. TYPES 안에서 title TYPE yde_g##_title,처럼 7장의 Data Element를 적으면 돼요. 두 방법 모두 9장에서 DB 데이터를 읽어 올 때 많이 써요. 지금은 눈으로만 봐요. YG##_127에 위 줄을 넣으면 gs_book을 두 번 선언하게 되어 문법 오류가 나요.

Structure끼리 옮기기

Structure는 칸을 하나씩 옮기지 않고 통째로 옮길 수 있어요. 아래는 눈으로만 보는 조각이에요(YG##_127에는 넣지 않아요).

DATA: gs_copy TYPE ty_book,           " gs_book과 모양이 같아요
      gs_db   TYPE yta_g##_book.      " 7장 Table 모양. 칸이 더 많아요

gs_copy = gs_book.                    " 모양이 같으면 = 로 통째로
MOVE-CORRESPONDING gs_book TO gs_db.  " 모양이 다르면 이름이 같은 칸끼리
  • 두 Structure의 모양(칸의 순서와 Type)이 같으면 = 하나로 모든 칸이 옮겨 가요.
  • 모양이 다르면 MOVE-CORRESPONDING 보내는 쪽 TO 받는 쪽.을 써요. 이름이 같은 칸끼리만 옮겨요. 위에서는 book_id부터 stock까지 다섯 칸이 옮겨 가고, gs_db에만 있는 mandt와 author는 원래 값 그대로예요.
자주 하는 실수

모양이 다른 Structure끼리 =를 쓰면 값이 엉뚱한 칸으로 밀려 들어가거나 문법 오류가 나요. 모양이 다르면 MOVE-CORRESPONDING을 써요.

이렇게도 써요

요즘 코드에서는 이렇게 써요. 읽을 줄만 알면 돼요.

gs_db = CORRESPONDING #( gs_book ).   " 이름이 같은 칸끼리. 안 맞는 칸은 비워져요

"이름이 같은 칸끼리"라는 생각은 9-3의 INTO CORRESPONDING FIELDS OF에서 다시 만나요.

8-2. 여러 줄을 담는 그릇: Internal Table

Structure가 한 줄이라면, Internal Table은 같은 모양의 줄을 여러 개 담는 표예요. 엑셀 시트 하나를 메모리에 올려 둔 것이라고 생각하면 쉬워요. JavaScript로 치면 Structure는 객체 하나, Internal Table은 객체 배열이에요(8-5 끝에서 표로 견줘 봐요).

YG##_127의 DATA gs_book TYPE ty_book. 바로 아래에 한 줄을 더해요.

DATA gt_book TYPE TABLE OF ty_book.      " 여러 줄을 담는 Internal Table
  • TYPE TABLE OF ty_book은 "ty_book 모양의 줄을 여러 개 담는 표"라는 뜻이에요. 윗줄 gs_book과의 차이는 TABLE OF뿐이에요. 없으면 한 줄짜리 Structure, 있으면 Internal Table이에요.
  • 이름 앞 gt_는 Global Internal Table이에요.
  • 이 장에서 배우는 APPEND, LOOP AT, READ TABLE은 줄을 한 줄씩 넣고 꺼내요. 그 한 줄을 담아 두는 Structure 변수를 Work Area(작업 공간)라고 불러요. 표와 같은 설계도로 만들어서 짝으로 써요. 8-1에서 만든 gs_book이 이제부터 Work Area예요. (여러 줄을 한꺼번에 채우는 방법은 9장에서 배워요.)
자주 하는 실수

TABLE OF를 빼먹고 DATA gt_book TYPE ty_book.이라고 쓰면 gt_book도 한 줄짜리 Structure가 돼요. 그러면 8-3의 APPEND 줄에서 "Internal Table이 아니에요(not an internal table)"라는 문법 오류가 나요. 오류는 APPEND 줄에 뜨지만 고칠 곳은 위쪽 DATA 줄이에요.

그림은 8-3까지 따라 했을 때의 모습이에요. 왼쪽 #는 줄 번호예요. 8-4의 sy-tabix와 8-5의 INDEX가 이 번호를 써요.

Internal Table ≠ DB Table

이름이 비슷해서 가장 많이 헷갈리는 부분이에요. DB Table(7장)은 데이터베이스에 저장되어 프로그램이 끝나도 남아요. Internal Table은 프로그램이 실행되는 동안만 메모리에 있다가 끝나면 사라져요. 9장에서는 DB Table의 데이터를 Internal Table로 복사해 와서 다뤄요.

Internal Table에는 세 종류가 있어요
  • Standard Table: 우리가 쓰는 종류예요. 넣은 순서대로 줄이 쌓이고, 줄 번호로 꺼낼 수 있어요.
  • Sorted Table, Hashed Table: 줄이 아주 많을 때 빨리 찾으려고 쓰는 종류예요. 지금은 이름만 알아 둬요.

DATA gt_book TYPE TABLE OF ty_book.은 DATA gt_book TYPE STANDARD TABLE OF ty_book WITH DEFAULT KEY.를 줄여 쓴 거예요. 10장부터 이 긴 모양이 나와요.

8-3. 줄 넣기: APPEND

Work Area에 값을 채운 다음 APPEND로 Internal Table 맨 뒤에 한 줄을 붙여요. 8-1에서 gs_book에 B0001을 채워 뒀으니, 그 줄부터 넣어요.

지금부터 " 8-3.처럼 절 번호 주석으로 시작하는 코드는 모두 프로그램 맨 아래에 차례로 이어 써요. START-OF-SELECTION. 아래라서 두 칸 들여 써요. 절 번호 주석이 없는 코드는 맨 아래에 넣지 않아요. 눈으로만 보는 코드이거나, 넣을 자리를 따로 알려 주는 코드예요.

  " 8-3. 줄 넣기: APPEND
  APPEND gs_book TO gt_book.          " 1번 줄: 8-1에서 채운 B0001

  CLEAR gs_book.
  gs_book-book_id = 'B0002'.
  gs_book-title   = '바다의 노래'.
  gs_book-genre   = 'N'.
  gs_book-price   = 15000.
  APPEND gs_book TO gt_book.          " 2번 줄이 생겨요 (stock은 0)

  CLEAR gs_book.
  gs_book-book_id = 'B0003'.
  gs_book-title   = '오늘의 산책'.
  gs_book-genre   = 'E'.
  gs_book-price   = 13000.
  gs_book-stock   = 5.
  APPEND gs_book TO gt_book.          " 3번 줄이 생겨요

  CLEAR gs_book.
  gs_book-book_id = 'B0004'.
  gs_book-title   = 'SQL 한 그릇'.
  gs_book-genre   = 'I'.
  gs_book-price   = 28000.
  gs_book-stock   = 2.
  APPEND gs_book TO gt_book.          " 4번 줄이 생겨요
자주 하는 실수

줄을 새로 채우기 전에 CLEAR gs_book.을 해요. 3-2에서 본 CLEAR예요. Structure에 쓰면 모든 칸이 한꺼번에 비워져요. 위 코드에서 두 번째 책은 재고가 0이라서 stock을 넣지 않았어요. CLEAR를 빼먹으면 첫 번째 책의 재고 3이 Work Area에 그대로 남아서 두 번째 줄에도 3이 들어가 버려요.

여기까지 쓰고 실행해 보세요. 화면은 8-1 때와 똑같이 한 줄이에요. 고장이 아니에요. APPEND는 화면에 아무것도 쓰지 않거든요. 네 줄이 잘 들어갔는지는 8-4에서 꺼내 보면서 확인해요.

8-4. 한 줄씩 꺼내 보기: LOOP AT

LOOP AT … INTO …는 Internal Table의 줄을 처음부터 끝까지 한 줄씩 Work Area에 꺼내 주는 반복문이에요.

  " 8-4. 한 줄씩 꺼내 보기: LOOP AT
  SKIP.                               " 빈 줄 하나 (4-9)
  LOOP AT gt_book INTO gs_book.
    WRITE: / sy-tabix, gs_book-book_id, gs_book-title, gs_book-price.
  ENDLOOP.

실행하면 8-1의 한 줄 아래에 빈 줄이 하나 생기고, 네 줄이 새로 나와요.

1 B0001 ABAP 첫걸음   25,000
2 B0002 바다의 노래   15,000
3 B0003 오늘의 산책   13,000
4 B0004 SQL 한 그릇   28,000

앞으로 결과 상자에는 그때 새로 나오는 줄만 적을게요. 앞에서 나온 줄은 화면 위쪽에 그대로 있어요.

  • 한 바퀴 돌 때마다 다음 줄이 gs_book에 들어와요.
  • sy-tabix에는 지금 꺼낸 줄이 몇 번째 줄인지 들어 있어요. 4장 DO의 sy-index와 비슷한 역할이에요.
  • LOOP AT 안에서는 sy-index가 아니라 꼭 sy-tabix를 써요. sy-index는 DO와 WHILE에서만 바뀌어요.
  • LOOP가 넣어 준 sy-tabix는 ENDLOOP 전까지만 믿어요. ENDLOOP를 지나면 LOOP 전의 값으로 돌아가요. 줄 수가 아니에요(우연히 같을 때도 있어요). 줄 수를 세는 방법은 8-6에서 배워요.
  • 실제 화면에서는 줄 번호 앞에도 빈칸이 길게 나와요. 3장에서 본 "숫자 앞 공백"이에요.

조건에 맞는 줄만: WHERE

LOOP AT 끝에 WHERE를 붙이면 조건에 맞는 줄만 꺼내요.

  " 8-4. 조건에 맞는 줄만: WHERE
  SKIP.
  LOOP AT gt_book INTO gs_book WHERE genre = 'I'.   " IT 책만
    WRITE: / gs_book-title.
  ENDLOOP.

실행하면 IT 책 두 권의 제목이 새로 나와요.

ABAP 첫걸음
SQL 한 그릇
  • WHERE 뒤에는 칸 이름만 써요. gs_book-genre가 아니라 genre예요.
  • 조건에 맞는 줄이 없으면 LOOP 안쪽이 한 번도 실행되지 않고 지나가요. 오류가 아니에요.
  • 이때 sy-tabix는 걸러 낸 순서가 아니라 표 안에서의 원래 줄 번호(여기서는 1과 4)예요.
자주 하는 실수

LOOP 안에서 gs_book-stock = 10.처럼 Work Area를 바꿔도 Internal Table은 그대로예요. Work Area는 꺼내 온 복사본이기 때문이에요. 표 안의 값을 바꾸려면 8-6의 MODIFY를 써야 해요.

직접 해 보기 · 디버거로 Internal Table 들여다보기

6장에서 배운 디버거를 표에 처음 써 보는 자리예요.

  1. 첫 번째 LOOP AT gt_book INTO gs_book. 줄에 Breakpoint를 걸고 F8로 실행해요(6-3).
  2. 디버거가 멈추면 소스 코드에서 gt_book을 더블클릭해 변수 목록에 올려요. 변수 목록의 GT_BOOK을 다시 더블클릭하면 표 모양으로 네 줄이 보여요.
  3. 원래 화면(Desktop 1 탭)으로 돌아와서, 변수 목록의 빈칸에 gs_book-book_id와 sy-tabix를 적어 넣어요(6-4).
  4. F5를 한 번씩 눌러요. 한 바퀴 돌 때마다 GS_BOOK-BOOK_ID가 B0001, B0002 순서로 바뀌고 SY-TABIX가 1, 2, 3, 4로 늘어요. (처음 멈췄을 때는 아직 LOOP가 돌기 전이라, 8-3에서 마지막으로 넣은 B0004와 그때의 줄 번호 4가 보여요. APPEND도 방금 넣은 줄 번호를 sy-tabix에 남기거든요.)

디버거 화면은 버전에 따라 조금 달라요. 다 봤으면 F8로 끝까지 실행하고 Breakpoint를 지워요.

8-5. 한 줄만 콕 집기: READ TABLE

반복하지 않고 딱 한 줄만 필요할 땐 READ TABLE을 써요.

  " 8-5. 한 줄만 콕 집기: READ TABLE
  SKIP.
  READ TABLE gt_book INTO gs_book WITH KEY book_id = 'B0003'.
  IF sy-subrc = 0.
    WRITE: /(1) sy-tabix, '번째 줄에서 찾았어요:', gs_book-title.
  ELSE.
    WRITE: / '그런 책은 없어요'.
  ENDIF.

실행하면 맨 아래에 한 줄이 새로 나와요.

3 번째 줄에서 찾았어요: 오늘의 산책
  • WITH KEY 칸 = 값으로 찾을 줄을 정해요. 위에서부터 찾다가 처음 맞는 한 줄만 가져와요.
  • 몇 번째 줄인지 알면 READ TABLE gt_book INTO gs_book INDEX 2.처럼 INDEX로 바로 꺼낼 수도 있어요.
  • 찾았는지는 sy-subrc로 확인해요. 0이면 찾은 거예요. 찾았으면 그 줄이 몇 번째인지가 sy-tabix에 들어 있어요.
  • /(1) sy-tabix는 줄 번호를 한 칸에 출력해요(4-9). 그래서 숫자 앞에 긴 빈칸이 없어요.

'B0003'을 없는 번호 'B0009'로 바꿔서 실행해 보세요. 그런 책은 없어요가 나와요. 확인했으면 'B0003'으로 되돌려 놓아요.

sy-subrc는 "방금 한 일"의 성적표예요

READ TABLE, MODIFY, DELETE, 9장의 SELECT처럼 성공·실패가 있는 문장은 실행된 직후에 sy-subrc를 바꿔요. 그래서 확인은 바로 다음 줄에서 해요. 다른 문장을 하나 더 실행한 뒤에 보면 그 문장의 결과로 바뀌어 있을 수 있어요.

못 찾았을 때 Work Area는 비워지지 않고 앞에서 꺼낸 값 그대로 남아 있어요. 그래서 gs_book은 IF sy-subrc = 0. 안에서만 써요.

옛 코드의 BINARY SEARCH

회사 코드에서는 READ TABLE 끝에 BINARY SEARCH가 붙은 모양을 자주 봐요. 줄이 아주 많을 때 빨리 찾으려고 쓰는 옵션이에요.

SORT gt_book BY book_id.
READ TABLE gt_book INTO gs_book WITH KEY book_id = 'B0003' BINARY SEARCH.

찾는 칸으로 먼저 정렬되어 있어야 해요(정렬하는 SORT는 8-6에서 배워요). 정렬하지 않은 표에 쓰면 오류 없이 있는 줄을 못 찾을 수 있어요. 지금은 읽을 줄만 알면 돼요.

JavaScript로 치면

ABAP JavaScript

Internal Table gt_book 객체 배열 [ {…}, {…} ]
APPEND gs_book TO gt_book. aBooks.push(oBook)
LOOP AT gt_book INTO gs_book. for (const oBook of aBooks) { … }
READ TABLE … WITH KEY 뒤에 sy-subrc 확인 aBooks.find(…) 뒤에 undefined 확인

다른 점이 두 가지 있어요. 줄 번호는 0이 아니라 1부터 세요(sy-tabix). 그리고 Work Area는 복사본이라서, 꺼낸 줄을 고쳐도 표는 그대로예요(8-4). 표까지 바꾸는 방법은 8-6에서, JavaScript처럼 그 줄 자체를 고치는 방법은 8-7에서 배워요.

8-6. 고치기 · 지우기 · 정렬하기

고치기: MODIFY

LOOP 안에서 Work Area를 고친 뒤 MODIFY를 쓰면 지금 줄이 바뀌어요.

  " 8-6. 고치기: MODIFY
  LOOP AT gt_book INTO gs_book WHERE genre = 'N'.
    gs_book-price = gs_book-price - 1000.   " 소설은 1000원 할인
    MODIFY gt_book FROM gs_book.            " 지금 줄에 반영
  ENDLOOP.

LOOP 안에서는 MODIFY gt_book FROM gs_book.만 써도 지금 돌고 있는 줄이 바뀌어요. MODIFY gt_book FROM gs_book INDEX sy-tabix.처럼 줄 번호를 붙여도 같은 뜻이에요(12장에서는 이렇게 써요).

LOOP 밖에서는 몇 번째 줄을 바꿀지 알려 줘야 해요. 보통 READ TABLE로 찾고, 그때 생긴 sy-tabix를 써요.

  " 8-6. 한 줄만 찾아서 고치기
  READ TABLE gt_book INTO gs_book WITH KEY book_id = 'B0004'.
  IF sy-subrc = 0.
    gs_book-stock = gs_book-stock + 10.     " 10권이 새로 들어왔어요
    MODIFY gt_book FROM gs_book INDEX sy-tabix.
  ENDIF.
자주 하는 실수
  • LOOP 밖에서 INDEX 없이 MODIFY gt_book FROM gs_book.만 쓰면 어느 줄인지 알 수 없어서, 실행 도중에 덤프(6-8)로 멈춰요.
  • IF sy-subrc = 0.을 빼먹지 마세요. 못 찾았을 때는 고칠 줄이 없어요.

MODIFY, DELETE, SORT는 화면에 아무것도 쓰지 않아요. 바뀐 것을 눈으로 보려면 LOOP로 한 번 더 출력해요. 이번에는 재고도 같이 찍어요. 줄이 길어지니까 줄 번호는 8-5처럼 /(1)로 한 칸에 찍어요.

  " 8-6. 고친 표 다시 출력하기
  SKIP.
  LOOP AT gt_book INTO gs_book.
    WRITE: /(1) sy-tabix, gs_book-book_id, gs_book-title,
            gs_book-price, gs_book-stock.
  ENDLOOP.

여기까지 넣고 실행하면 아래 네 줄이 새로 나와요.

1 B0001 ABAP 첫걸음            25,000   3
2 B0002 바다의 노래            14,000   0
3 B0003 오늘의 산책            13,000   5
4 B0004 SQL 한 그릇            28,000  12

B0002의 가격이 14,000으로, B0004의 재고가 12로 바뀌었어요.

지우기: DELETE

필요 없는 줄은 DELETE로 표에서 지워요.

  " 8-6. 지우기: DELETE
  DELETE gt_book WHERE stock = 0.     " 재고 없는 책 모두 지우기
  • DELETE 표 WHERE 조건.은 조건에 맞는 줄을 모두 지워요. 여기서는 B0002 한 줄이 빠져서 세 줄이 남아요.
  • 한 줄만 지울 때는 DELETE gt_book INDEX 1.처럼 줄 번호를 적어요(이번에는 넣지 않아요).
  • 줄을 지우면 뒤에 있던 줄이 앞으로 당겨져요. 2번 줄을 지웠으니 3번 줄이 2번이 돼요.

정렬하기: SORT

줄의 순서는 SORT로 바꿔요.

  " 8-6. 정렬하기: SORT
  SORT gt_book BY price DESCENDING.   " 비싼 순서

DESCENDING(내림차순)을 쓰지 않으면 ASCENDING(오름차순)이에요. SORT gt_book BY genre price.처럼 칸을 여러 개 적으면 장르별로, 같은 장르 안에서는 싼 순서로 정렬돼요. 정렬하면 줄 번호도 새 순서대로 다시 매겨져요.

몇 줄인지 세기 · 비우기

줄 수를 담을 변수가 하나 필요해요. 선언은 START-OF-SELECTION. 위에 모아 두니까, gt_book 선언 바로 아래에 한 줄을 더해요.

DATA gv_lines TYPE i.                    " 줄 수를 담을 변수

그리고 프로그램 맨 아래에 이어 써요.

  " 8-6. 줄 수 세기
  DESCRIBE TABLE gt_book LINES gv_lines.

  SKIP.
  LOOP AT gt_book INTO gs_book.
    WRITE: /(1) sy-tabix, gs_book-book_id, gs_book-title,
            gs_book-price, gs_book-stock.
  ENDLOOP.
  WRITE: / '책 수:', gv_lines.

실행하면 맨 아래에 이렇게 나와요.

2 B0001 ABAP 첫걸음            25,000   3
3 B0003 오늘의 산책            13,000   5
책 수: 3

재고가 0이던 B0002가 사라졌고, 비싼 책부터 나와요.

  • DESCRIBE TABLE 표 LINES 변수.는 표의 줄 수를 세어서 변수에 넣어 줘요. =이 없어서 낯설지만 "gt_book의 줄 수(LINES)를 gv_lines에 알려 줘"라고 읽으면 돼요.
  • 표를 통째로 비울 때는 CLEAR gt_book.을 써요. 모든 줄이 사라져요. Work Area를 비우는 CLEAR gs_book.과 한 글자 차이니 조심해요. 지금은 넣지 않아요. 8-7에서 표를 더 쓸 거예요.
이렇게도 써요

gt_book = VALUE #( ( book_id = 'B0001' title = 'ABAP 첫걸음' price = 25000 )
                   ( book_id = 'B0002' title = '바다의 노래' price = 15000 ) ).

옛 코드의 Header Line

오래된 프로그램에는 DATA gt_book TYPE … OCCURS 0 WITH HEADER LINE. 같은 코드가 있어요. 8-7. 복사본이 아니라 그 줄 자체: Field Symbol

8-4에서 "Work Area는 복사본이라 고치려면 MODIFY가 필요해요"라고 했죠. 반대로 표 안의 그 줄 자체에 이름표를 붙여서 바로 고치는 방법이 있어요. 그 이름표가 Field Symbol이에요. 그림 8-2의 Work Area처럼 표 밖에 따로 있는 상자가 아니에요.

먼저 gv_lines 선언 바로 아래에 한 줄을 더해요.

FIELD-SYMBOLS <gs_book> TYPE ty_book.    " 꺾쇠 < > 까지가 이름이에요

IT 책이 한 권씩 팔려서 재고를 1 줄인다고 해 볼게요. 아래 두 코드는 견줘 보기만 해요(프로그램에는 넣지 않아요). 첫 번째는 8-6에서 배운 방식, 두 번째는 Field Symbol이에요.

" Work Area: 복사본을 고치고 MODIFY
LOOP AT gt_book INTO gs_book
     WHERE genre = 'I'.
  gs_book-stock = gs_book-stock - 1.
  MODIFY gt_book FROM gs_book.
ENDLOOP.
" Field Symbol: 그 줄을 바로 고쳐요
LOOP AT gt_book ASSIGNING <gs_book>
     WHERE genre = 'I'.
  <gs_book>-stock = <gs_book>-stock - 1.
ENDLOOP.

INTO gs_book 자리에 ASSIGNING <gs_book>을 썼어요. 한 바퀴 돌 때마다 <gs_book>이 그 줄을 가리켜요. 복사하지 않으니 <gs_book>-stock을 바꾸면 표가 바로 바뀌고, MODIFY가 필요 없어요. JavaScript의 for (const oBook of aBooks) 안에서 oBook.stock을 바꾸면 배열 안의 책이 바로 바뀌던 것과 같아요.

이제 프로그램 맨 아래에 아래 코드를 이어 써요. 두 번째 방식의 LOOP에, 같은 방법으로 한 줄만 찾아 고치는 READ TABLE과 출력을 더했어요.

  " 8-7. Field Symbol로 바로 고치기
  LOOP AT gt_book ASSIGNING <gs_book> WHERE genre = 'I'.
    <gs_book>-stock = <gs_book>-stock - 1.   " MODIFY 없이 바로 바뀌어요
  ENDLOOP.

  READ TABLE gt_book ASSIGNING <gs_book> WITH KEY book_id = 'B0003'.
  IF sy-subrc = 0.                           " 찾았을 때만 써요
    <gs_book>-title = '오늘의 산책 (개정판)'.
  ENDIF.

  SKIP.
  LOOP AT gt_book INTO gs_book.
    WRITE: /(1) sy-tabix, gs_book-book_id, gs_book-title,
            gs_book-price, gs_book-stock.
  ENDLOOP.

실행하면 맨 아래에 세 줄이 새로 나와요.

1 B0004 SQL 한 그릇            28,000  11
2 B0001 ABAP 첫걸음            25,000   2
3 B0003 오늘의 산책 (개정판)   13,000   5

IT 책 두 권의 재고가 1씩 줄고(12 → 11, 3 → 2), B0003의 제목이 바뀌었어요. MODIFY는 한 번도 쓰지 않았어요.

자주 하는 실수
  • READ TABLE … ASSIGNING이 줄을 못 찾아도(sy-subrc가 0이 아니어도) <gs_book>은 비워지지 않아요. 앞에서 가리키던 줄을 그대로 가리켜요. 위 코드라면 바로 앞 LOOP가 마지막으로 돌았던 줄, 곧 IT 책 가운데 뒤쪽인 B0001 줄이에요. 그 상태로 <gs_book>-title을 고치면 오류도 없이 엉뚱한 줄이 고쳐져요.
  • 한 번도 줄을 가리킨 적이 없는 Field Symbol을 쓰면 덤프(GETWA_NOT_ASSIGNED)로 멈춰요. 덤프는 6-8에서 배웠죠.

그래서 sy-subrc를 꼭 확인하고, <gs_book>은 IF sy-subrc = 0. 안에서만 써요.

이렇게도 써요

요즘 코드에서는 FIELD-SYMBOLS 줄을 따로 쓰지 않고, 쓰는 자리에서 바로 만들어요. 이 교재에서는 그 자리에서 만든 것의 이름 앞에 8-6의 ls_book처럼 ls_를 붙여요. Field Symbol이면 <ls_…>예요(이름 규칙은 부록 F).

LOOP AT gt_book ASSIGNING FIELD-SYMBOL(<ls_book>).
  <ls_book>-stock = <ls_book>-stock + 1.
ENDLOOP.

선언할 때는 FIELD-SYMBOLS(끝에 S), 그 자리에서 만들 때는 FIELD-SYMBOL( )(S 없음)이에요. 회사 코드에서는 <fs_book>처럼 <fs_…>로 시작하는 이름도 흔해요. 꺾쇠가 붙어 있으면 Field Symbol이라고 읽으면 돼요.

DB 없이 코드에서 직접 데이터를 넣어요. 코드는 TYPES → DATA → START-OF-SELECTION. 순서로 써요.

  1. YG##_127과 똑같은 ty_book(칸 다섯 개, title은 40칸)을 만들고, 그 설계도로 Internal Table과 Work Area를 만들어요.
  2. 아래 표의 다섯 권을 APPEND로 넣어요. 7-7에서 넣은 데이터에서 저자만 뺀 거예요.
  3. B0004를 READ TABLE로 찾아 재고를 10 늘리고 MODIFY해요.
  4. 재고가 0인 책을 DELETE해요.
  5. 가격이 비싼 순서로 SORT하고, 줄 번호(sy-tabix), 도서 번호, 제목, 가격, 재고를 출력해요. 줄 번호는 8-6처럼 /(1)로 한 칸에 찍어요.
  6. 마지막에 남은 책 수를 출력해요(8-6의 DESCRIBE TABLE).
  7. (더 해 보기) 3번을 Field Symbol로 바꿔 봐요. FIELD-SYMBOLS <gs_book> TYPE ty_book.을 선언하고 READ TABLE … ASSIGNING <gs_book>으로 찾으면, MODIFY 없이도 결과가 같아요(8-7).
book_id title genre price stock
B0001 ABAP 첫걸음 I 25000 3
B0002 바다의 노래 N 15000 0
B0003 오늘의 산책 E 13000 5
B0004 SQL 한 그릇 I 28000 2
B0005 별을 세는 밤 N 17000 7

이 그림은 칸 사이 빈칸을 줄이지 않고 그렸어요. 제목이 40칸이라 가격이 멀리 떨어져 있어요. 좁은 화면에서는 그림을 옆으로 밀면 가격과 재고가 보여요. WRITE를 어떻게 썼는지에 따라 빈칸 수는 달라져요. 책의 순서와 값이 같으면 맞게 한 거예요.

예시 답안 보기
REPORT yg##_128.

" 1. 설계도와 변수 (ty_book은 YG##_127과 같아요)
TYPES: BEGIN OF ty_book,
         book_id TYPE c LENGTH 5,
         title   TYPE c LENGTH 40,
         genre   TYPE c LENGTH 1,
         price   TYPE p LENGTH 8 DECIMALS 0,
         stock   TYPE i,
       END OF ty_book.

DATA: gt_book  TYPE TABLE OF ty_book,
      gs_book  TYPE ty_book,
      gv_lines TYPE i.

START-OF-SELECTION.
  " 2. 다섯 권 넣기 (짧은 문장은 한 줄에 여러 개 써도 돼요)
  CLEAR gs_book.
  gs_book-book_id = 'B0001'. gs_book-title = 'ABAP 첫걸음'.
  gs_book-genre = 'I'. gs_book-price = 25000. gs_book-stock = 3.
  APPEND gs_book TO gt_book.

  CLEAR gs_book.
  gs_book-book_id = 'B0002'. gs_book-title = '바다의 노래'.
  gs_book-genre = 'N'. gs_book-price = 15000. gs_book-stock = 0.
  APPEND gs_book TO gt_book.

  CLEAR gs_book.
  gs_book-book_id = 'B0003'. gs_book-title = '오늘의 산책'.
  gs_book-genre = 'E'. gs_book-price = 13000. gs_book-stock = 5.
  APPEND gs_book TO gt_book.

  CLEAR gs_book.
  gs_book-book_id = 'B0004'. gs_book-title = 'SQL 한 그릇'.
  gs_book-genre = 'I'. gs_book-price = 28000. gs_book-stock = 2.
  APPEND gs_book TO gt_book.

  CLEAR gs_book.
  gs_book-book_id = 'B0005'. gs_book-title = '별을 세는 밤'.
  gs_book-genre = 'N'. gs_book-price = 17000. gs_book-stock = 7.
  APPEND gs_book TO gt_book.

  " 3. B0004 재고 10 늘리기
  READ TABLE gt_book INTO gs_book WITH KEY book_id = 'B0004'.
  IF sy-subrc = 0.
    gs_book-stock = gs_book-stock + 10.
    MODIFY gt_book FROM gs_book INDEX sy-tabix.
  ENDIF.

  " 4. 재고 0인 책 지우기
  DELETE gt_book WHERE stock = 0.

  " 5. 비싼 순서로 정렬하고 출력. (1)과 (3)은 칸 수 지정이에요 (4-9)
  SORT gt_book BY price DESCENDING.
  LOOP AT gt_book INTO gs_book.
    WRITE: /(1) sy-tabix, gs_book-book_id, gs_book-title,
            gs_book-price, (3) gs_book-stock.
  ENDLOOP.

  " 6. 남은 책 수
  DESCRIBE TABLE gt_book LINES gv_lines.
  WRITE: / '남은 책:', gv_lines.

7번은 DATA 문장 아래에 FIELD-SYMBOLS <gs_book> TYPE ty_book. 한 줄을 더하고, 3번 부분을 이렇게 바꿔요. 결과는 같아요.

  " 3. B0004 재고 10 늘리기 (Field Symbol)
  READ TABLE gt_book ASSIGNING <gs_book> WITH KEY book_id = 'B0004'.
  IF sy-subrc = 0.
    <gs_book>-stock = <gs_book>-stock + 10.   " MODIFY가 필요 없어요
  ENDIF.
확인 문제
  1. Structure와 Internal Table의 차이를 "줄"이라는 말로 설명해 보세요.
  2. LOOP AT gt_book INTO gs_book. 안에서 gs_book-price = 0.만 하고 끝냈어요. Internal Table의 가격도 0이 될까요?
  3. READ TABLE 바로 다음에 확인해야 하는 시스템 필드는 무엇이고, 값이 0이면 무슨 뜻일까요?
  4. APPEND 전에 CLEAR gs_book.을 하지 않으면 어떤 일이 생길 수 있을까요?
  5. Internal Table과 DB Table은 무엇이 다를까요?
  6. LOOP AT gt_book ASSIGNING <gs_book>. 안에서 <gs_book>-price = 0.만 하고 끝냈어요. 이번에는 Internal Table의 가격이 0이 될까요? 2번과 왜 다를까요?
  7. 6번의 LOOP가 끝난 바로 뒤에 READ TABLE gt_book ASSIGNING <gs_book> WITH KEY book_id = 'B0009'.를 실행했는데 그런 책이 없었어요. sy-subrc를 확인하지 않고 <gs_book>-stock = 0.을 하면 어떻게 될까요?
  8. MOVE-CORRESPONDING gs_a TO gs_b.는 어떤 칸을 옮길까요?
정답 보기
  1. Structure는 칸이 여러 개인 한 줄, Internal Table은 같은 모양의 줄을 여러 개 담는 표예요.
  2. 아니요, 그대로예요. Work Area는 복사본이라서 MODIFY gt_book FROM gs_book.을 해야 표에 반영돼요.
  3. sy-subrc예요. 0이면 찾았다(성공)는 뜻이에요.
  4. 이전 줄의 값이 Work Area에 남아서, 이번에 채우지 않은 칸에 이전 값이 그대로 들어갈 수 있어요.
  5. DB Table은 데이터베이스에 저장되어 계속 남고, Internal Table은 프로그램이 도는 동안 메모리에만 있다가 사라져요.
  6. 네, 0이 돼요. Field Symbol은 복사본이 아니라 표 안의 그 줄 자체를 가리키기 때문이에요. MODIFY가 필요 없어요.
  7. 오류 없이 엉뚱한 줄(표의 마지막 줄)의 재고가 0이 돼요. 못 찾아도 <gs_book>은 LOOP가 마지막으로 돌았던 줄을 그대로 가리키기 때문이에요. 그래서 <gs_book>은 IF sy-subrc = 0. 안에서만 써요.
  8. 두 Structure에서 이름이 같은 칸끼리만 옮겨요. 이름이 안 맞는 칸은 건드리지 않아요.
정리
  • Structure는 칸이 여러 개인 한 줄이에요. 칸은 gs_book-title처럼 하이픈으로 꺼내요.
  • 모양이 같은 Structure는 =로, 모양이 다르면 MOVE-CORRESPONDING으로 이름이 같은 칸끼리 옮겨요.
  • Internal Table은 여러 줄을 담는 메모리 속 표이고, 한 줄을 다루는 Work Area와 짝으로 써요. 프로그램이 끝나면 사라져서, 계속 남는 DB Table과 달라요.
  • 넣기는 APPEND, 전체 돌기는 LOOP AT … INTO, 한 줄 찾기는 READ TABLE, 고치기는 MODIFY, 지우기는 DELETE, 정렬은 SORT, 줄 수 세기는 DESCRIBE TABLE … LINES예요.
  • sy-tabix는 몇 번째 줄인지, sy-subrc는 방금 한 일이 성공(0)했는지 알려 줘요.
  • 새 줄을 채우기 전에는 CLEAR로 Work Area를 비워요.
  • Work Area는 복사본이라 고친 뒤 MODIFY가 필요해요. Field Symbol(ASSIGNING <gs_book>)은 그 줄 자체라서 고치면 표가 바로 바뀌어요.
  • READ TABLE이 못 찾으면 Work Area도 Field Symbol도 앞의 것 그대로예요. 꼭 sy-subrc가 0일 때만 써요.
