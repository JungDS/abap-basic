0-1. 이 교재로 배우는 것

ABAP은 SAP 시스템 안에서 돌아가는 프로그래밍 언어예요. 처음엔 낯선 화면과 용어가 많아서 길을 잃기 쉬운데요, 사실 우리가 만들 프로그램은 대부분 아래 다섯 칸짜리 흐름 하나로 설명할 수 있어요.

사용자가 조건을 넣으면, 프로그램이 DB에서 데이터를 읽어 메모리에 담고, 필요한 계산을 한 뒤 화면에 보여 줘요. DB는 프로그램이 끝나도 데이터가 남아 있는 저장소이고, 메모리는 프로그램이 도는 동안만 쓰는 임시 공간이에요.

칸 위의 숫자는 그 칸을 배우는 장이에요. 배우는 순서는 왼쪽 칸부터가 아니에요. 가장 쉬운 맨 오른쪽 "보여 주기"(2장)부터 시작해요. 그림에 없는 1장(SAP GUI), 6장(디버거), 10장(모듈화)은 이 흐름을 만들고, 고치고, 정리할 때 쓰는 도구를 익히는 장이에요. 마지막 12장에서는 다섯 칸을 모두 이어서 "도서 조회 프로그램"을 하나 완성할 거예요.

아래 표에 낯선 낱말이 보여도 괜찮아요. 그 장에 가면 하나씩 풀어 줄게요. 지금은 이런 순서로 간다는 것만 봐 두세요.

장 제목 한 줄 소개
1 SAP 시스템과 SAP GUI 첫걸음 로그인하고, 화면을 둘러보고, 트랜잭션 코드로 이동해요
2 첫 프로그램 만들기 SE38에서 만들고 → 검사하고 → 활성화하고 → 실행해요

순서가 왜 이래요?

수업에서는 Dictionary를 먼저 해 봤지만, 이 교재는 혼자 다시 볼 때 가장 덜 막히는 순서로 짰어요. 화면에 글자 한 줄 띄우는 것(2장)부터 시작해서, 변수(3장) → 판단과 반복(4장) → 입력(5장)처럼 한 장에 새 개념이 조금씩만 늘어나요. Dictionary는 "데이터를 저장할 곳"이 필요해지는 7장에서 다시 자세히 다뤄요.

필요한 장만 골라 봐도 되지만 7장은 건너뛰지 마세요. 7장에서 만드는 Table과 데이터를 9장부터 12장까지 계속 쓰거든요.

상자 말고 새로 만들기 카드도 자주 나와요. 프로그램 같은 것을 새로 만드는 자리마다 이런 카드가 있어요.

카드는 무엇을 어떤 이름과 Title로 만드는지 알려 줘요. 맨 윗줄은 만들 것의 종류(Program)와 만드는 화면(SE38)이에요. SE38은 그 화면으로 바로 가는 주소인데, 1장에서 배워요. 그 아래 줄들은 그 화면에 넣을 값이에요. Title은 프로그램에 붙이는 제목이에요. 위 카드는 2장에서 처음 만들 프로그램이니, 지금은 모양만 봐 두세요.

장 맨 끝에는 정리와 다음 장 예고 상자가 있어요. 2장부터는 대부분의 장 끝에 미니 실습도 있어요. 먼저 혼자 만들어 보고, 막히면 접혀 있는 "예시 답안 보기"를 펼쳐요.

코드와 그림 읽는 법

  • 코드는 모두 이런 글꼴로 보여요: WRITE 'Hello ABAP'.
  • YG##_101처럼 이름 끝에 101 같은 번호가 붙은 예제 프로그램의 코드 상자에는 오른쪽 위에 복사 버튼이 있어요(인쇄본에는 없어요). 짧은 조각 코드와 실습 정답에는 버튼이 없어요. 직접 쳐 보는 것이 연습이라서요. 예제도 처음에는 손으로 따라 쳐 보세요. 복사한 코드를 붙여 넣는 법은 2장에서 알려 줄게요.
  • 교재에 나오는 이름 속의 ## 두 글자는 내 번호 자리예요. 내 번호는 수업에서 받은 번호이고, 꼭 두 자리로 써요. 5번 학생이면 YG##_101은 YG05_101이 돼요.
  • 웹 교재에서는 이 자리가 첫 페이지에서 적은 번호로 자동으로 바뀌어 보여요. YG##_101의 형광펜으로 칠한 두 글자가 내 번호로 보이면 맞게 된 거예요. 복사 버튼으로 복사할 때도 내 번호가 들어가요.
  • 내 번호를 잘못 적었으면 목차 맨 위의 내 번호 버튼을 눌러 바꿀 수 있어요. 휴대폰에서는 화면을 맨 위까지 올리면 나오는 목차에 있어요.
  • ##가 그대로 보이는 인쇄본이나 PDF를 받았다면 내 번호로 바꿔 읽으면 돼요. SAP GUI에 입력할 때도 내 번호로 바꿔서 쳐요.
  • SAP GUI 화면은 설명 그림으로 그렸어요. 실제 화면과 색이나 버튼 배치가 조금 다를 수 있어요. 그림 안의 1 같은 번호는 본문 설명의 번호와 짝이에요. 휴대폰처럼 좁은 화면에서 그림의 오른쪽이 잘려 보이면 그림을 옆으로 밀어 보세요.
  • 그림과 본문에 나오는 버튼·메뉴 이름(Create, Activate 등)은 영어 화면 기준이에요. 한국어로 로그인했다면 같은 자리의 이름이 한글로 보일 수 있어요. 어느 쪽이든 늘 같은 언어로 로그인해요(까닭은 1-3).
  • 키보드 단축키는 Ctrl+F2처럼 보여 줘요. Ctrl을 누른 채 F2를 누른다는 뜻이에요. 노트북에서 F8 같은 키가 듣지 않으면 Fn 키와 함께 눌러 보세요.

0-3. 실습 이름 규칙

SAP 시스템은 여러 사람이 함께 쓰는 하나의 큰 건물이에요. 그리고 같은 이름의 프로그램은 한 시스템에 하나만 만들 수 있어요. Table처럼 시스템에 저장되는 다른 것들도 마찬가지예요. 그래서 이름에 내 번호를 넣어 서로 겹치지 않게 해요. 이 교재의 실습은 아래 규칙을 따라요.

종류 규칙 예시 (5번 학생) 만드는 곳
Program YG##_1nn YG05_101 2장부터
Domain YDO_G##_명칭 YDO_G05_NAME 7장
Data Element YDE_G##_명칭 YDE_G05_TITLE 7장
Table YTA_G##_명칭 YTA_G05_BOOK 7장
Function Group YFG_G## YFG_G05 10장
Function Module Y_G##_명칭 Y_G05_DISCOUNT 10장
Structure YST_G##_명칭 YST_G05_BOOK_LIST 11장

표에 있는 것처럼 시스템에 만들어 저장하는 것을 객체라고 불러요. 지금은 첫 줄(Program)만 알면 돼요. 5번 학생의 YG05_101을 뜯어보면 YG 뒤에 내 번호 05, 밑줄(_), 프로그램 번호 101을 차례로 붙인 이름이에요. 규칙의 1nn은 101, 102처럼 교재가 정해 둔 세 자리 번호가 들어가는 자리예요.

나머지 줄은 그 장에서 만들 때 다시 알려 줄게요. 규칙의 명칭 자리에는 NAME, BOOK처럼 무엇인지 알려 주는 영어 낱말이 들어가요. 5장에서 만드는 Message Class(YMC_G##)까지 넣은 표는 부록 F에 있어요.

왜 Z나 Y로 시작해요?

SAP가 만든 프로그램과 이름이 겹치지 않도록, SAP를 쓰는 쪽(고객, 곧 우리)이 만드는 객체는 이름이 Z 또는 Y로 시작해야 해요. 그 밖의 이름(예: ABC_TEST)은 SAP가 쓰는 자리예요. 이런 이름으로 만들려고 하면 시스템 버전에 따라 등록 키(Access Key)를 묻는 창이 뜨거나 권한 오류가 나면서 막혀요. 그럴 때는 취소하고 이름을 고쳐요. 아무것도 묻지 않는 시스템도 있을 수 있으니, 이름을 넣을 때마다 Y로 시작하는지 먼저 확인해요.

SAP 시스템이 보기에 Y와 Z는 똑같은 "고객이 쓰는 이름"이에요. 둘 중 무엇을 쓸지는 회사나 수업마다 정하는 약속이에요. 이 교재에서는 연습용 객체를 모두 Y로 시작해요. 그래서 프로그램은 YG##_101, Table은 YTA_G##_BOOK처럼 지어요. 회사에 가면 Z로 시작하는 이름도 많이 보게 될 거예요. 프로그램을 다른 시스템으로 옮기는지도 첫 글자와는 상관없어요(1-6에서 봐요).

프로그램 번호와 Title

프로그램 번호는 교재가 101부터 나오는 순서대로 정해 뒀어요. 따라 치는 예제와 스스로 푸는 실습을 나누지 않고 이어서 매겼어요. 그래서 내 프로그램은 YG##_101, YG##_102처럼 이어져요. 예제를 건너뛰어도 번호를 당겨 쓰지 않고, 카드에 적힌 이름 그대로 만들어요. 이름만 봐서는 무슨 프로그램인지 알 수 없으니, 만들 때 Title을 새로 만들기 카드에 적힌 글자 그대로 넣어요. Title은 나중에 내 프로그램을 다시 찾을 때 길잡이가 돼요(2-8).

Title 앞의 [예제]는 따라 치는 프로그램, [실습]은 스스로 푸는 프로그램이라는 표시예요. 예를 들어 YG##_101은 [예제] 나의 첫 ABAP 프로그램, YG##_102는 [실습] 자기소개예요. 전체 번호표는 부록 G에 있어요.

자주 하는 실수
  • 예시의 05는 5번 학생의 번호예요. 그대로 따라 치지 말고 꼭 내 번호를 넣어요.
  • 내 번호는 항상 두 자리예요. 5번은 G5가 아니라 G05예요.
  • 내 번호를 잘못 넣으면 친구의 프로그램이 열릴 수 있어요. 내가 쓴 적 없는 코드가 보이면 고치지 말고 이름 속의 내 번호부터 확인해요. 잘못 만든 프로그램은 지우고 다시 만들면 돼요(2-8).

코드 안의 변수 이름

코드 안에서 쓰는 변수 이름에도 약속이 있어요. 이쪽은 겹칠까 봐 정한 것이 아니에요. 변수는 내 프로그램 안에서만 쓰니까 친구와 이름이 같아도 괜찮아요. 이름만 봐도 무엇인지 알 수 있게 앞에 붙이는 글자(앞머리)를 정해 둔 거예요. 지금 외울 필요는 없어요. 처음 나오는 장에서 다시 알려 줄게요.

앞머리 무엇에 붙여요 예시 처음 나오는 곳
gv_ 전역 변수 (Global Variable) gv_result 3장
pa_ Selection Screen 입력 칸 (PARAMETERS) pa_name 5장
gs_ 전역 Structure gs_book 8장
gt_ 전역 Internal Table gt_book 8장
so_ Selection Screen 범위 입력 칸 (SELECT-OPTIONS) so_price 9장

전역(Global)은 프로그램 어디에서나 쓸 수 있다는 뜻이에요. 이 밖에 gc_(상수), ty_(직접 만든 Type), lv_(지역 변수) 같은 앞머리도 나와요. 전체는 부록 F에 모아 뒀어요. 코드에서는 이름을 소문자로 써요.

0-4. 막혔을 때

  1. 상태 표시줄(화면 맨 아래)을 먼저 보세요. SAP는 오류나 안내를 거의 다 거기에 보여 줘요.
  2. F1 도움말을 써 보세요. 코드에서 궁금한 단어(예: WRITE)에 커서를 놓고 F1을 누르면 설명서가 열려요. 설명서는 영어로 나오지만, 예제 코드(Example)만 봐도 도움이 돼요.
  3. 부록 C(자주 보는 오류와 해결)를 찾아보세요. 자주 만나는 오류 메시지와 고치는 법을 모아 뒀어요.
  4. 실습 데이터가 꼬였다면 처음 상태로 되돌리세요. 9장에서 Table의 데이터를 바꾸는 예제를 실행하고 나면 결과가 교재와 달라질 수 있어요. 그럴 때는 9-7의 되돌리기 프로그램(YG##_137)을 실행해요.
  5. 질문할 땐 캡처를 같이 보내 주세요. 코드 화면과 오류 메시지가 함께 보이게 캡처하면 훨씬 빨리 답을 받을 수 있어요. 프로그램 이름과 교재의 몇 장 몇 절을 하던 중인지도 적어 주세요.
확인 문제
  1. 12번 학생이 교재의 YG##_101 프로그램을 만들려고 해요. SAP GUI에 입력할 이름은 무엇일까요? 3번 학생은요?
  2. 새로 만들기 카드의 Title에 [실습] 자기소개라고 적혀 있어요. 따라 치는 프로그램일까요, 스스로 푸는 프로그램일까요? 정답 코드에 복사 버튼이 있을까요?
  3. 그림 0-1의 다섯 칸을 순서대로 말해 보세요.
  4. 따라 하다가 오류 메시지를 만났어요. 가장 먼저 화면의 어디를 볼까요? 메시지의 뜻을 모르겠으면 교재의 어디를 펼칠까요?
정답 보기
  1. YG12_101과 YG03_101이에요. 내 번호는 항상 두 자리로 써요.
  2. 스스로 푸는 프로그램이에요. 실습 정답에는 복사 버튼이 없어요. 직접 쳐 보는 것이 연습이니까요.
  3. 입력받기 → DB에서 읽기 → 메모리에 담기 → 계산·판단 → 보여 주기예요.
  4. 화면 맨 아래 상태 표시줄을 먼저 봐요. 뜻을 모르겠으면 부록 C(자주 보는 오류와 해결)를 찾아봐요.
정리
  • 우리가 만들 프로그램은 대부분 "입력받기 → DB에서 읽기 → 메모리에 담기 → 계산·판단 → 보여 주기" 흐름이에요.
  • 상자 색으로 지금 하는 일을 구분해요. 새로 만들기 카드는 무엇을 어떤 이름과 Title로 만드는지 알려 줘요.
  • ##는 내 번호(두 자리) 자리예요. 웹 교재에서는 내 번호로 바뀌어 보여요.
  • 프로그램 이름(YG##_101부터)과 Title은 새로 만들기 카드에 적힌 글자 그대로 넣어요.
  • 내가 만드는 객체의 이름은 Y나 Z로 시작해야 해요. 그 가운데 Y만 쓰는 것은 우리 수업의 약속이에요.
  • 막히면 상태 표시줄, F1 도움말, 부록 C 순서로 찾아봐요.
다음 장 예고

1장에서는 SAP GUI로 로그인해서 첫 화면을 둘러봐요. 트랜잭션 코드로 화면을 옮겨 다니고, 내가 만든 프로그램이 어디에 저장되는지도 알아봐요.
