4장

조건문과 반복문

이번 장 목표
  • IF와 CASE로 조건에 따라 다른 일을 하게 만들 수 있어요.
  • 비교 연산자와 AND·OR·NOT으로 조건을 정확하게 쓸 수 있어요.
  • DO와 WHILE로 같은 일을 여러 번 반복하고, sy-index로 몇 번째 바퀴인지 알 수 있어요.
  • EXIT·CONTINUE·CHECK로 반복을 멈추거나 건너뛸 수 있어요.
  • 반복문 안에 반복문을 넣어 구구단을 출력할 수 있어요.

4-1. 조건에 따라 다르게: IF

지금까지의 프로그램은 위에서 아래로 한 줄씩 전부 실행됐어요. 하지만 "60점 이상이면 합격, 아니면 불합격"처럼 상황에 따라 다른 일을 해야 할 때가 많아요. 이때 쓰는 것이 IF예요. 이렇게 조건에 따라 갈라지는 문장을 조건문이라고 해요.

이 장에서도 카드가 붙은 예제는 2-2에서 한 순서대로 새 프로그램을 만들어 실행해 보세요. 카드 없이 나오는 짧은 코드는 모양만 눈에 익히면 돼요.

Title
[예제] IF로 합격 판정
REPORT yg##_109.

DATA gv_score TYPE i VALUE 75.

START-OF-SELECTION.
  IF gv_score >= 60.
    WRITE / '합격이에요'.
  ELSE.
    WRITE / '아쉽지만 불합격이에요'.
  ENDIF.

75점은 60점 이상이라 실행하면 이렇게 나와요.

합격이에요
  • IF 조건. 뒤에는 조건이 맞을 때 할 일을 써요.
  • ELSE. 뒤에는 조건이 틀릴 때 할 일을 써요. 필요 없으면 ELSE 부분은 빼도 돼요.
  • 마지막은 꼭 ENDIF.로 닫아요. IF마다 ENDIF가 하나씩 짝을 이뤄요. 빠뜨리면 문법 오류가 엉뚱한 줄(대개 그보다 아래 줄)에서 나기도 해요. 그럴 땐 IF와 ENDIF의 짝부터 세어 봐요.
  • IF와 ENDIF 사이의 줄은 두 칸 들여 써서 "여기는 IF 안이에요"가 보이게 해요. Pretty Printer(Shift+F1)를 누르면 알아서 맞춰 줘요.
직접 해 보기 · 점수를 바꿔 가며 실행하기

조건문은 값을 바꿔서 다른 갈래로 가는 것을 직접 봐야 내 것이 돼요.

  1. VALUE 75를 VALUE 40으로 바꾸고 다시 활성화(Ctrl+F3)해서 실행(F8)해요. 이번에는 아쉽지만 불합격이에요가 나와요.
  2. VALUE 60이면 어떻게 될까요? 먼저 예상해 보고 실행해서 확인해요. 합격이에요가 나오면 맞아요. >=는 "크거나 같다"라서 60도 들어가요.
실행했는데 아무 화면도 안 나와요

ELSE가 없는 IF는 조건이 틀리면 아무 일도 하지 않아요. 출력한 것이 하나도 없으면 결과 화면이 뜨지 않고 ABAP Editor에 그대로 있어요. 고장이 아니라 "보여 줄 게 없어요"라는 뜻이에요.

4-2. 비교 연산자

뜻 기호 글자로 쓰기 예
같다 = EQ gv_a = 10
다르다 <> NE gv_a <> 0
작다 < LT gv_a < 60
크다 > GT gv_a > 100
작거나 같다 <= LE gv_a <= 9
크거나 같다 >= GE gv_a >= 1
사이에 있다 BETWEEN … AND … gv_a BETWEEN 1 AND 100
비어 있다(초기값) IS INITIAL gv_name IS INITIAL
비어 있지 않다 IS NOT INITIAL gv_name IS NOT INITIAL

기호와 글자는 뜻이 똑같아요. 회사 코드에서는 둘 다 보이니 읽을 줄만 알면 돼요. 이 교재는 기호를 써요. 글자 쪽은 영어 줄임말이에요. EQ(Equal), NE(Not Equal), LT(Less Than), GT(Greater Than), LE(Less or Equal), GE(Greater or Equal).

  • IS INITIAL은 변수가 지금 비어 있는지 물어요. "비어 있다"는 3-2에서 본 초기값이라는 뜻이에요. 글자는 공백, 숫자는 0이면 조건이 맞아요. VALUE 75로 만든 변수는 한 번도 안 바꿨어도 75가 들어 있으니 비어 있지 않아요.
  • 'A' 같은 글자 값도 =로 비교해요. gv_grade = 'A'처럼 값을 작은따옴표로 감싸고, 대문자와 소문자는 다른 글자로 봐요.
BETWEEN은 양 끝을 포함해요

gv_a BETWEEN 1 AND 100은 "1 이상이고 100 이하"라는 뜻이에요. 1과 100도 "사이"에 들어가요.

JavaScript와 다른 점
  • 비교도 = 하나로 써요. JavaScript처럼 =를 두 개나 세 개 이어 쓰지 않아요. gv_a = 10.처럼 문장이 변수로 시작하면 "값 넣기"(3-2)이고, IF gv_a = 10.처럼 IF 뒤에 오면 "같은지 비교"예요.
  • "다르다"는 !=가 아니라 <>예요.
  • 조건을 괄호로 감쌀 필요가 없고, 중괄호 { } 대신 ENDIF.로 닫아요.
  • 비교 기호 앞뒤는 꼭 한 칸씩 띄워요. gv_a>=60처럼 붙여 쓰면 문법 오류가 나요. IF 조건., ELSE., ENDIF. 끝의 마침표도 빼먹기 쉬워요.

4-3. 여러 갈래로 나누기: ELSEIF

갈래가 셋 이상이면 ELSEIF를 이어 써요. 위에서부터 차례로 검사하다가 처음 맞는 곳 하나만 실행해요.

새로 만들기ProgramSE38
Program
YG##_110
Title
[예제] ELSEIF로 등급 나누기
REPORT yg##_110.

DATA gv_score TYPE i VALUE 85.

START-OF-SELECTION.
  IF gv_score >= 90.
    WRITE / 'A 등급'.
  ELSEIF gv_score >= 80.
    WRITE / 'B 등급'.          " 85점은 여기에 걸려요
  ELSEIF gv_score >= 70.
    WRITE / 'C 등급'.
  ELSE.
    WRITE / '다시 도전!'.
  ENDIF.
B 등급

85점은 첫 조건(>= 90)에는 안 맞고 둘째 조건(>= 80)에 맞아요. 그래서 B 등급만 출력하고, 그 아래 갈래는 검사하지 않아요. 85를 95, 72, 50으로 바꿔 가며 실행해 보세요. 차례로 A 등급, C 등급, 다시 도전!이 나와요.

자주 하는 실수
  • 순서가 거꾸로면 결과가 틀려요. IF gv_score >= 70.을 맨 위에 두면 95점도 첫 줄에서 걸려서 C 등급이 돼요. 큰 기준부터 차례로 써요.
  • ELSEIF는 붙여서 한 단어로 써요. ELSE IF로 띄우면 문법 오류가 나요.

4-4. 조건 여러 개 묶기: AND · OR · NOT

연산자 뜻 예
AND 둘 다 맞아야 gv_age >= 20 AND gv_age < 30 (20대)
OR 하나만 맞아도 gv_day = 6 OR gv_day = 7 (토요일이나 일요일. 월요일을 1로 셀 때)
NOT 반대로 NOT gv_name IS INITIAL (이름이 비어 있지 않으면)

NOT gv_name IS INITIAL은 4-2의 gv_name IS NOT INITIAL과 같은 뜻이에요. 회사 코드에서는 두 모양이 다 보여요. 그리고 JavaScript의 &&, ||, ! 자리에 ABAP은 AND, OR, NOT을 글자로 써요.

예를 들어 "1보다 작거나 100보다 크면"은 이렇게 써요.

IF gv_num < 1 OR gv_num > 100.
  WRITE / '1부터 100 사이의 숫자만 넣어 주세요'.
ENDIF.
자주 하는 실수

IF gv_day = 6 OR 7.처럼 쓰면 안 돼요. 사람 말로는 자연스럽지만 ABAP은 OR 양쪽을 각각 완전한 조건으로 읽어요. IF gv_day = 6 OR gv_day = 7.처럼 변수를 다시 써 줘요.

조건이 헷갈릴 땐 괄호

AND와 OR를 섞으면 AND가 먼저 묶여요. 헷갈리면 괄호로 확실하게 묶어 주세요. 괄호 안쪽은 꼭 한 칸씩 띄워요.

IF ( gv_day = 6 OR gv_day = 7 ) AND gv_rain = 'X'.
  WRITE / '비 오는 주말이에요'.
ENDIF.

gv_day는 요일 번호(6은 토요일, 7은 일요일)이고, gv_rain = 'X'는 "비가 오면"이라는 뜻이에요. ABAP에서는 "예"를 'X', "아니요"를 빈칸으로 적는 습관이 있어요. 5장에서 다시 나와요.

직접 해 보기 · 조건 두 개 묶기

점수는 100점까지니까, 100을 넘는 잘못된 값은 합격으로 치지 않게 해 볼게요.

  1. 4-1에서 만든 YG##_109를 다시 열어요(2-8). IF gv_score >= 60.을 IF gv_score >= 60 AND gv_score <= 100.으로 바꿔요.
  2. VALUE를 75, 120으로 바꿔 가며 활성화하고 실행해요. 75는 합격이에요, 120은 아쉽지만 불합격이에요가 나와요.
  3. 같은 줄을 IF gv_score BETWEEN 60 AND 100.으로 바꿔도 결과가 같은지 확인해요.

4-5. 값 하나로 갈래 나누기: CASE

변수 하나의 값에 따라 갈래가 여러 개라면 CASE가 더 읽기 쉬워요.

새로 만들기ProgramSE38
Program
YG##_111
Title
[예제] CASE로 메뉴 고르기
REPORT yg##_111.

DATA gv_menu TYPE i VALUE 2.

START-OF-SELECTION.
  CASE gv_menu.
    WHEN 1.
      WRITE / '아메리카노'.
    WHEN 2.
      WRITE / '카페라테'.
    WHEN 3 OR 4.
      WRITE / '스무디'.
    WHEN OTHERS.
      WRITE / '없는 메뉴예요'.
  ENDCASE.
카페라테

VALUE 2를 4로 바꾸면 스무디, 9로 바꾸면 없는 메뉴예요가 나와요.

  • WHEN 값. 아래에 그 값일 때 할 일을 써요. 맞는 WHEN 하나만 실행하고 ENDCASE 다음으로 넘어가요. JavaScript의 switch와 달리 break를 쓸 필요가 없어요. 글자 값이면 WHEN 'A'.처럼 작은따옴표로 감싸요.
  • WHEN 3 OR 4.처럼 여러 값을 묶을 수도 있어요. 이 OR는 WHEN 뒤에서만 되는 값 나열이에요. IF에서는 4-4에서 본 대로 gv_menu = 3 OR gv_menu = 4라고 써야 해요.
  • WHEN OTHERS.는 위의 어떤 값에도 해당하지 않을 때예요. IF의 ELSE와 같아요. 맨 마지막에 한 번만 써요.
  • 마지막은 ENDCASE.로 닫아요.
IF와 CASE, 언제 뭘 쓰나요?

"값이 1이면, 2면, 3이면…"처럼 같은 변수의 값을 하나씩 비교하면 CASE, "60점 이상이면"처럼 범위나 여러 변수를 비교하면 IF가 잘 어울려요.

4-6. 정해진 횟수만큼 반복: DO … TIMES

같은 일을 여러 번 해야 할 때 코드를 복사해서 붙이는 대신 반복문을 써요.

DO 3 TIMES.
  WRITE / 'ABAP 파이팅!'.
ENDDO.

DO 횟수 TIMES.와 ENDDO. 사이를 정한 횟수만큼 반복해요. 이 코드는 ABAP 파이팅!을 세 줄 출력해요. 횟수 자리에는 DO gv_cnt TIMES.처럼 숫자 변수를 써도 돼요.

몇 번째 바퀴인지 알려 주는 sy-index

반복문이 한 번 도는 것을 이 교재에서는 "한 바퀴"라고 부를게요. 반복하는 동안 SAP는 지금이 몇 번째 바퀴인지를 시스템 필드 sy-index에 넣어 줘요. 첫 바퀴는 1, 두 번째 바퀴는 2예요. JavaScript의 for에서 쓰던 i처럼 0부터가 아니라 1부터 세요. 이걸 이용하면 1부터 5까지 더하기를 이렇게 쓸 수 있어요.

새로 만들기ProgramSE38
Program
YG##_112
Title
[예제] 1부터 5까지의 합
REPORT yg##_112.

DATA gv_sum TYPE i.

START-OF-SELECTION.
  DO 5 TIMES.
    gv_sum = gv_sum + sy-index.
  ENDDO.

  WRITE: / '1부터 5까지의 합:', gv_sum.
1부터 5까지의 합:         15

숫자 앞의 긴 공백은 3-2에서 본 그대로예요. 칸 수는 조금 달라도 괜찮아요.

  • gv_sum = gv_sum + sy-index.는 "지금 gv_sum에 sy-index를 더한 값을 다시 gv_sum에 넣어라"로 읽어요. 처음 gv_sum은 0이에요(3-2의 초기값).
  • WRITE는 ENDDO. 아래, 반복문 밖에 있어서 반복이 다 끝난 뒤 한 번만 실행돼요. 이 줄을 ENDDO. 위로 옮기면 바퀴마다 한 줄씩 1, 3, 6, 10, 15가 출력돼요. 직접 옮겨서 확인해 보세요.

이렇게 표로 값을 따라가 보는 연습을 해 두면, 6장에서 디버거로 직접 확인할 때 훨씬 쉬워요.

4-7. 몇 번 돌지 모를 때: EXIT와 WHILE

몇 번 반복할지 미리 모를 때도 있어요. 예를 들어 "1부터 차례로 더하다가 합이 100을 넘는 순간 멈추기"가 그래요. 방법은 두 가지예요. 횟수를 쓰지 않은 DO.로 계속 돌다가 EXIT.로 빠져나오는 방법과, 조건이 맞는 동안만 도는 WHILE이에요. 코드를 치기 전에 아래 상자부터 읽어요.

실행하기 전에: 끝나지 않는 반복
  • EXIT가 없는 DO.는 끝나지 않아요(무한 반복). F8을 눌렀는데 결과 화면이 나오지 않고 화면이 멈춘 듯 계속 기다리기만 하면 무한 반복이에요. WHILE도 조건이 영원히 맞으면 똑같아요. 출력이 없어서 곧바로 ABAP Editor로 돌아온 경우(4-1)와는 달라요.
  • 멈추려면 SAP GUI 창 맨 왼쪽 위 구석의 작은 아이콘을 눌러서, 열린 메뉴에서 Stop Transaction을 골라요. 아이콘 모양은 SAP GUI 버전과 테마에 따라 조금 달라요. 멈춘 뒤 다른 화면으로 돌아가 있으면 SE38에서 프로그램을 다시 열어요(2-8). 멈추지 않고 두면 한참 뒤에야(보통 10분쯤) SAP가 프로그램을 강제로 끝내요.
  • Stop Transaction을 누르면 저장하지 않은 코드는 사라질 수 있어요. 그래서 반복문이 든 프로그램은 실행하기 전에 Ctrl+S부터 눌러요.
  • 아래 예제처럼 숫자를 계속 더하는 반복문은 EXIT를 빠뜨리면 합계가 TYPE i에 담을 수 있는 크기를 금방 넘어서, 기다릴 틈도 없이 영어가 가득한 오류 화면(덤프, 6-8)이 뜨기도 해요. 놀라지 말고 F3으로 돌아와 EXIT와 조건을 확인해요.

방법 1. DO + EXIT

DO.에 횟수를 쓰지 않으면 계속 반복해요. 멈추고 싶은 곳에서 EXIT.를 쓰면 반복문을 빠져나가요. JavaScript의 break와 같아요.

Program
YG##_113
Title
[예제] DO와 EXIT로 100 넘기기
REPORT yg##_113.

DATA: gv_sum   TYPE i,
      gv_count TYPE i.

START-OF-SELECTION.
  DO.
    gv_sum = gv_sum + sy-index.
    IF gv_sum > 100.
      gv_count = sy-index.     " 몇 번째에서 멈췄는지 기억해 두기
      EXIT.                    " 반복문 빠져나가기
    ENDIF.
  ENDDO.

  WRITE: / '더한 횟수:', gv_count,
         / '합계:',      gv_sum.
더한 횟수:         14
합계:        105

반복문 안에 IF를 넣었어요. 바퀴마다 합을 검사하다가 100을 넘는 순간 EXIT로 빠져나와요. 1부터 13까지 더하면 91이라 아직 100을 넘지 않고, 14번째 바퀴에서 105가 되면서 처음으로 100을 넘어요. 반복문이 끝나면 sy-index는 반복 전 값으로 돌아가기 때문에, 빠져나오기 직전에 gv_count에 옮겨 뒀어요(아래 "자주 하는 실수").

방법 2. WHILE

WHILE 조건.은 조건이 맞는 동안 반복해요. 바퀴를 시작하기 전에 조건부터 검사해요.

Title
[예제] WHILE로 100 넘기기

DATA: gv_sum TYPE i,
      gv_num TYPE i.

START-OF-SELECTION.
  WHILE gv_sum <= 100.
    gv_num = gv_num + 1.
    gv_sum = gv_sum + gv_num.
  ENDWHILE.

  WRITE: / '더한 횟수:', gv_num,
         / '합계:',      gv_sum.

실행 결과는 방법 1과 똑같이 14와 105예요.

  • 방법 1의 IF gv_sum > 100.은 멈출 조건이고, 방법 2의 WHILE gv_sum <= 100.은 계속할 조건이에요. 서로 정반대예요. WHILE gv_sum > 100.이라고 쓰면 처음부터 조건이 틀려서 한 바퀴도 돌지 않아요.
  • WHILE 안에서도 sy-index는 1, 2, 3으로 올라가요. 위 코드의 gv_num은 sy-index와 같은 값이에요.
자주 하는 실수

반복문이 끝나면 sy-index는 반복 전 값(보통 0)으로 돌아가요. 그래서 ENDDO나 ENDWHILE 뒤에서 몇 번째 바퀴였는지 알고 싶으면, 위 예제들처럼 반복문 안에서 다른 변수(gv_count, gv_num)에 옮겨 둬야 해요.

4-8. 이번 바퀴만 건너뛰기: CONTINUE와 CHECK

EXIT가 반복문 전체를 끝낸다면, CONTINUE는 이번 바퀴만 건너뛰고 다음 바퀴로 가요. JavaScript의 continue와 같아요. 다섯 바퀴짜리 반복문을 두 번 돌려 볼게요. 앞의 반복문은 3번째 바퀴에서 CONTINUE를 쓰고, 뒤의 반복문은 3번째 바퀴에서 EXIT를 써요.

  WRITE / 'CONTINUE를 쓴 반복'.

    ENDIF.

  • 뒤의 반복문은 1, 2만 출력해요. 3번째 바퀴에서 EXIT를 만나 반복문을 빠져나와서, 4번째와 5번째 바퀴는 돌지도 않았어요.

그림으로 보면 이래요. 그림에 함께 적힌 CHECK는 바로 아래에서 배워요. CONTINUE와 같은 쪽이에요.

더 짧게 쓰는 CHECK

CHECK 조건.은 조건이 틀리면 이번 바퀴의 나머지를 건너뛰어요. YG##_115에서 앞의 반복문에 있는 IF sy-index = 3.부터 ENDIF.까지 세 줄(CONTINUE가 들어 있는 쪽)을 CHECK sy-index <> 3. 한 줄로 바꿔도 똑같이 1, 2, 4, 5가 나와요. IF와 CONTINUE에는 건너뛸 조건을, CHECK에는 통과시킬 조건을 써요. 서로 반대예요.

CHECK는 3-4에서 배운 MOD(나머지)와 함께 "홀수만", "3의 배수만"처럼 골라낼 때 자주 써요. 2로 나눈 나머지가 1이면 홀수, 0이면 짝수예요.

DO 10 TIMES.
  CHECK sy-index MOD 2 = 1.  " 홀수일 때만 아래로 내려가요
  WRITE / sy-index.          " 홀수(1, 3, 5, 7, 9)만 출력돼요
ENDDO.
자주 하는 실수
  • EXIT와 CHECK를 반복문 밖에서 쓰면 뜻이 달라져요. 반복문이 아니라 START-OF-SELECTION 아래에 남은 코드를 전부 건너뛰어 버려요(CHECK는 조건이 틀릴 때만요). CONTINUE는 반복문 밖에서는 아예 쓸 수 없어요.
  • 그래서 EXIT·CONTINUE·CHECK는 반복문 안에서만 쓰기로 해요. 반복문이 아니라 지금 하던 처리 덩어리(예: START-OF-SELECTION 아래 전체)를 통째로 끝내고 싶을 때는 RETURN을 써요. 5장부터 자주 나와요.

4-9. 반복 안의 반복: 구구단

구구단 2단만 출력한다면 반복문 하나로 충분해요. 곱하는 수가 1부터 9까지 바뀌니 sy-index를 그대로 쓰면 돼요.

DO 9 TIMES.
  gv_result = 2 * sy-index.
  WRITE: / '2 x', sy-index, '=', gv_result.
ENDDO.

2 곱하기 1부터 2 곱하기 9까지 아홉 줄을 출력해요. 숫자 앞에는 긴 공백이 붙는데, 조금 뒤에 줄여 볼 거예요.

3단도 출력하려면 이 반복문 전체를 한 번 더 돌려야 해요. 그래서 이 반복문을 DO 2 TIMES.로 한 번 더 감싸고, 숫자 2 자리에는 단을 담은 변수 gv_dan을 써요. 이렇게 반복문 안에 반복문을 넣으면 바깥 반복문이 단을 바꾸고(2단, 3단), 안쪽 반복문이 1부터 9까지 곱해요.

새로 만들기ProgramSE38
Program

Title
[예제] 구구단 2단과 3단
REPORT yg##_116.

DATA: gv_dan    TYPE i,
      gv_result TYPE i.

START-OF-SELECTION.
  DO 2 TIMES.                        " 바깥 반복: 단 (2단, 3단)
    gv_dan = sy-index + 1.           " 바깥 바퀴 1, 2 → 2단, 3단
    DO 9 TIMES.                      " 안쪽 반복: 곱하는 수 (1~9)
      gv_result = gv_dan * sy-index.
      WRITE: /(1) gv_dan, 'x', (1) sy-index, '=', (2) gv_result.
    ENDDO.
    SKIP.                            " 단 사이에 빈 줄 하나
  ENDDO.
  • 반복문이 겹치면 sy-index는 지금 돌고 있는 가장 안쪽 반복문의 바퀴 수예요. 안쪽 DO 9 TIMES 안에서는 sy-index가 1부터 9까지 바뀌어서, 바깥쪽이 몇 번째 바퀴였는지 알 수 없어요. 그래서 안쪽 반복이 시작되기 전에 단을 gv_dan에 옮겨 둬요.
  • 바깥 반복은 1, 2로 도는데 단은 2, 3이어야 해서 sy-index + 1로 1을 더했어요.
  • SKIP.은 빈 줄을 하나 넣어요.

출력할 칸 수 정하기

WRITE에서 변수 앞에 (1), (2)처럼 괄호 안에 숫자를 쓰면 그 칸 수만큼만 써서 출력해요. 3장에서 본 숫자 앞의 긴 공백이 없어져요. 단과 곱하는 수는 한 자리라 (1), 결과는 두 자리까지 나오니 (2)로 정했어요. /(1)은 줄 바꿈 /와 칸 수 (1)을 붙여 쓴 거예요.

3-6에서 배운 "일부만 꺼내기"는 괄호가 변수 이름 뒤에 붙고(gv_date(4)), 출력 칸 수는 변수 이름 앞에 와요. 생김새는 비슷해도 다른 문법이에요.

한 자리 수가 왼쪽에 붙는 까닭

TYPE i 같은 숫자는 원래 맨 오른쪽 한 칸이 - 부호 자리예요. 칸이 넉넉하면 그 칸을 비워 두고, 칸이 모자랄 때만 양수가 그 칸까지 써요. 그래서 (2)로 찍은 2는 왼쪽 칸에 오고(오른쪽 칸은 빈 부호 자리), 18은 두 칸을 다 써요. 그림 4-4에서 = 뒤의 숫자가 왼쪽으로 맞춰진 것도 이 때문이에요.

자주 하는 실수
  • 이 괄호는 4-4의 조건 괄호와 달라요. (2)처럼 괄호 안을 띄우지 않고 숫자를 바로 붙여 써요.
  • 칸을 정했는데 값이 더 길면 잘려서 나와요. 숫자는 맨 앞 칸에 *가 찍혀서 "칸이 모자라요"라고 알려 줘요. 예를 들어 값이 105인데 (2)로 쓰면 *5가 나와요. 나올 수 있는 가장 큰 값을 생각해서 칸 수를 정해요. 음수가 나올 수 있으면 - 부호 자리로 한 칸을 더 잡아요.

정리
  • IF … ELSEIF … ELSE … ENDIF로 조건에 따라 다른 일을 해요. 위에서부터 처음 맞는 하나만 실행해요.
  • 조건은 =, <>, <, >, <=, >=, IS INITIAL로 쓰고 AND·OR·NOT으로 묶어요. OR 양쪽은 각각 완전한 조건이어야 해요.
  • 같은 변수의 값으로 갈래를 나눌 땐 CASE … WHEN … ENDCASE가 읽기 좋아요.
  • DO 횟수 TIMES는 정해진 횟수만큼 반복해요. 횟수를 모를 땐 DO + EXIT(멈출 조건)나 WHILE(계속할 조건)을 써요.
  • 반복이 끝나지 않으면(무한 반복) 창 맨 왼쪽 위 아이콘 메뉴의 Stop Transaction으로 멈춰요. 반복문은 실행하기 전에 저장부터 해요.
  • sy-index는 지금 몇 번째 바퀴인지 알려 주고, 반복문이 끝나면 원래 값으로 돌아가요. 반복문이 겹치면 가장 안쪽 반복문의 바퀴 수예요.
  • EXIT는 반복 끝내기, CONTINUE·CHECK는 이번 바퀴 건너뛰기예요. 셋 다 반복문 안에서만 써요.
  • WRITE (2) gv_result처럼 변수 앞에 괄호를 쓰면 출력할 칸 수를 정할 수 있어요.
