11장

ALV로 결과 보기

이번 장 목표
  • WRITE 목록과 ALV의 차이를 말할 수 있어요.
  • CL_SALV_TABLE로 Internal Table을 ALV 화면에 띄울 수 있어요.
  • 컬럼 제목이 Data Element에서 온다는 것을 알고, 칸 숨기기·제목 바꾸기·폭 맞추기를 할 수 있어요.
  • 출력용 줄 모양을 Dictionary Structure로 만들어 ALV에 쓸 수 있어요.
  • 정렬, 필터, 합계, 엑셀 내려받기 버튼을 켤 수 있어요.

11-1. ALV가 뭐예요?

지금까지는 결과를 WRITE로 한 줄씩 찍었어요. 칸을 맞추려고 (20)처럼 길이를 정하고, 정렬하고 싶으면 SORT를 코드에 넣어야 했죠.

ALV(ABAP List Viewer)는 Internal Table을 넘겨주기만 하면 표 화면을 만들어 주는 SAP의 도구예요. 사용자가 화면에서 직접 정렬하고, 거르고, 합계를 내고, 엑셀로 내려받을 수 있어요. 회사에서 쓰는 조회 프로그램은 대부분 결과를 ALV로 보여 줘요.

ALV에서는 표의 칸을 컬럼(Column)이라고 불러요. 표 맨 윗줄에 보이는 이름이 컬럼 제목이에요.

WRITE 목록 ALV
칸 맞추기 길이를 직접 정해요 칸을 알아서 나눠요. 폭도 코드 한 줄이면 맞춰요
컬럼 제목 직접 찍어야 해요 Data Element에서 자동으로 와요
정렬·필터·합계 코드로 해야 해요 사용자가 버튼으로 해요
엑셀 내려받기 어려워요 버튼 하나예요

ALV를 만드는 방법은 여러 가지가 있어요. 이 교재에서는 코드가 가장 짧은 CL_SALV_TABLE 클래스를 써요.

11-2. 가장 짧은 ALV

9장에서 한 것처럼 SELECT로 책을 gt_book에 읽어 온 다음, 그 표를 그대로 ALV로 띄워 볼게요. 프로그램을 새로 하나 만들어요.

처음 보는 모양이 많지만 걱정하지 않아도 돼요. ALV를 띄우는 코드는 거의 그대로 가져다 쓰는 틀이에요. 프로그램마다 바뀌는 곳은 Table 이름과 Internal Table 이름 정도예요. 먼저 따라 쳐서 실행해 보고, 그다음에 한 줄씩 볼게요.

새로 만들기ProgramSE38
Program
YG##_143
Title
[예제] 도서 목록 ALV
REPORT yg##_143.

DATA: gt_book TYPE TABLE OF yta_g##_book,
      go_alv  TYPE REF TO cl_salv_table.     " ALV 객체를 가리키는 변수

START-OF-SELECTION.
  " 1. 데이터 읽기 (9장)
  SELECT * FROM yta_g##_book INTO TABLE gt_book.

  " 2. ALV 만들기
  TRY.
      cl_salv_table=>factory(
        IMPORTING
          r_salv_table = go_alv
        CHANGING
          t_table      = gt_book ).
    CATCH cx_salv_msg.
      MESSAGE 'ALV를 만들지 못했어요' TYPE 'S' DISPLAY LIKE 'E'.
      RETURN.
  ENDTRY.

  " 3. 화면에 띄우기
  go_alv->display( ).

이 장의 그림과 숫자는 7-7에서 넣은 책 다섯 권 기준이에요. 결과가 그림과 다르면 9-7의 YG##_137(도서 데이터 처음 상태로 되돌리기)을 먼저 실행해요.

직접 해 보기
  1. 위 코드를 쓰고 저장 → 검사 → 활성화한 뒤 F8로 실행해요. 입력 칸이 없는 프로그램이라 바로 표가 나와요.
  2. 그림 11-2처럼 책 다섯 권이 한 줄씩 보이면 성공이에요.
  3. 아직은 정렬·필터 버튼이 없고, 칸 폭도 Table에 정한 길이 그대로라 도서 제목과 저자 칸이 아주 넓어요. 좁은 칸은 컬럼 제목이 잘려 보일 수도 있어요. 잘못된 것이 아니에요. 폭은 11-3에서, 버튼은 11-4에서 한 줄씩 넣어 고쳐요.
  4. 컬럼 제목이 비어 있거나 맨 앞에 칸이 하나 더 보여도 코드 탓이 아니에요. 까닭은 11-3에서 알려 줘요.
  5. F3(Back)을 누르면 ABAP Editor로 돌아와요.

새로 나온 것을 하나씩 볼게요.

코드 뜻
TYPE REF TO cl_salv_table go_alv는 값을 담는 상자가 아니라 ALV 객체를 가리키는 변수예요. 선언만 했을 때는 아직 아무것도 가리키지 않아요. 이름 앞의 go_는 Global Object, 객체를 가리키는 전역 변수라는 표시예요.
cl_salv_table=>factory( … ) 클래스의 Method factory를 불러 ALV 객체를 만들어요. =>는 10-4에서 본 "이 클래스의"예요.
IMPORTING r_salv_table = go_alv factory가 만든 ALV 객체를 go_alv로 받아요. 10-3의 CALL FUNCTION처럼, 부르는 쪽의 IMPORTING은 내가 받는 값이에요.
CHANGING t_table = gt_book 보여 줄 Internal Table을 알려 줘요. ALV는 이 표를 복사하지 않고 그대로 바라봐요.
go_alv->display( ) 만든 ALV를 화면에 띄워요. 객체의 Method는 ->로 불러요.
TRY … CATCH cx_salv_msg … ENDTRY 6-8에서 본 TRY … CATCH예요. factory가 ALV를 만들지 못하면 예외 cx_salv_msg가 일어나서 CATCH 아래로 가요.

=의 왼쪽(r_salv_table, t_table)은 SAP가 정해 둔 파라미터 이름이라 바꾸면 안 돼요. 오른쪽이 내 변수예요. 10-3과 같은 규칙이에요.

cx_salv_msg처럼 cx_로 시작하는 이름은 예외 클래스예요. 어떤 문제가 생겼는지 알려 주는 이름표라고 생각하면 돼요. 6-8의 cx_sy_zerodivide가 "0으로 나눴어요"였다면, cx_salv_msg는 "ALV를 만들다 문제가 생겼어요", 11-3에 나올 cx_salv_not_found는 "그런 칸이 없어요"예요. TRY로 감싸지 않아도 활성화는 되지만(경고가 나올 수 있어요), 정말로 예외가 일어나면 받아 줄 곳이 없어서 덤프(UNCAUGHT_EXCEPTION)로 멈춰요.

클래스, 객체, 그리고 go_alv
  • CL_SALV_TABLE은 SAP가 미리 만들어 둔 클래스예요. 10-4의 lcl_calc는 프로그램 안에 직접 썼지만, 이 클래스는 시스템에 이미 있어서 이름만 적으면 쓸 수 있어요. SAP가 만든 Function Module을 불러 쓰는 것과 같아요.
  • 클래스가 설계도라면, 프로그램이 실행되는 동안 그 설계도로 메모리에 만든 실물이 객체예요. 0-3에서 말한 객체(프로그램, Table처럼 시스템에 만들어 저장하는 것)와는 다른 말이에요.
  • go_alv에는 객체가 통째로 들어 있지 않아요. 객체가 어디 있는지 가리키기만 해요. 그래서 TYPE이 아니라 TYPE REF TO로 선언해요. ALV 객체가 TV라면 go_alv는 리모컨이에요.
화살표 두 가지: =>와 ->
  • 클래스=>Method( ): 클래스 이름으로 바로 불러요. 10-4의 lcl_calc=>discount( ), 여기의 cl_salv_table=>factory( )가 그래요.
  • 객체->Method( ): 만들어진 객체로 불러요. go_alv->display( )처럼요.

헷갈리면 화살표 왼쪽을 봐요. cl_salv_table, lcl_calc 같은 클래스 이름이면 =>, go_alv 같은 내 변수면 ->예요. 둘을 바꿔 쓰면 문법 오류가 나니, 이런 줄에서 오류가 나면 화살표부터 확인해요. 화살표 모양만 기억해 두면 충분해요. 객체지향은 다음 과정에서 자세히 배워요.

자주 하는 실수
  • display( )를 빼먹으면 아무것도 안 나와요. 만들기(factory)와 띄우기(display)는 따로예요.
  • 데이터는 display( )보다 먼저 읽어 와야 해요. SELECT를 display( ) 아래에 쓰면 빈 표가 나와요. display( )를 부르는 순간 Internal Table에 들어 있는 내용이 화면에 나오거든요. 헷갈리지 않게 읽기 → factory → display 순서로 쓰는 습관을 들여요.
  • factory를 빼먹고 go_alv->display( )를 부르면 덤프로 멈춰요. go_alv가 아직 아무 객체도 가리키지 않는데 일을 시켰기 때문이에요. 덤프 이름은 OBJECTS_OBJREF_NOT_ASSIGNED로 시작해요(덤프 읽는 법은 6-8, 덤프 목록은 부록 C).
  • 괄호 안쪽은 앞뒤를 한 칸씩 띄워요. display()처럼 붙이면 오류가 나요. 빈 괄호도 display( )예요.
직접 해 보기 · Pattern과 SE24 구경하기 (나중에 해도 돼요)

r_salv_table, t_table 같은 파라미터 이름을 외울 필요는 없어요. 10-3에서 CALL FUNCTION을 넣어 준 Pattern 버튼이 Method를 부르는 문장도 넣어 줘요.

  1. YG##_143의 빈 줄에 커서를 두고 Pattern(Ctrl+F6)을 눌러요.
  2. ABAP Objects Patterns를 고르고 Enter를 눌러요.
  3. 다음 창에서 Call Method를 고르고, 클래스 이름을 넣는 칸에 CL_SALV_TABLE, Method 칸에 FACTORY를 넣고 Enter를 눌러요. Instance 칸은 비워 둬요. 칸 이름은 버전에 따라 조금 달라요.
  4. factory를 부르는 뼈대가 들어와요. 넣어 주는 모양은 버전과 설정에 따라 달라요. CALL METHOD cl_salv_table=>factory로 시작하는 옛 모양일 수도 있는데, 뜻은 같아요. 구경했으면 들어온 줄을 지워요.
  5. 명령 필드에 /oSE24를 넣어 새 창으로 Class Builder를 열어요. CL_SALV_TABLE을 넣고 Display를 누르면 Methods 탭에 FACTORY, DISPLAY 같은 Method가 줄지어 있어요. FACTORY 줄에 커서를 두고 Parameters를 누르면 파라미터가 줄지어 보여요. 그 가운데 Exporting인 R_SALV_TABLE, Changing인 T_TABLE이 우리가 쓴 두 개예요. 나머지는 넘기지 않아도 되는(Optional) 값이라 지금은 몰라도 돼요. 구경했으면 이 창은 닫아요.

R_SALV_TABLE은 클래스 쪽에서 보면 내보내는 값(Exporting)이라, 부르는 쪽에서는 IMPORTING에 적어요. 10-3에서 본 "부르는 쪽에서는 방향이 반대"와 같아요.

11-3. 컬럼 제목은 어디서 와요?

ALV를 띄워 보면 컬럼 제목이 TITLE이 아니라 도서 제목처럼 나와요. 7-5에서 Data Element를 만들 때 적은 Field Label을 ALV가 가져다 쓰기 때문이에요.

  • Data Element를 쓴 칸은 컬럼 제목이 자동으로 붙어요. ALV가 칸 폭에 따라 Field Label 네 칸(Short·Medium·Long·Heading)에 적어 둔 글자 가운데 하나를 골라 써요.
  • 11-2의 gt_book은 TYPE TABLE OF yta_g##_book으로 만들었어요. Table의 모든 칸에 Data Element가 붙어 있어서 제목이 전부 저절로 나온 거예요. 그런데도 제목이 비어 있으면 로그인한 언어가 평소와 같은지 확인해요. Field Label도 Title처럼 로그인한 언어마다 따로 저장돼요.
  • TYPE c LENGTH 20처럼 Data Element 없이 만든 칸은 제목이 비어 보여요.
  • 그래서 Internal Table의 줄 모양(한 줄에 어떤 칸이 있는지. 8-1의 ty_book 같은 것)을 직접 만들 때는 TYPE yde_g##_title처럼 Data Element를 쓰거나, TYPE yta_g##_book-title처럼 Table의 칸을 참조해요. Table이름-칸이름은 "그 칸과 같은 Type"이라는 뜻이라, 그 칸의 Data Element가 따라와요.
TYPES: BEGIN OF ty_list,
         book_id TYPE yta_g##_book-book_id,   " 컬럼 제목: 도서 번호
         title   TYPE yta_g##_book-title,     " 컬럼 제목: 도서 제목
         memo    TYPE c LENGTH 20,            " 컬럼 제목: (비어 있음)
       END OF ty_list.

칸 다듬기: 폭 맞추기, 숨기기, 제목 바꾸기

ALV 객체 안에는 컬럼, 툴바(표 위에 버튼이 놓인 줄), 화면 모양을 맡은 객체가 따로 들어 있어요. 설정은 늘 두 걸음이에요. get_…( )으로 그 객체를 받고, set_…( )으로 값을 바꿔요. 컬럼부터 해 볼게요.

YG##_143을 고쳐요. 먼저 START-OF-SELECTION. 위, 변수를 선언한 곳에 두 줄을 더해요.

DATA: go_columns TYPE REF TO cl_salv_columns_table,   " 컬럼 전체
      go_column  TYPE REF TO cl_salv_column.          " 컬럼 하나

그다음 ENDTRY. 아래, go_alv->display( ). 위에 아래 코드를 넣어요. 설정은 화면을 띄우기 전에 끝내야 하거든요.

  " 컬럼 전체를 맡은 객체 받기
  go_columns = go_alv->get_columns( ).

  " 모든 칸 폭을 내용에 맞추기
  go_columns->set_optimize( abap_true ).

  TRY.
      " AUTHOR(저자) 칸 숨기기
      go_column = go_columns->get_column( 'AUTHOR' ).
      go_column->set_visible( abap_false ).

      " STOCK(재고) 칸 제목 바꾸기
      go_column = go_columns->get_column( 'STOCK' ).
      go_column->set_short_text( '남은 재고' ).
      go_column->set_medium_text( '남은 재고' ).
      go_column->set_long_text( '남은 재고' ).
    CATCH cx_salv_not_found.
      " 칸 이름을 잘못 적으면 여기로 와요
      MESSAGE '칸 이름을 다시 확인해 주세요' TYPE 'S' DISPLAY LIKE 'E'.
  ENDTRY.

활성화하고 실행하면 칸 폭이 내용에 맞게 줄고, 저자 칸이 사라지고, 재고 칸의 제목이 남은 재고로 바뀌어요. 도서 제목 칸의 제목이 제목으로 짧게 보여도 괜찮아요. 7-5에서 Short에 적어 둔 글자를 ALV가 고른 거예요.

  • set_optimize( abap_true )처럼 괄호 안에 값만 적었죠? 넘길 값이 하나뿐인 Method는 파라미터 이름을 빼고 값만 적어도 돼요. 11-2의 factory처럼 여러 개를 넘길 때는 이름 = 값으로 적어요.
  • abap_true는 5-3에서 본 것처럼 'X', abap_false는 빈칸과 같은 값이에요. 켜기와 끄기로 읽으면 돼요.
  • get_column( 'AUTHOR' ) 안에는 화면에 보이는 컬럼 제목(저자)이 아니라 Internal Table의 칸 이름을 대문자로 적어요. 7-6에서 Table의 Fields 탭에 적은 그 이름이에요.
  • 없는 이름을 적으면 예외 cx_salv_not_found가 일어나요. 덤프가 나는 것이 아니라 CATCH로 넘어가서, TRY 안의 남은 설정까지 건너뛰어요. ALV는 그대로 뜨니까, 숨긴 칸이 그대로 보이면 칸 이름부터 확인해요.
  • 코드로 바꾸는 제목은 Short(10자까지)·Medium(20자까지)·Long(40자까지) 세 가지예요. ALV가 칸 폭에 따라 골라 쓰니 세 개 모두 바꿔 두는 것이 안전해요. 제목이 길면 Short에는 줄인 말을 넣어요.
  • go_columns(끝에 s, 컬럼 전체)와 go_column(컬럼 하나)은 다른 변수예요. 바꿔 쓰지 않게 조심해요.
MANDT 칸은 왜 안 보여요?

SELECT *로 Table의 모든 칸을 읽었으니 MANDT도 Internal Table에 들어 있어요. 그런데 화면에는 나오지 않았죠? ALV가 클라이언트 칸은 사용자에게 필요 없는 칸으로 보고 알아서 숨겨 주기 때문이에요. 버전에 따라 MANDT가 보이면 저자 칸과 같은 방법으로 숨겨요.

ALV에 어떤 컬럼이 나올지는 SELECT 문장이 아니라 Internal Table의 칸이 정해요. 어떤 칸을 아예 빼고 싶으면 9-3처럼 필요한 칸만 가진 줄 모양으로 Internal Table을 만들어요.

더 좋은 방법: 제목을 Data Element에 맡기기

TYPE c LENGTH 20처럼 Data Element 없이 만든 칸은 제목이 비니까, 위의 set_short_text 세 줄로 칸마다 제목을 붙여 줘야 해요. 칸이 늘 때마다 되풀이하기는 번거롭죠. 그 칸에 쓸 Data Element를 만들어 주면 이 코드가 필요 없어요. Field Label이 저절로 제목이 되니까요.

Data Element만 있으면 프로그램 안의 TYPES에 써도 제목은 나와요. 회사에서는 한 걸음 더 나아가 줄 모양까지 Dictionary에 만들어 두는 경우가 많아요. 7-6 끝에서 이름만 본 Structure예요. Table과 똑같이 칸을 정하지만 DB에 저장하지 않는 설계도예요. 8-1의 Structure는 그 프로그램 안에서만 썼지만, Dictionary에 만든 Structure는 모든 프로그램이 함께 써요.

도서 목록에 DB에는 없는 칸 두 개, 장르 이름(소설·IT·에세이)과 재고 상태(품절·부족·충분)를 더해 볼게요. 먼저 두 칸에 쓸 Data Element를 7-5와 같은 방법으로 만들어요. Field Label 탭의 네 칸을 모두 채우는 것을 잊지 마세요.

  1. SE11에서 Data type을 고르고 YST_G##_BOOK_LIST를 입력한 뒤 Create를 눌러요. 작은 창이 뜨면 이번에는 Structure를 고르고 Enter를 눌러요.
  2. Short Description을 적고, Components 탭에 그림 11-5처럼 여덟 줄을 넣어요. Component에 칸 이름, Component Type에 Data Element 이름을 넣고 Enter를 누르면 Type과 길이가 채워져요. 7-6의 Fields 탭과 같아요. Component Type은 여덟 줄 모두 YDE_G##_ 뒤에 칸 이름을 붙인 이름이에요(GENRE_T 줄이면 YDE_G##_GENRE_T).
  3. 메뉴 Extras → Enhancement Category에서 Can Be Enhanced (Deep)을 골라요(7-6과 같아요).
  4. 저장(Local Object) → 검사 → 활성화해요. 활성화가 안 되면 새로 만든 Data Element 두 개가 Active인지 먼저 봐요.

Table을 만들 때와 견줘 보세요. MANDT도, Key도, Delivery Class도, Technical Settings도 없어요. 데이터를 저장하지 않는 설계도라서 그래요.

이 Structure를 줄 모양으로 쓰는 프로그램을 만들어요.

활성화할 때 YST_G##_BOOK_LIST를 모른다는 오류가 나오면 Structure가 아직 Active가 아닌 거예요. Data Element 두 개, Structure, 프로그램 순서로 활성화해요.

실행하면 여덟 칸 모두에 제목이 나와요. 이 프로그램에는 set_short_text 같은 제목을 붙이는 코드가 한 줄도 없어요.

  • 줄 모양이 Structure라서 MANDT 칸은 아예 없어요. DB에 없는 GENRE_T, STATUS 칸도 Field Label 덕분에 제목이 나와요(그림의 색칠한 칸).
  • gt_list의 줄 모양은 Table과 달라요. 그래서 SELECT *와 INTO TABLE 대신, 읽을 칸을 적고 INTO CORRESPONDING FIELDS OF TABLE로 이름이 같은 칸끼리 담았어요(9-3).
  • TYPE STANDARD TABLE OF … WITH DEFAULT KEY는 8-2에서 본 TYPE TABLE OF의 긴 모양이에요. TYPE TABLE OF yst_g##_book_list라고 써도 똑같아요.
  • 제목을 고치고 싶으면 프로그램이 아니라 Data Element의 Field Label을 고쳐요. 그 Data Element를 쓰는 모든 화면이 함께 바뀌어요.

11-4. 버튼 켜기: 정렬 · 필터 · 합계 · 엑셀

YG##_143으로 돌아가요. CL_SALV_TABLE로 띄운 화면은 처음에는 툴바에 버튼이 거의 없어요. 한 줄로 기본 버튼을 모두 켤 수 있어요. 이 줄도 go_alv->display( ). 위에 넣어요.

  go_alv->get_functions( )->set_all( abap_true ).     " 툴바 버튼 모두 켜기

get_functions( )가 돌려준 객체에서 바로 ->set_all( )을 부르는 모양이에요. 받은 객체를 한 번만 쓸 때는 이렇게 변수 없이 Method를 이어서 부를 수 있어요.

버튼에 마우스를 올리면 표의 영문 이름이 보여요.

번호 버튼 영문 이름 쓰는 법
1 정렬 Sort in Ascending Order, Sort in Descending Order 컬럼 제목을 클릭해 고른 뒤 누르면 그 칸 기준으로 정렬돼요. 그림은 가격 내림차순 정렬이에요.
2 필터 Set Filter 칸을 고르고 누르면 조건을 넣는 창이 떠요. 조건(예: 장르 = I)을 넣으면 그 줄만 남아요.
3 합계 Total 숫자 칸을 고르고 누르면 맨 아래에 합계 줄이 생겨요.
4 엑셀 내려받기 Spreadsheet… 엑셀 파일로 내려받아요.
5 레이아웃 Change Layout… 보이는 칸과 칸 순서를 바꿔요.

버튼의 모양과 위치, 이름은 SAP GUI 버전과 테마에 따라 조금씩 달라요. set_all을 켜면 그림보다 훨씬 많은 버튼이 생기는데, 이 장에서는 그림에 있는 것만 써요. 다른 버튼을 잘못 눌러 낯선 창이 뜨면 F12(Cancel)로 닫고, 낯선 화면으로 넘어갔으면 F3(Back)으로 돌아와요.

직접 해 보기
  1. YG##_143에 set_all 한 줄을 넣고 활성화한 뒤 실행해요. 툴바에 버튼이 여러 개 생겼으면 성공이에요.
  2. 가격 컬럼 제목을 클릭해요. 가격 칸 전체의 색이 바뀌어요. 그 상태에서 내림차순 버튼을 눌러요. 그림 11-7처럼 B0004가 맨 위로 와요.
  3. 가격 칸을 고른 채로 합계 버튼을 눌러요. 맨 아래에 합계 줄이 생기고 98,000이 보여요. 칸을 먼저 고르라는 메시지가 나오면 가격 컬럼 제목을 다시 클릭하고 눌러요.
  4. 장르 컬럼 제목을 클릭하고 필터 버튼을 눌러요. 조건을 넣는 창이 뜨면 I를 넣고 Enter를 눌러요. 두 권만 남고 합계가 53,000으로 바뀌어요.
  5. 엑셀 내려받기 버튼을 눌러요. 버튼을 못 찾겠으면 메뉴 List → Export → Spreadsheet…로 해도 돼요. 파일 형식을 묻는 창, 저장할 곳을 묻는 창이 차례로 떠요(창 모양은 버전에 따라 달라요). "SAP GUI Security" 창이 뜨면 Allow를 눌러요. 저장한 파일을 열어 보면 화면에 보이던 두 권이 들어 있어요.
  6. F3으로 나갔다가 다시 실행하면 처음 모습으로 돌아와요. ALV 화면에서 한 정렬과 필터는 그 화면에서만 살아 있고, DB Table의 데이터는 바뀌지 않아요.

화면 꾸미기: 제목과 줄무늬

ALV 화면 맨 위 제목 표시줄에는 프로그램의 Title([예제] 도서 목록 ALV)이 보여요. 다른 글자를 보여 주고 싶으면 set_list_header로 바꿔요. set_striped_pattern을 켜면 줄마다 바탕색이 번갈아 바뀌어서 긴 표를 읽기 쉬워요.

먼저 변수를 선언한 곳에 한 줄을 더해요.

DATA go_display TYPE REF TO cl_salv_display_settings.  " 화면 모양

그리고 go_alv->display( ). 위에 세 줄을 넣어요.

  go_display = go_alv->get_display_settings( ).
  go_display->set_list_header( '도서 목록' ).         " 화면 제목
  go_display->set_striped_pattern( abap_true ).      " 한 줄씩 줄무늬

활성화하고 다시 실행하면 제목 표시줄이 도서 목록으로 바뀌고, 줄 색이 번갈아 보여요.

자주 하는 실수
  • 설정(get_columns, set_all 같은 줄)은 모두 display( )보다 위에 써요. 아래에 쓰면 오류 없이 아무것도 바뀌지 않아요. display( )는 사용자가 ALV 화면에서 나올 때까지 그 줄에서 기다리고, 그 아래 줄은 화면을 닫은 뒤에야 실행되거든요.
  • display( )는 맨 마지막에 한 번만 써요.

여기까지 넣은 YG##_143의 전체 코드예요. 내 코드와 견줘 보세요.

11-5. 정리: ALV 프로그램의 순서

ALV 프로그램은 거의 항상 이 순서예요. 11-2의 세 단계 사이에 "설정하기"가 끼어들어 네 단계가 됐어요. 12장 종합 실습도 이 뼈대로 만들어요.

회사 프로그램에서 만날 다른 ALV

오래된 프로그램에서는 Function Module REUSE_ALV_GRID_DISPLAY로 만든 ALV를 자주 봐요. ALV 안에서 값을 직접 고치게 하거나, 다른 입력 칸과 한 화면에 ALV를 넣을 때는 CL_GUI_ALV_GRID 클래스를 많이 써요. 이름은 달라도 "Internal Table을 넘기면 표가 나온다"는 생각은 같아요. 처음에는 CL_SALV_TABLE로 익히고, 필요할 때 넓혀 가면 돼요.

  4. get_column( 'stock' )처럼 소문자로 적으면 어떻게 될까요?

정답 보기
  1. go_alv->display( ).예요. factory는 ALV를 만들기만 하고, 띄우는 건 display예요.
  2. TYPE yta_g##_book-title처럼 Table의 칸이나 Data Element를 참조해요. 그 Data Element의 Field Label이 제목이 돼요.
  3. =>는 클래스 이름으로 부를 때(cl_salv_table=>factory), ->는 만들어진 객체로 부를 때(go_alv->display) 써요.
  4. 칸을 찾지 못해서 예외 cx_salv_not_found가 일어나요. 덤프가 나는 것이 아니라 CATCH로 넘어가서, 그 TRY 안의 남은 설정을 건너뛴 채 ALV가 떠요. 칸 이름은 대문자로 적어요.
  5. go_alv->get_functions( )->set_all( abap_true ).예요.
  6. display( )는 사용자가 ALV 화면에서 나올 때까지 그 줄에서 기다려요. 그 아래에 쓴 설정은 화면을 닫은 뒤에야 실행돼서 반영되지 않아요. 설정은 모두 display( ) 위에 써요.
  7. Data Element YDE_G##_GENRE_T, YDE_G##_STATUS의 Field Label이에요. Structure YST_G##_BOOK_LIST의 칸이 이 Data Element를 쓰기 때문에 ALV가 Field Label을 제목으로 가져왔어요.
정리
  • ALV는 Internal Table을 넘기면 정렬·필터·합계·엑셀이 되는 표 화면을 만들어 줘요.
  • 순서는 읽기 → factory → 설정 → display예요. 설정은 모두 display( ) 위에 쓰고, factory는 TRY … CATCH cx_salv_msg로 감싸요.
  • 클래스 이름으로 부를 때는 =>(cl_salv_table=>factory), 만들어진 객체로 부를 때는 ->(go_alv->display)예요.
  • 컬럼 제목은 Data Element의 Field Label에서 와요. Data Element 없는 칸은 제목이 비어요.
  • DB에 없는 칸도 Data Element를 만들어 주면 제목이 저절로 나와요. 출력용 줄 모양을 Dictionary Structure(YST_G##_BOOK_LIST)로 만들어 두면 여러 프로그램이 함께 쓸 수 있어요.
  • get_columns( )로 컬럼 전체를 받아 폭을 맞추고(set_optimize), get_column( '칸 이름' )으로 한 칸을 꺼내 숨기거나(set_visible) 제목을 바꿔요(set_short_text 등).
  • get_functions( )->set_all( abap_true )로 툴바 버튼을 켜고, get_display_settings( )로 화면 제목(set_list_header)과 줄무늬(set_striped_pattern)를 정해요.
