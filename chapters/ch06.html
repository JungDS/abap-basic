6장

디버거 기초

이번 장 목표
  • 디버거가 무엇이고 언제 쓰는지 설명할 수 있어요.
  • 중단점(Breakpoint)을 걸고 디버거를 시작할 수 있어요.
  • F5·F6·F7·F8로 한 줄씩, 또는 한꺼번에 실행할 수 있어요.
  • 실행 도중 변수 값을 확인하고, 직접 바꿔 볼 수 있어요.
  • 디버거로 버그(잘못된 곳)를 찾아 고칠 수 있어요.

6-1. 디버거는 프로그램의 슬로 모션이에요

프로그램은 눈 깜짝할 사이에 끝나서, 결과가 이상해도 어디서부터 틀어졌는지 알기 어려워요. 디버거(Debugger)는 프로그램을 원하는 줄에서 멈춰 세우고, 한 줄씩 진행시키면서 변수에 무슨 값이 들어 있는지 보여 주는 도구예요. 축구 경기를 슬로 모션으로 돌려 보는 것과 비슷해요.

4장에서 반복문의 값을 표로 따라가 봤죠(그림 4-2). 디버거는 그 표를 SAP가 대신 보여 주는 것이라고 생각하면 돼요.

언제 쓰나요?
  • 결과가 예상과 다를 때 (합계가 30이어야 하는데 25가 나올 때)
  • IF의 어느 갈래로 들어가는지 확인하고 싶을 때
  • 반복문이 몇 번 도는지, 언제 멈추는지 보고 싶을 때
  • 남이 만든 프로그램이 어떻게 돌아가는지 공부할 때

6-2. 연습용 프로그램 준비

아래 프로그램을 YG##_06_DEBUG로 만들고 활성화해 두세요. 2, 4, 6, 8, 10을 더하는 프로그램이에요.

REPORT yg##_06_debug.

DATA: gv_num TYPE i,
      gv_sum TYPE i.

START-OF-SELECTION.
  DO 5 TIMES.
    gv_num = sy-index * 2.
    gv_sum = gv_sum + gv_num.
  ENDDO.

  WRITE: / '합계:', gv_sum.

6-3. 디버거 시작하는 세 가지 방법

방법 1. 중단점 걸기 (가장 많이 써요)

중단점(Breakpoint)은 "여기 오면 멈춰!"라는 표시예요.

직접 해 보기
  1. ABAP Editor에서 DO 5 TIMES. 줄 왼쪽 회색 여백(줄 번호 옆)을 한 번 클릭해요. 빨간 정지 표시 가 생기면 중단점이 걸린 거예요. 1
  2. F8로 실행해요.
  3. 새 창으로 디버거가 열리고, 중단점을 건 줄에서 멈춰 있어요.

중단점을 없앨 때는 빨간 표시를 다시 클릭하면 돼요. 커서를 줄에 두고 Ctrl+Shift+F12를 눌러도 걸었다 풀었다 할 수 있어요.

방법 2. /h 입력하고 실행하기

명령 필드에 /h를 입력하고 Enter를 누르면 상태 표시줄에 "Debugging switched on"이 나와요. 이 상태에서 F8로 실행하면 처음부터 디버거로 들어가요. Selection Screen이 있는 프로그램이라면, 입력 화면에서 /h를 입력한 뒤 F8을 누르면 AT SELECTION-SCREEN부터 볼 수 있어요.

방법 3. 코드에 BREAK-POINT. 쓰기

코드 안에 BREAK-POINT.라고 쓰면 그 줄에서 멈춰요.

자주 하는 실수

BREAK-POINT.는 그 프로그램을 실행하는 모든 사람을 멈춰 세워요. 확인이 끝나면 꼭 지워요. 연습할 땐 방법 1(여백 클릭)을 쓰는 게 가장 안전해요.

6-4. 디버거 화면 둘러보기

번호 이름 하는 일
1 실행 버튼 한 줄씩 또는 한꺼번에 진행시켜요 (6-5에서 자세히)
2 소스 코드 노란 화살표 ▶ 줄이 다음에 실행할 줄이에요
3 변수 목록 보고 싶은 변수의 지금 값을 보여 줘요
자주 하는 실수

노란 화살표가 있는 줄은 아직 실행되지 않은 줄이에요. 그림 6-2에서 8번 줄 gv_num = sy-index * 2.에 화살표가 있으니, GV_NUM은 아직 0이에요. F5를 한 번 눌러야 2가 돼요.

변수 값 보는 법

  • 소스 코드에서 변수 이름을 두 번 클릭하면 오른쪽 변수 목록에 추가돼요.
  • 또는 변수 목록의 빈 칸에 이름(예: gv_sum)을 직접 입력하고 Enter를 눌러요.
  • 값이 바뀌면 그 줄이 다른 색으로 강조되어서, 방금 무엇이 바뀌었는지 알 수 있어요.

6-5. 한 줄씩 움직이기: F5 · F6 · F7 · F8

키 이름 하는 일 비유
F5 Single Step 딱 한 줄 실행하고 멈춰요. 안에 들어갈 수 있으면 들어가요 한 걸음씩 걷기
F6 Execute 한 줄 실행. 10장에서 배울 FORM 같은 덩어리는 통째로 실행해요 계단을 한 번에 오르기
F7 Return 지금 들어와 있는 덩어리를 끝까지 실행하고 나와요 방에서 나오기
F8 Continue 다음 중단점까지(없으면 끝까지) 쭉 실행해요 빨리 감기

지금은 FORM 같은 덩어리가 없어서 F5와 F6가 똑같이 움직여요. 차이는 10장에서 직접 느껴 볼 거예요.

직접 해 보기 · 반복문 따라가기
  1. 6-3의 방법 1로 디버거를 시작해요. DO 5 TIMES.에서 멈춰 있어요.
  2. 소스 코드에서 sy-index, gv_num, gv_sum을 각각 두 번 클릭해서 변수 목록에 넣어요.
  3. F5를 한 번씩 누르면서 세 변수가 어떻게 바뀌는지 아래 표에 직접 적어 보세요.
  4. 다 봤으면 F8로 끝까지 실행해서 결과 화면을 확인해요.

6-6. 실행 중에 값 바꿔 보기

디버거에서는 변수 값을 직접 바꿀 수도 있어요. "만약 이 값이 100이었다면?"을 코드를 고치지 않고 바로 시험해 볼 수 있어요.

직접 해 보기
  1. 변수 목록에서 GV_SUM 줄의 연필 모양 아이콘(Change)을 누르거나 값 칸을 두 번 클릭해요.
  2. 값을 100으로 바꾸고 Enter를 눌러요.
  3. F8로 끝까지 실행하면 합계가 원래보다 커져서 나와요.
바꾼 값은 이번 실행에만 적용돼요

디버거에서 바꾼 값은 지금 한 번의 실행에만 영향을 줘요. 코드는 그대로이니 안심하고 이것저것 바꿔 보세요.

6-7. 한 걸음 더: Watchpoint

반복이 1,000번이라면 F5를 1,000번 누를 수는 없겠죠. Watchpoint는 "이 변수가 바뀌면(또는 이 조건이 되면) 멈춰!"라는 표시예요.

  1. 디버거 도구 모음의 Watchpoint 버튼을 눌러요.
  2. 변수 이름에 gv_sum을 넣고, 조건(Free Condition Entry)에 gv_sum > 20을 넣어요.
  3. F8을 누르면 gv_sum이 20을 넘는 순간 멈춰요.

6-8. 미니 실습: 버그 잡기

직접 해 보기

아래 프로그램 YG##_06_BUG는 1부터 10까지 홀수의 합(1 + 3 + 5 + 7 + 9 = 25)을 구하려고 만들었는데, 실행하면 30이 나와요.

  1. 프로그램을 그대로 만들어 실행하고 30이 나오는 걸 확인해요.
  2. DO 10 TIMES. 줄에 중단점을 걸고 디버거로 따라가 보세요.
  3. gv_sum에 어떤 수들이 더해지는지 확인하고, 잘못된 줄을 찾아 고쳐요.
  4. 고친 뒤 다시 실행해서 25가 나오는지 확인해요.
REPORT yg##_06_bug.

DATA gv_sum TYPE i.

START-OF-SELECTION.
  DO 10 TIMES.
    CHECK sy-index MOD 2 = 0.
    gv_sum = gv_sum + sy-index.
  ENDDO.

  WRITE: / '홀수의 합:', gv_sum.
정답 보기

디버거로 보면 gv_sum에 2, 4, 6, 8, 10이 더해지고 있어요. 홀수가 아니라 짝수를 더하고 있었던 거예요.

CHECK는 조건이 맞을 때만 아래로 내려가요. sy-index MOD 2 = 0은 "2로 나눈 나머지가 0", 즉 짝수일 때 맞는 조건이에요. 홀수만 통과시키려면 이렇게 고쳐요.

CHECK sy-index MOD 2 = 1.
확인 문제
  1. 디버거의 노란 화살표가 gv_sum = gv_sum + gv_num. 줄에 있어요. 이 줄은 이미 실행된 걸까요, 아직일까요?
  2. 중단점이 하나밖에 없어요. 디버거에서 F8을 누르면 어떻게 될까요?
  3. 프로그램 코드를 고치지 않고 "만약 gv_num이 0이었다면?"을 시험해 보고 싶어요. 어떻게 할까요?
  4. 친구가 확인용으로 코드에 BREAK-POINT.를 넣고 그대로 두었어요. 무엇이 문제일까요?
정답 보기
  1. 아직 실행되지 않았어요. 노란 화살표는 "다음에 실행할 줄"이에요.
  2. 다음 중단점까지 쭉 실행하는데, 더 이상 중단점이 없으면 프로그램 끝까지 실행되고 결과 화면이 나와요. (반복문 안에 중단점이 있다면 다음 바퀴에서 다시 멈춰요.)
  3. 디버거에서 gv_num의 값을 연필 아이콘으로 0으로 바꾼 뒤 계속 실행해 봐요.
  4. 그 프로그램을 실행하는 모든 사람이 디버거에서 멈춰요. 확인이 끝나면 꼭 지워야 해요.
정리
  • 디버거는 프로그램을 멈춰 세우고 한 줄씩 진행하며 변수 값을 보는 도구예요.
  • 시작 방법: 여백 클릭(중단점), /h 후 실행, BREAK-POINT.(쓰고 나면 꼭 지우기).
  • F5 한 줄, F6 덩어리째 한 줄, F7 덩어리에서 나오기, F8 다음 중단점까지.
  • 노란 화살표 줄은 아직 실행 전이에요.
  • 변수 이름을 두 번 클릭하면 값을 볼 수 있고, 연필 아이콘으로 바꿔 볼 수도 있어요.
다음 장 예고

지금까지 만든 프로그램은 실행이 끝나면 데이터가 사라져요. 7장에서는 데이터를 오래 보관할 곳, 즉 Table을 ABAP Dictionary에서 만들어 봐요. 1주차에 해 본 Domain, Data Element를 그림과 함께 차근차근 다시 정리해요.
