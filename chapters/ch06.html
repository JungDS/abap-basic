6장

디버거 기초

이번 장 목표
  • 디버거가 무엇이고 언제 쓰는지 설명할 수 있어요.
  • Breakpoint(중단점)를 걸고 디버거를 시작할 수 있어요.
  • F5·F6·F7·F8로 한 줄씩, 또는 한꺼번에 실행할 수 있어요.
  • 실행 도중 변수 값을 확인하고, 직접 바꿔 볼 수 있어요.
  • 디버거로 버그(잘못된 곳)를 찾아 고칠 수 있어요.
  • 프로그램이 덤프(오류 화면)로 멈췄을 때 원인이 적힌 곳을 찾아 읽고, IF나 TRY … CATCH로 대비할 수 있어요.

6-1. 디버거는 프로그램의 슬로 모션이에요

프로그램은 눈 깜짝할 사이에 끝나서, 결과가 이상해도 어디서부터 틀어졌는지 알기 어려워요. 디버거(Debugger)는 프로그램을 원하는 줄에서 멈춰 세우고, 한 줄씩 진행시키면서 변수에 무슨 값이 들어 있는지 보여 주는 도구예요. 축구 경기를 슬로 모션으로 돌려 보는 것과 비슷해요.

4장에서 반복문의 값을 표로 따라가 봤죠(그림 4-2). 디버거는 그 표를 SAP가 대신 보여 주는 것이라고 생각하면 돼요.

언제 쓰나요?
  • 결과가 예상과 다를 때 (합계가 30이어야 하는데 25가 나올 때)
  • IF의 어느 갈래로 들어가는지 확인하고 싶을 때
  • 반복문이 몇 번 도는지, 언제 멈추는지 보고 싶을 때
  • 남이 만든 프로그램이 어떻게 돌아가는지 공부할 때

6-2. 연습용 프로그램 준비

디버거로 들여다볼 프로그램을 먼저 하나 만들어요. 2, 4, 6, 8, 10을 차례로 더하는 프로그램이에요. 아래 카드대로 만들고(2-2) 활성화까지 해 두세요.

새로 만들기ProgramSE38
Program
YG##_124
Title
[예제] 디버거 연습: 짝수의 합
REPORT yg##_124.

DATA: gv_num TYPE i,
      gv_sum TYPE i.

START-OF-SELECTION.
  DO 5 TIMES.
    gv_num = sy-index * 2.
    gv_sum = gv_sum + gv_num.
  ENDDO.

  WRITE: / '합계:', gv_sum.

실행하면 눈 깜짝할 사이에 결과가 나와요. (숫자 앞 공백 칸 수는 조금 달라도 괜찮아요.)

합계:         30

이 30이 어떤 순서로 만들어지는지, 이제 디버거로 천천히 들여다볼 거예요.

6-3. 디버거 시작하는 세 가지 방법

방법 1. Breakpoint 걸기 (가장 많이 써요)

Breakpoint(중단점)는 "여기 오면 멈춰!"라는 표시예요.

직접 해 보기
  1. ABAP Editor에서 DO 5 TIMES. 줄 왼쪽 회색 여백(줄 번호 옆)을 한 번 클릭해요. 빨간 정지 표시 가 생기면 Breakpoint가 걸린 거예요. 1
  2. F8로 실행해요.
  3. 새 창으로 디버거가 열리고, Breakpoint를 건 줄에서 멈춰 있어요. 화면이 낯설어도 괜찮아요. 6-4에서 하나씩 볼 거예요.
  4. 디버거 창은 닫지 말고 그대로 두세요. 6-4와 6-5에서 이 창으로 이어 가요. 디버거가 열려 있는 동안에는 원래 ABAP Editor 창을 눌러도 반응이 없어요. 고장이 아니에요. 끝내고 싶을 때는 디버거 창에서 F8을 눌러요. 프로그램이 끝까지 실행되고 원래 창으로 돌아와요.

그림의 줄 번호는 6-2의 코드만 넣었을 때 기준이에요. 프로그램 맨 위에 주석 줄이 남아 있으면 번호가 그만큼 밀려요. 번호가 달라도 괜찮으니 코드 글자를 보고 같은 줄을 찾아요.

Breakpoint를 없앨 때는 빨간 표시를 다시 클릭하면 돼요. 커서를 줄에 두고 Ctrl+Shift+F12를 눌러도 걸었다 풀었다 할 수 있어요. Breakpoint는 활성화한 프로그램에 걸어요. 코드를 고쳤으면 먼저 활성화하고 걸어 주세요.

디버거는 새 창으로 열려요. SAP GUI 창을 더 열 수 없을 만큼(보통 6개, 1-5) 이미 열어 두었으면 새 창을 띄우지 못해서 모양이 다른 옛 디버거가 나올 수 있어요. 그럴 땐 안 쓰는 창을 닫고 다시 실행해 봐요.

아래 방법 2와 3은 지금은 읽어만 둬도 돼요. 직접 해 보려면 열어 둔 디버거를 먼저 F8로 끝내고 해요.

방법 2. /h 입력하고 실행하기

명령 필드에 /h를 입력하고 Enter를 누르면 상태 표시줄에 "Debugging switched on"이 나와요. 이 상태에서 F8로 실행하면 처음부터 디버거로 들어가요. Selection Screen이 있는 프로그램이라면, 그 화면에서 /h를 입력한 뒤 F8을 누르면 AT SELECTION-SCREEN부터 볼 수 있어요.

방법 3. 코드에 BREAK-POINT. 쓰기

코드 안에 BREAK-POINT.라고 쓰면 그 줄에서 멈춰요.

자주 하는 실수

BREAK-POINT.는 그 프로그램을 실행하는 모든 사람을 멈춰 세워요. 확인이 끝나면 꼭 지워요. 연습할 땐 방법 1(여백 클릭)을 쓰는 게 가장 안전해요.

Breakpoint에는 두 종류가 있어요
  • 방법 1에서 여백을 눌러 건 것은 보통 Session Breakpoint예요. 지금 로그인한 내 SAP GUI 창에서 실행한 프로그램만 멈춰 세워요. 로그오프하면 사라져요.
  • 다음 과정에서는 브라우저에서 도는 SAPUI5 앱이 ABAP 코드를 불러요. 이 코드는 SAP GUI 창이 아닌 다른 길로 들어오기 때문에 Session Breakpoint에서는 멈추지 않아요. 이럴 때 거는 것이 External Breakpoint예요.
  • 지금은 이름만 기억해 두면 돼요. 거는 방법은 그때 다시 배워요. 여백을 눌렀을 때 어느 쪽이 걸리는지와 아이콘 모양은 설정과 버전에 따라 조금 달라요. 지금은 어느 쪽이든 그대로 연습하면 돼요.

6-4. 디버거 화면 둘러보기

방법 1로 디버거를 열면 아래와 같은 화면이 나와요. Breakpoint를 건 7번 줄에서 막 멈춘 모습이에요. 설정에 따라 Standard 탭이 먼저 열릴 수도 있어요. 그 탭에도 소스 코드와 변수 목록이 있으니 그대로 따라 하면 돼요.

번호 이름 하는 일
1 실행 버튼 한 줄씩 또는 한꺼번에 진행시켜요 (6-5에서 자세히)
2 소스 코드 노란 화살표 ▶ 줄이 다음에 실행할 줄이에요
3 변수 목록 보고 싶은 변수의 지금 값을 보여 줘요

변수 목록은 처음에는 비어 있어요. 그림은 변수 세 개를 넣어 둔 모습이에요. 넣는 법은 바로 아래에 있어요.

자주 하는 실수

노란 화살표가 있는 줄은 아직 실행되지 않은 줄이에요. 그림 6-2에서는 7번 줄 DO 5 TIMES.에 화살표가 있어요. 반복을 아직 시작하지 않았으니 SY-INDEX도 0이에요. F5를 누를 때마다 화살표와 값이 어떻게 바뀌는지는 6-5에서 직접 눌러 보며 확인해요.

변수 값 보는 법

  • 소스 코드에서 변수 이름을 더블클릭하면 오른쪽 변수 목록에 추가돼요.
  • 또는 변수 목록의 빈칸에 이름(예: gv_sum)을 직접 입력하고 Enter를 눌러요.
  • 한 줄 실행할 때마다 Val. 칸의 값이 새로 바뀌어요. 방금 실행한 줄이 무엇을 바꿨는지 여기서 확인해요.

6-5. 한 줄씩 움직이기: F5 · F6 · F7 · F8

키 이름 하는 일 비유
F5 Single Step 딱 한 줄 실행하고 멈춰요. 안에 들어갈 수 있으면 들어가요 한 걸음씩 걷기
F6 Execute 한 줄 실행. 10장에서 배울 FORM 같은 덩어리는 통째로 실행해요 계단을 한 번에 오르기
F7 Return 지금 들어와 있는 덩어리를 끝까지 실행하고 나와요 방에서 나오기
F8 Continue 다음 Breakpoint까지(없으면 끝까지) 쭉 실행해요 빨리 감기

지금은 FORM 같은 덩어리가 없어서 F5와 F6이 똑같이 움직여요. 차이는 10장에서 직접 느껴 볼 거예요.

직접 해 보기 · 반복문 따라가기
  1. 디버거가 DO 5 TIMES.에서 멈춰 있는 상태에서 시작해요. 6-3에서 연 창이 그대로 있으면 그 창을 쓰고, 없으면 6-3의 방법 1로 다시 열어요.
  2. 소스 코드에서 sy-index, gv_num, gv_sum을 각각 더블클릭해서 변수 목록에 넣어요.
  3. F5를 한 번씩 누르면서 화살표와 세 변수를 봐요. 첫 바퀴는 아래 표처럼 움직여요.
  4. 같은 방법으로 다섯 바퀴를 따라가면서 그림 6-3의 빈칸을 직접 채워 보세요.
  5. 다 봤으면 F8로 끝까지 실행해서 결과 화면을 확인해요.
F5 화살표가 옮겨 가는 줄 방금 바뀐 값
1번째 8번 줄 gv_num = sy-index * 2. SY-INDEX 0 → 1
2번째 9번 줄 gv_sum = gv_sum + gv_num. GV_NUM 0 → 2
3번째 10번 줄 ENDDO. GV_SUM 0 → 2
4번째 다시 8번 줄 (둘째 바퀴 시작) SY-INDEX 1 → 2

화살표가 어떤 줄에 도착했을 때, 그 줄이 할 일은 아직 일어나지 않았어요. 표의 "방금 바뀐 값"은 화살표가 떠나온 줄이 바꾼 거예요. 1번째 F5에서 SY-INDEX를 1로 만든 것은 7번 줄 DO 5 TIMES.예요. 한 바퀴는 F5 세 번이에요.

다섯째 바퀴의 gv_sum이 결과 화면의 30과 같으면 맞게 채운 거예요.

그림 6-3 정답 보기

셋째 바퀴는 3 · 6 · 12, 넷째 바퀴는 4 · 8 · 20, 다섯째 바퀴는 5 · 10 · 30이에요. 위에서부터 sy-index, gv_num, gv_sum 순서예요.

6-6. 실행 중에 값 바꿔 보기

디버거에서는 변수 값을 직접 바꿀 수도 있어요. "만약 이 값이 100이었다면?"을 코드를 고치지 않고 바로 시험해 볼 수 있어요.

직접 해 보기
  1. 결과 화면에서 F3으로 돌아와 F8로 다시 실행해요. Breakpoint가 그대로 있어서 디버거가 또 열리고 DO 5 TIMES. 줄에 멈춰요. gv_sum을 변수 목록에 넣어요.
  2. 변수 목록에서 GV_SUM 줄의 연필 모양 아이콘(Change)을 눌러요. 값 칸을 고칠 수 있게 돼요.
  3. 값을 100으로 바꾸고 Enter를 눌러요.
  4. F8로 끝까지 실행하면 합계가 30이 아니라 130으로 나와요. 100에서 시작해서 30이 더해졌으니까요.
바꾼 값은 이번 실행에만 적용돼요

디버거에서 바꾼 값은 지금 한 번의 실행에만 영향을 줘요. 코드는 그대로이니 안심하고 이것저것 바꿔 보세요.

6-7. 한 걸음 더: Watchpoint

반복이 1,000번이라면 F5를 1,000번 누를 수는 없겠죠. Watchpoint는 "이 변수가 바뀌면(또는 이 조건이 되면) 멈춰!"라는 표시예요. 디버거가 열려 있을 때 걸어요.

직접 해 보기 · Watchpoint
  1. YG##_124의 결과 화면에서 F3으로 돌아와 F8로 다시 실행해요. 6-6처럼 디버거가 DO 5 TIMES. 줄에서 멈춰요. gv_sum이 변수 목록에 없으면 넣어요.
  2. 디버거 도구 모음의 Watchpoint 버튼을 눌러요.
  3. 창이 뜨면 변수 이름에 gv_sum을 넣고, 조건(Free Condition Entry)에 gv_sum > 20을 넣은 뒤 Enter를 눌러요. 창의 모양은 버전에 따라 조금 달라요.
  4. F8을 눌러요. 끝까지 가지 않고 gv_sum이 20을 넘는 순간 멈춰요. 변수 목록의 GV_SUM은 30이에요. 다섯째 바퀴에서 30이 된 바로 다음이에요(넷째 바퀴의 20은 20보다 크지 않으니까요).
  5. F8을 한 번 더 누르면 끝까지 실행돼요.

오류 메시지가 나오는 곳에서 멈추기

남이 만든 긴 프로그램에서 오류 메시지가 떴는데, 어느 줄이 낸 것인지 모를 때가 있어요. Breakpoint를 걸 줄을 모르니까, 줄 대신 문장 종류로 걸어요. "MESSAGE 문장을 만나면 어디서든 멈춰!"라고 시키는 거예요. 5-5에서 만든 구구단 프로그램 YG##_121([예제] 입력한 단의 구구단)로 해 봐요.

직접 해 보기 · MESSAGE에서 멈추기
  1. SE38에서 YG##_121을 열어(2-8) F8로 실행해요. Selection Screen이 나오면 명령 필드에 /h를 넣고 Enter를 눌러요(6-3의 방법 2).
  2. 단을 넣는 칸에 15를 넣고 F8을 눌러요. 디버거가 열려요.
  3. 디버거 메뉴에서 Breakpoints → Breakpoint at → Breakpoint at Statement를 골라요. 창이 뜨면 MESSAGE라고 넣고 Enter를 눌러요. 메뉴 이름은 버전에 따라 조금 달라요.
  4. F8을 누르면 MESSAGE로 시작하는 줄에서 멈춰요. 바로 그 줄이 오류 메시지를 내는 곳이에요.
  5. 다 봤으면 F8을 한 번 더 눌러요. Selection Screen으로 돌아오고 상태 표시줄에 그 오류 메시지가 보여요.

멈춘 줄 바로 위의 IF 조건을 읽으면 왜 이 메시지가 나왔는지도 알 수 있어요. 디버거 안에서 건 Breakpoint는 디버거가 끝나면 함께 사라지니 따로 지우지 않아도 돼요.

6-8. 프로그램이 멈췄을 때: 덤프 읽기

디버거는 주로 "끝까지 돌기는 하는데 결과가 이상한" 프로그램을 들여다볼 때 써요. 그런데 가끔은 프로그램이 실행 도중에 아예 멈춰 버리고, 영어가 가득한 화면이 나와요. 이것을 덤프(Dump)라고 불러요. 정식 이름은 Runtime Error예요.

덤프는 고장이 아니에요. "어디서, 왜 멈췄는지"를 SAP가 남겨 주는 사고 보고서예요. 읽는 법만 알면 오히려 고마운 화면이에요. 일부러 한 번 만나 볼게요. 도서 다섯 권의 가격 합계 98,000원을 권수로 나눠 평균 가격을 구하는 프로그램이에요.

새로 만들기ProgramSE38
Program
YG##_125
Title
[예제] 덤프 만나 보기: 0으로 나누기
REPORT yg##_125.

PARAMETERS: pa_total TYPE i DEFAULT 98000,
            pa_cnt   TYPE i DEFAULT 0.

DATA gv_avg TYPE i.

START-OF-SELECTION.
  gv_avg = pa_total / pa_cnt.
  WRITE: / '평균 가격:', gv_avg.
직접 해 보기 · 덤프 만나기
  1. 위 카드대로 프로그램을 만들고, 코드를 넣어 활성화한 뒤 F8로 실행해요. Selection Screen에 PA_TOTAL(합계)과 PA_CNT(권수) 칸이 나와요.
  2. 값은 건드리지 말고 F8을 한 번 더 눌러요. PA_CNT 칸은 비어 보이지만 0이 들어 있어요(숫자 칸의 0은 빈칸으로 보여요, 5-3). 권수가 0인 채로 실행하는 거예요.
  3. 결과 화면 대신 그림 6-4와 같은 화면이 나와요. 이것이 덤프예요. 놀라지 말고 번호가 붙은 세 곳을 찾아봐요.
번호 어디 무엇을 알려 주나요
1 Runtime Errors 오류 이름이에요. 끊어 읽으면 뜻이 보여요. COMPUTE(계산) + INT(정수) + ZERODIVIDE(0으로 나누기)
2 Except. 예외 이름이에요. 조금 뒤에 CATCH 다음에 쓸 이름이에요
3 Source Code Extract 멈춘 줄이에요. >>>>> 표시가 붙은 줄을 실행하다가 멈췄어요. 줄 번호는 내 화면과 달라도 괜찮아요

화면은 버전에 따라 조금 달라요. Source Code Extract는 꽤 아래쪽에 있으니 화면을 내려서 찾아요. 영어가 길어 보이면 Short Text 줄(Division by 0)부터 읽어요. 무슨 일이 났는지 가장 짧게 말해 줘요.

덤프가 난 바로 그 화면에서 Debugger 버튼을 누르면, 멈춘 순간의 변수 값을 디버거로 볼 수 있어요. pa_cnt를 변수 목록에 넣어 보면 0이 들어 있어요. 이미 멈춘 프로그램을 들여다보는 것이라 F5로 더 나아갈 수는 없어요. 값을 봤으면 디버거 메뉴 Debugger → Exit Debugger로 끝내요(메뉴 이름은 버전에 따라 조금 달라요).

덤프는 기록으로 남아요. 나중에 다시 보려면 T-code ST22에서 오늘 날짜와 내 ID로 찾아요. 회사에서 "덤프 났어요, ST22 봐 주세요"라는 말을 자주 듣게 될 거예요.

다 봤으면 덤프 화면에서 F3으로 빠져나와요. 편집기가 아니라 SAP 첫 화면으로 돌아갈 수도 있어요. 그러면 /nSE38로 YG##_125를 다시 열면 돼요(2-8). 프로그램도 SAP도 망가지지 않았어요. 다시 실행해서 이번에는 PA_CNT에 5를 넣으면 평균이 잘 나와요. (숫자 앞 공백 칸 수는 조금 달라도 괜찮아요. 사용자 설정에 따라 19.600처럼 점으로 보이기도 해요.)

평균 가격:     19,600

참고로 합계와 권수를 둘 다 0으로 두면 덤프 없이 0이 나와요. ABAP은 0 / 0만은 0으로 계산하거든요.

고치는 두 가지 방법

① 미리 막기 (권장). 나누기 전에 IF로 확인해요. 메시지를 띄우고 멈추는 모양은 5-5에서 배운 그대로예요. START-OF-SELECTION. 아래를 이렇게 바꿔요.

START-OF-SELECTION.
  IF pa_cnt = 0.
    MESSAGE '권수가 0이라 평균을 낼 수 없어요' TYPE 'S' DISPLAY LIKE 'E'.
    RETURN.
  ENDIF.

  gv_avg = pa_total / pa_cnt.
  WRITE: / '평균 가격:', gv_avg.

② 일어난 뒤에 받기: TRY … CATCH. 실행 중에 생긴 "처리할 수 없는 일"을 예외(Exception)라고 해요. 예외를 아무도 받아 주지 않으면 덤프가 돼요. TRY로 감싸 두면 예외를 받아서 다른 일을 할 수 있어요. ①을 실행해 봤으면, 같은 자리를 이번에는 이렇게 바꿔 봐요.

START-OF-SELECTION.
  TRY.
      gv_avg = pa_total / pa_cnt.
    CATCH cx_sy_zerodivide.
      MESSAGE '권수가 0이라 평균을 낼 수 없어요' TYPE 'S' DISPLAY LIKE 'E'.
      RETURN.
  ENDTRY.

  WRITE: / '평균 가격:', gv_avg.
  • TRY.와 CATCH 사이에는 조심해서 실행할 코드를 써요. CATCH 예외이름. 아래에는 그 예외가 일어났을 때 대신 할 일을 써요. 예외 이름은 덤프 화면 2에 적혀 있던 CX_SY_ZERODIVIDE예요.
  • 예외가 일어나지 않으면 CATCH 아래는 건너뛰고 ENDTRY. 다음 줄로 가요. 그래서 권수에 5를 넣으면 전과 똑같이 19,600이 나와요.
  • JavaScript에서 배운 try { … } catch (e) { … }와 같은 생각이에요. 들여쓰기가 조금 특이한데, Pretty Printer가 이렇게 맞춰 줘요.

어느 쪽으로 고치든, 권수 0으로 실행하면 덤프 대신 Selection Screen으로 돌아와서 상태 표시줄에 빨간 메시지가 나와요. 미리 확인할 수 있는 것은 ①처럼 IF로 막는 쪽이 읽기 쉬워요. 사실 권수는 입력값이라 5-5처럼 AT SELECTION-SCREEN에서 막는 것이 제자리예요. 여기서는 ②와 견주기 쉽게 같은 자리에 썼어요. TRY … CATCH는 미리 확인하기 어려울 때 쓰고, 11장에서 다시 만나요.

덤프 이름은 아주 많아요. 자주 만나는 것은 부록 C의 덤프 표에 원인과 함께 모아 뒀어요.

6-9. 미니 실습: 버그 잡기

이번에는 디버거로 진짜 버그를 잡아 볼 차례예요. 아래 프로그램은 1부터 10까지 홀수의 합(1 + 3 + 5 + 7 + 9 = 25)을 구하려고 만들었는데, 실행하면 30이 나와요.

새로 만들기ProgramSE38
Program
YG##_126
Title
[실습] 버그 잡기: 홀수의 합
REPORT yg##_126.

DATA gv_sum TYPE i.

START-OF-SELECTION.
  DO 10 TIMES.
    CHECK sy-index MOD 2 = 0.
    gv_sum = gv_sum + sy-index.
  ENDDO.

  WRITE: / '홀수의 합:', gv_sum.
직접 해 보기
  1. 위 카드대로 프로그램을 만들고, 코드를 버그까지 그대로 넣어 실행해요. 30이 나오는 걸 확인해요.
  2. DO 10 TIMES. 줄에 Breakpoint를 걸고 실행해요. 디버거가 열리면 sy-index와 gv_sum을 변수 목록에 넣고 F5로 따라가 보세요.
  3. gv_sum에 어떤 수들이 더해지는지 확인하고, 잘못된 줄을 찾아 고쳐요.
  4. 고친 뒤 다시 실행해서 25가 나오는지 확인해요.
정답 보기

디버거로 보면 gv_sum에 2, 4, 6, 8, 10이 더해지고 있어요. 홀수가 아니라 짝수를 더하고 있었던 거예요.

CHECK는 조건이 맞을 때만 아래로 내려가요(4-8). sy-index MOD 2 = 0은 "2로 나눈 나머지가 0", 즉 짝수일 때 맞는 조건이에요. 홀수만 통과시키려면 이렇게 고쳐요.

CHECK sy-index MOD 2 = 1.

더 빨리 찾는 요령도 있어요. Breakpoint를 gv_sum = gv_sum + sy-index. 줄에 걸고 F8을 누르면, 멈출 때마다 지금 더하려는 sy-index가 보여요.

확인 문제
  1. 디버거의 노란 화살표가 gv_sum = gv_sum + gv_num. 줄에 있어요. 이 줄은 이미 실행된 걸까요, 아직일까요?
  2. Breakpoint가 하나밖에 없어요. 디버거에서 F8을 누르면 어떻게 될까요?
  3. 프로그램 코드를 고치지 않고 "만약 gv_num이 0이었다면?"을 시험해 보고 싶어요. 어떻게 할까요?
  4. 친구가 확인용으로 코드에 BREAK-POINT.를 넣고 그대로 두었어요. 무엇이 문제일까요?
  5. 프로그램을 실행했더니 덤프 화면이 나왔어요. 가장 먼저 찾아볼 세 곳은 어디일까요? 이 덤프를 내일 다시 보려면 어느 T-code로 갈까요?
  6. gv_avg = pa_total / pa_cnt.는 pa_cnt가 0이면 덤프가 나요. 덤프가 나지 않게 하는 방법 두 가지를 말해 보세요.
정답 보기
  1. 아직 실행되지 않았어요. 노란 화살표는 "다음에 실행할 줄"이에요.
  2. 다음 Breakpoint까지 쭉 실행하는데, 더 이상 Breakpoint가 없으면 프로그램 끝까지 실행되고 결과 화면이 나와요. (반복문 안쪽 줄에 Breakpoint가 있다면 다음 바퀴에서 다시 멈춰요. DO 5 TIMES. 줄은 반복을 시작할 때 한 번만 지나가요.)
  3. 디버거에서 gv_num의 값을 연필 아이콘으로 0으로 바꾼 뒤 계속 실행해 봐요.
  4. 그 프로그램을 실행하는 모든 사람이 디버거에서 멈춰요. 확인이 끝나면 꼭 지워야 해요.
  5. Runtime Errors(오류 이름), Except.(예외 이름), Source Code Extract에서 >>>>>가 붙은 줄(멈춘 줄)이에요. 나중에 다시 볼 때는 ST22로 가요.
  6. ① 나누기 전에 IF pa_cnt = 0.으로 확인해서 미리 막아요. ② TRY.와 ENDTRY.로 감싸고 CATCH cx_sy_zerodivide.에서 받아요. 미리 확인할 수 있으면 ①이 더 좋아요.
정리
  • 디버거는 프로그램을 멈춰 세우고 한 줄씩 진행하며 변수 값을 보는 도구예요.
  • 시작 방법: 여백 클릭(Breakpoint), /h 후 실행, BREAK-POINT.(쓰고 나면 꼭 지우기).
  • 여백을 눌러 건 Session Breakpoint는 내 SAP GUI 창에서 실행한 프로그램만 멈춰요. 브라우저가 부르는 코드는 External Breakpoint로 멈춰요.
  • F5 한 줄, F6 덩어리째 한 줄, F7 덩어리에서 나오기, F8 다음 Breakpoint까지.
  • 노란 화살표 줄은 아직 실행 전이에요.
  • 변수 이름을 더블클릭하면 값을 볼 수 있고, 연필 아이콘으로 바꿔 볼 수도 있어요.
  • 덤프는 사고 보고서예요. 오류 이름, 예외 이름, 멈춘 줄(>>>>>)을 먼저 보고, 나중에는 ST22에서 다시 봐요.
  • 0으로 나누기 같은 예외는 IF로 미리 막거나 TRY … CATCH로 받아요.
